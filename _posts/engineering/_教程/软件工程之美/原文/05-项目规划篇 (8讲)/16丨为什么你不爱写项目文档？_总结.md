# 《16丨为什么你不爱写项目文档？》总结
> 来源：本专栏第 16 讲 · 项目规划篇

## 一句话结论
程序员"不喜欢写文档"又"不喜欢项目文档太少"的矛盾，源于短期高估、长期低估文档价值；写好文档的真正障碍不是文笔，而是没想清楚。

## 为什么不爱写文档？
- **不知道怎么写**——应占很大一部分比例
- **太忙没时间写或者懒得写**——总有不忙的时候，却也宁可去重构代码
- **"敏捷开发所以不用写文档？"**——敏捷宣言最后一句："尽管右项有其价值，我们更重视左项的价值。"敏捷从未否认文档价值，只是更重视"工作的软件"

## 为什么要写文档？
| 受益方 | 价值 |
| --- | --- |
| 写文档的人 | 写作即思考：写代码前梳理思路，想清重点难点、要依赖谁及早协商、安全风险；避免陷入细节、上线后才发现漏洞 |
| 未来的维护和交接 | "好记性不如烂笔头"：设计、操作流程、环境配置记录下来，不依赖口口相传；作者每到新项目组就把问题、配置、操作步骤记入团队 WIKI，新人照此快速上手 |
| 团队更好的协作沟通 | 文档是沟通工具：产品设计有雏形即可评审提意见，避免定稿后无法更改 |

> 如果你连文档都写不出来，那又怎么能指望代码写得好呢？

（写作不行只是用词欠缺，真正的障碍是心中只有未成型的混乱想法，必须努力把模糊的想法确定化、具体化。）

## 如何写好文档？
文档写作关键是把想法表达出来，用词格式是其次；像在家做饭，不需要宽油大火、色香味俱全。
1. **从模仿开始**——作者在飞信项目第一次写技术方案，领导给了一份旧文档让"依葫芦画瓢"，再学画线框图、时序图，很快完成；后来写开源项目英文文档也参照同类项目。模仿就是最好的写文档方式。
2. **从小文档开始**——笔记、一两句话、几张截图都是开始；把给别人的讲解整理成小文档，以后直接发文档免去重复开会，并逐步完善。
3. **从粗到细，迭代更新**——脑图理结构 → PPT（列一二三、画图、可讲解并收集反馈）→ 正式文档（把 PPT 内容和图搬进去搭骨架，再补细节）。"写得越细则无用功越多，最后，你甚至会因为不想改文档而抵触不同的意见。"
4. **画图技巧**——"字不如表，表不如图"。常用图：
   - 线框图：方框表示模块、箭头表示关系/数据流向，重点理清模块及关系（例：Twitter 缓存方案、Netflix 账单系统架构）
   - 流程图：表示不同条件下的逻辑路径，重点理清关键节点走向（例：重置密码流程）
   - 时序图：表示对象间消息发送的时间顺序，网络通信文档常用（例：注销登录过程）
   - 截图：UI、交互效果、数据图表配箭头文字说明

## 其他建议
- 平衡：不过度追求形式化文档，"工作的软件高于详尽的文档"；好的代码格式、注释、单元测试可很大程度代替代码文档
- 推荐用 Markdown 专注内容；在线文档工具优于离线（版本管理、多人协作）：GitHub WIKI、石墨文档、Google Docs、Evernote
- 把文档撰写作为正规项目任务：安排人、安排时间、放进项目计划，"懒得写"就没借口了
- 文档写作需要多练习，写得越多越熟练
