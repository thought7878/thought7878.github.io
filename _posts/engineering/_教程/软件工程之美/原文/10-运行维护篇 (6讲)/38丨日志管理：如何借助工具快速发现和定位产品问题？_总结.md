# 《38丨日志管理：如何借助工具快速发现和定位产品问题？》总结
> 来源：本专栏第 38 讲 · 运行维护篇

## 一句话结论
微服务架构下日志分散在几十上百个容器里，必须统一管理；基于 ELK 搭建日志管理系统，实现集中检索、可视化图表和阈值自动报警，就能第一时间发现并快速定位线上问题。

## 什么是日志管理
- 日志：操作系统和应用软件自动生成的事件说明或消息记录，包含时间、请求 URL、IP 地址、返回状态码等（如 `GET / HTTP/1.1 200`）。
- 日志管理：对系统和应用产生的日志进行统一收集、筛选解析、统一存储、方便检索的方法。
- 微服务架构下，一个系统由若干微服务组成、每个又部署在若干容器上，排查故障要从几十上百个地方收集分析，所以必须统一管理，无需从头自研，用成熟工具搭建即可。

## 为什么日志管理能快速发现和定位问题
1. **集中式管理后可统一检索**：所有日志放一起，用类似 SQL 的方式高效查询归类，不用逐个应用翻日志；
2. **图表直观展示运行情况**：实时统计 API 错误率、平均耗时等生成图表，看走势、与历史对比（如部署后性能是升是降）；
3. **按数值设置规则自动报警**：如 API 错误率超 10%、90% 请求超 1 秒即触发报警，通知值班人员，第一时间发现故障。

## 大厂日志管理系统架构（以 ELK 为例）
ELK = Elasticsearch（搜索框架，全文检索）+ Logstash（数据收集工具，收集、过滤、解析日志）+ Kibana（图形化界面）。四个重要模块：

| 模块 | 说明 |
| --- | --- |
| 日志采集和解析 | Logstash 收集日志；带时间戳的文本行无法有效检索，必须解析成结构化数据；不同语言应用格式不一，需提取公共元素（时间、IP、主机名、应用名） |
| 存储和搜索 | ElasticSearch 专业全文检索与存储，类 SQL 查询，数据庞大需索引分析才能快速检索 |
| 结果可视化 | Kibana 图形化展示，看走势、对比历史数据 |
| 监控和报警 | ELK 之上装 ElastAlert、Watcher 等插件，超阈值自动通知值班人员 |

## 如何搭建
- 可直接基于开源免费的 ELK 搭建（网上教程很多）；
- 其他选择：Splunk（商业，搜索强、好用但贵）、Grafana（开源可视化，效果比 Kibana 好，支持自动报警）、Wavefront（VMware 旗下商业监控分析）、PagerDuty（报警服务，集成手机/邮件/Slack，可按排班呼叫当值人员）。
