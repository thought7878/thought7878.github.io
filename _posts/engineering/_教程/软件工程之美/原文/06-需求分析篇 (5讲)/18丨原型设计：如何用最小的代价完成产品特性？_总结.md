
## 一句话结论

`原型设计`从一种*快速开发模型*演变为**产品经理独立可用的沟通工具**，**借助工程方法（分析、设计、实施、验证）四阶段，产品经理无需程序员即可低成本、高效率地确认需求**。

## 原型设计的发展历史

- **起源**：20 世纪 70 年代，*需求不明确、需求多变*是难题。《人月神话》作者弗雷德里克·布鲁克斯（Frederick P. Brooks, Jr.）在《没有银弹》中*首次提出"在获取和制订软件需求时，将快速原型开发作为迭代计划的一部分"*
- **快速原型模型**：开发网站分三阶段——① 纯静态 HTML 页面*确认界面布局*；② 模拟后台服务（内存存数据）*确认交互*；③ *接入真实数据库完成开发*。核心是 *"第一阶段确认界面布局和内容，第二阶段确认交互，第三阶段实现"*
- **局限**：快速原型模型*必须有开发人员配合，产品经理难以独立完成*

## 三种保真度演进

| 类型     | 工具/方式         | 优点                         | 缺点                  |     |
| ------ | ------------- | -------------------------- | ------------------- | --- |
| 低保真原型  | 线框图（纸和笔即可）    | 简单方便，直观展示界面布局              | 不够真实，难反映界面关系与交互     |     |
| 中等保真原型 | Axure 等专业原型软件 | 可展示整体结构和交互，产品经理自己搞定，无需开发介入 | 界面真实度、色彩不如最终产品      |     |
| 高保真原型  | 高保真原型工具       | 界面漂亮、交互炫酷，完成后可不做 UI 设计     | 学习/制作成本高，变更成本高，易陷细节 |     |

使用**建议**：先用低保真原型*快速确认需求*，再用高保真原型*确认最终交互和 UI 设计*。

## 怎么做好原型设计？（以极客时间 iPad 版为例）

*借鉴工程思维，将原型设计分为四个阶段：*

1. **分析**：初步了解模糊的需求，明确原型设计目标（如 iPad 版内容基于 iPhone，布局和交互重新设计，发挥大屏优势）
2. **设计**：从两个维度考虑——
   - **信息架构维度**：画产品`信息结构图`（像书的目录），*从粗到细梳理模块及关系*
   - **使用流程维度**：画产品`使用流程图`，*重点考虑用户使用场景，同时考虑异常情况*（留言输入错误、网络失败等）
3. **实施**：对每个界面制作原型，*优先满足产品需求，再求好看好用*；*给可点击元素加跳转链接，按流程图连接界面*
4. **验证**：产品经理*先反复自验，再交他人体验、开评审会收反馈*。案例：竖版界面原型经朋友反馈"返回专栏不方便"，改回传统返回式导航——"在原型设计工具中，几分钟就完成了"

## 总结

**想做自己的产品，先别急着写代码，不妨先做个原型——*用最小的代价完成产品特性***。
