
## 一句话结论

**程序员的价值**体现在所做产品和自身稀缺性上，技术提升会遇到瓶颈，而`产品意识`（商业意识、用户意识、数据意识）正是**可与技术互补的一技之长，能减少技术革新带来的焦虑**。

## 程序员的价值

| 价值体现     | 说明                                                       |
| -------- | -------------------------------------------------------- |
| 所创造产品的价值 | 产品越有价值，个人价值越大。*程序员的价值不完全在技术，而在于用技术做成产品、产品创造价值，再反过来成就程序员* |
| 团队中的稀缺性  | *能搞定技术难题、擅长培训新人、擅长与业务沟通、高质量完成模块、能设计好架构提升团队效率*等一技之长，难以被取代 |

**焦虑源于对未来不确定**、不知道自身价值在哪。*技术水平到一定程度后提升缓慢，此时同步发展其他领域（写作、产品意识）事半功倍*。产品意识是*程序员固有思维中比较欠缺、可以互补且相对容易掌握的*。

## 什么是产品意识

`产品意识`本质是一种**站在产品角度思考问题的思维方式，细分为三部分：**

1. `商业意识`——*产品要有商业价值，也要有成本意识：*

- 成功产品（Windows、iPhone、Google）既满足用户需求又创造商业价值
- 程序员热衷做的 Github 客户端、博客系统没什么商业价值，难以持续
- 成本意识案例：为炫技采用高成本技术方案、忽视开会成本、为省钱不买成熟商业组件反而浪费更多成本

2. `用户意识`——挖掘用户真实需求，要有同理心：

- 没有用户意识：产品细节没定义清楚也不主动提出；做技术方案追求炫酷而非用户体验；设计接口不考虑调用者便利性
- 有了用户意识：负责的模块体验更好、技术方案更好满足用户需求、API 更好用

3. `数据意识`——用数据发现问题、证实结果：

- 典型如 *A/B 测试*。微博"时间乱序"功能虽被大 V 吐槽，但数据证明是好设计，上线后不断优化，现在很多人喜欢
- 程序员常对数据不敏感：*编译警告、测试覆盖率、Crash 比例、API 错误率、性能指标常被选择性忽略*
- 语言框架之争不妨基于数据（如 jQuery 和 React 前端发展趋势对比）

## 如何培养产品意识？

### 1. 解放思想：从技术思维转向产品思维。

|     | 技术思维                | 产品思维                     |
| --- | ------------------- | ------------------------ |
| 关注点 | 用什么技术、技术细节、功能"如何"实现 | 用户体验、功能创造的价值、为什么要/不要一个功能 |

以 Slack 为例：*技术角度分析*，它前端用 jQuery、HTML5 跨平台、REST API、国内访问慢；*产品角度分析*，它把工作沟通变高效、好玩、云端消息检索方便、开放 API 可无缝集成办公软件、付费查看 10000 条之前消息的设计（消息已过万条说明有足够付费意愿）。

### 2. 改变习惯
- 日常**使用产品时**多思考
	- 产品的商业价值是什么？
	- 为什么要有这个功能？
	- 目标用户是谁？
	- 使用场景是什么？
	- 体验好不好？ 
- **开发时**也要思考：*是否完全理解需求、作为用户有哪些可改进、哪些技术能提升体验、API 是否好用*。
- 产品经理提一堆需求时，可一起梳理优先级
- 需求技术**复杂时**，先探讨背后要解决的问题、是否有替代方案。

### 3. 多实践
业余时间做小应用或原型，找朋友试用提意见。**宝玉自己的产品都来自生活需求——给孩子批量生成缩略图、帮老婆做整页截图工具、帮父亲建家谱应用、给校友建论坛**。

## 总结

培养产品意识=解放思想（技术思维→产品思维）+ 改变习惯（多站在产品角度思考）+ 多实践。慢慢培养后，不仅能打造更高价值的产品，也能在技术之外有一技之长，减少焦虑。
