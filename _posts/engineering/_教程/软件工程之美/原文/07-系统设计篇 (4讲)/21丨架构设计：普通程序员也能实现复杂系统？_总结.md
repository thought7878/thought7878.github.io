
## 一句话结论

`架构设计`就是**通过组织人员和技术，低成本满足需求及需求变化、保障软件稳定高效运行**；**普通程序员不必依赖高手，借助成熟架构模式也能实现复杂系统**。

## 为什么软件项目需要架构设计？

**复杂软件项目的两大特点：** **需求不确定、技术复杂**。

*技术复杂性有四个来源：*

| 来源           | 示例                            |
| ------------ | ----------------------------- |
| **需求让技术变复杂** | 个人博客 vs 淘宝复杂度天壤之别；需求变化会破坏原有架构 |
| **人员让技术变复杂** | 团队水平、技术方向各异，协作成本高             |
| **技术本身复杂**   | 语言、框架、微服务、大数据、AI 均需学习         |
| **稳定运行复杂**   | 明星八卦致微博宕机、阿里云宕机牵连依赖系统         |
***复杂性带来的问题：***
- 开发很复杂、很困难
- 开发成本很高、效率很低
- 产品质量会降低

***架构设计恰恰可以很好地解决技术复杂的问题、解决技术复杂带来的上面的问题***
***架构设计的四大价值：*** 
- **降低**满足需求和需求变化的**开发成本**（抽象分解，淘宝拆成微服务后*单个服务难度接近个人博客*；分层架构隔离 UI 与业务逻辑）、（**降低复杂度/难度**）
- **组织人员高效协作**（前后端分离再细分小组）、
- **组织好各种技术**（分层架构各司其职）、
- **保障稳定运行**（分布式分流、异地多活）。

其中满足需求、需求变化、稳定运行是`目标`，组织人员和技术是`手段`。

## 什么是架构设计？

- `目标`：用最小的人力成本满足需求开发和响应变化，用最小的运行成本保障运行。"能跑"不等于好架构——把小网站拆成几十个微服务就是反例。
- `方法`：**微服务、前后端分离、分层架构**，本质都是"`分而治之`"。
- `道`：**组织人员和技术，把系统和团队拆分，安排好切分后的排列关系，通过约定协议相互通信**。类比乐高：前后端*通过 REST 交互*，组件间*通过方法调用*，小组间*通过流程规范协作*。

## 如何做好架构设计？

以*极客时间服务端*为例（目标：日 PV 上万、峰值每秒约 10 个访问、稳定性要求高），四步走：

1. **分析需求**：`用例分析`识别角色——编辑、专栏作者、未付费用户、付费用户，覆盖网站/安卓/iPhone 多终端。
2. **选择相似的成熟架构**：选传统分层架构；语言框架依团队而定（PHP 团队不贸然选 Java，JS 团队可考虑 Nodejs），降低学习成本。
3. **自顶向下层层细化**：
   - `部署`：基于云服务，增加异地网站服务器和异地云数据库备份保障稳定性；
   - `分层分模块`：用户界面层、服务层、业务逻辑层、数据访问层、数据存储；基于用例图抽象模块（如留言模块、文稿模块）；
   - 再做 `API 设计`、`数据库表设计`，模块设计可让负责人参与。
4. **验证和优化**：多轮`评审`收集反馈，决策时考虑架构能支撑多长期限的业务增长；开发中持续调整（如 API 访问量大就与网站服务拆分）。
