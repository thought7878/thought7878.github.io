# 《32丨软件测试：什么样的公司需要专职测试？》总结

> 来源：本专栏第 32 讲 · 软件测试篇

## 一句话结论

测试的核心工作是发现 Bug、报告 Bug、跟踪 Bug，难点在于基于测试设计的专业用例能力；只有同时具备高水平工程师、大量自动化测试、完善发布监控、进度宽松、用户容忍度高的公司（如 Facebook）才不需要专职测试，多数公司保留专职测试更有利于质量保障。

## 软件测试的主要工作

测试设计是架构设计的"具象"：把业务需求分解成一个个具体用户操作步骤（测试用例），开发后逐一验证、报告 Bug、跟踪修复。

- 发现 Bug：开发关注"如何实现功能"，测试关注所有正常、异常、极端场景（大小写、特殊字符、超长输入、并发、暴力破解），用例覆盖更全
- 报告 Bug：通过 Bug 跟踪系统提交 Ticket，写清描述、重现步骤、截图日志
- 跟踪 Bug：验证修复 + 回归测试，确认修复不引入新错误

## 科学测试方法

| 方法 | 说明 |
| --- | --- |
| 等价类划分 | 一类数据对发现 Bug 效果相同，取一值即可（如 1-100 等价、0 与负数等价、101 以上等价） |
| 边界值分析 | 边界最易出错，如 0、1、100、101 |
| 探索性测试 | 基于已测试结果按策略推进（RPG 迷宫：分叉优先走右边） |
| 其他 | 场景设计、因果图、错误推测法（推荐《微软的软件测试之道》） |

## 为什么开发兼职测试很难

- 除编程与业务外还要学测试方法，要求高
- 实现时漏的逻辑，测试时也想不起来测（如漏了 SQL 注入检测）
- 难以对自己写的程序做破坏性测试的心理障碍
- 进度紧张时首先压缩测试时间，质量失控

## Facebook 为何能没有专职测试

工程师水平高于业界平均；产品周期宽松，有时间写自动化测试；几千内部员工先测（部分充当测试角色）；发布监控完善、可快速回滚或发补丁；社交产品用户对 Bug 容忍度高（"想想看如果是波音飞机上的软件能这么做吗？"）。Google、Amazon 情况类似。

## 大厂实践的启示

- 自动化测试代替重复性手工测试是必然趋势
- 测试设计是测试人员的核心竞争力（无效用例任何方法都测不出好效果）
- 开发与测试融合双赢：测试提供用例参考，开发写自动化测试代码
