Figma 中 **Group** 和 **Frame** 的核心区别是：  
**Group 是“轻量编组”，Frame 是“真正的容器”**。

| 对比项 | Group | Frame |
|---|---|---|
| 本质 | 轻量级图层组合，类似文件夹 | 真正的容器，类似 HTML 的 `div` |
| 尺寸 | 由内容自动决定，调整尺寸会整体缩放内容 | 可设置固定宽高，调整尺寸不会默认缩放内容 |
| 裁剪内容 Clip content | ❌ 不支持 | ✅ 支持，可隐藏超出边界的内容 |
| Auto Layout | ❌ 不支持 | ✅ 支持自动布局 |
| 子层 Constraints | ❌ 组内子层不能设置约束 | ✅ 子层可设置约束响应 Frame 尺寸变化 |
| 填充/描边 | 作用于组内所有子层，不是背景 | 作为 Frame 自身的背景/边框，位于子层下方 |
| 圆角 | ❌ 不支持 | ✅ 支持 |
| 布局网格 | ❌ 不支持 | ✅ 支持 |
| 适用场景 | 临时组合、批量移动/缩放、整理图层 | 卡片、按钮、页面区域、组件、自动布局 |

---

### 关键差异详解

#### 1. 尺寸与缩放行为
- **Group**：没有独立的“容器尺寸”，宽高由内部内容包围盒决定。拖动 Group 的缩放手柄时，内部图层会一起被缩放。
- **Frame**：有明确的宽高属性。调整 Frame 大小时，内部子层默认不会被缩放，而是根据 Constraints 或 Auto Layout 重新排布。

#### 2. 裁剪内容
- **Frame** 可以开启 **Clip content**，把超出边界的内容隐藏。
- **Group** 无法裁剪，内容可以超出组的边界显示。

#### 3. 自动布局与约束
- **Frame** 可以启用 **Auto Layout**，实现自动排列、间距、内边距等。
- **Group** 不能启用 Auto Layout；组内子层也没有 Constraints 概念。

#### 4. 填充/描边的区别
- **Group** 的填充/描边会**应用到组内所有子图层**。例如给 Group 加红色填充，组内所有形状都会变红，而不是在组背后加一个红色背景。
- **Frame** 的填充是**容器自身的背景**，位于所有子层下方；描边也是 Frame 自身的边框。

#### 5. 圆角与网格
- **Frame** 可以设置圆角、布局网格。
- **Group** 没有这些属性。

---

### 互相转换

- **Group → Frame**：右键选择 **Frame selection**，转换后可以获得 Frame 的容器能力。
- **Frame → Group**：右键选择 **Group selection**，但会丢失 Auto Layout、裁剪、圆角等 Frame 特性。

---

### 简单建议

- 如果只是把几个图层放在一起方便移动、缩放、管理，用 **Group**。
- 如果需要固定尺寸、背景、圆角、裁剪、自动布局、响应式约束，用 **Frame**。  
- 在设计系统和组件化场景中，优先使用 **Frame**，它更接近前端容器模型。
