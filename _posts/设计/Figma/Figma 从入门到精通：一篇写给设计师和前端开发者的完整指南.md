## 新手开始前要准备什么

如果你第一次打开 Figma，不要急着马上画完整页面。Figma 的学习难点不在“按钮在哪里”，而在于你能不能建立正确的文件习惯。很多新手一开始就用矩形、文字和图片堆页面，短期看起来能做出效果，但后面一改内容就全乱，交付给开发也很难读。

建议先准备这几件事：

| 准备项 | 新手怎么做 | 为什么重要 |
| --- | --- | --- |
| 账号 | 注册 Figma 账号，优先用邮箱登录 | 云端文件、分享链接、团队协作都依赖账号 |
| 客户端 | Mac / Windows 装桌面版，网页端作为备选 | 桌面版对本地字体和大文件更稳定 |
| 字体 | 安装常用中文字体，如思源黑体、苹方、微软雅黑 | 避免设计稿在别人电脑上显示异常 |
| 素材目录 | 把图片、图标、参考截图分文件夹放好 | 后期替换素材时不会到处找文件 |
| 快捷键 | 先记 10 个最常用快捷键 | Figma 是高频操作工具，快捷键会明显提升效率 |

### **快捷键**
新手最先记住这些快捷键就够了：

| 快捷键 | 功能 | 使用场景 |
| --- | --- | --- |
| `V` | 移动 / 选择 | 选中、拖动、框选元素 |
| `F` | Frame | 新建手机页面、网页画板、组件容器 |
| `R` | 矩形 | 画按钮、卡片、输入框、图片容器 |
| `O` | 椭圆 | 画头像、圆形图标背景、角标 |
| `T` | 文字 | 添加标题、说明、按钮文字 |
| `P` | 钢笔 | 画自定义图标和路径 |
| `Shift + A` | 自动布局 | 做按钮、列表、卡片、导航栏 |
| `Cmd/Ctrl + Alt + K` | 创建组件 | 把按钮、导航、卡片变成可复用组件 |
| `Cmd/Ctrl + G` | 编组 | 临时组合元素 |
| `Cmd/Ctrl + /` | 快速搜索 | 找插件、命令、菜单功能 |

一个*很实用的入门方法：先不要追求“画得好看”，先追求“结构正确”*。同样一个按钮，如果你用矩形加文字直接堆出来，它只是一个外观；如果你用 Frame + Auto Layout + 文本样式 + 组件做出来，它才是可以复用、可以交付、可以维护的设计资产。

## 一、为什么是 Figma？竞品横向对比

在正式学习 Figma 之前，有必要回答一个问题： **市面上有那么多设计工具，为什么偏偏选 Figma？**

### 主流设计工具对比

| 维度 | Figma | Sketch | Adobe XD | Axure |
| --- | --- | --- | --- | --- |
| 平台 | Web + Mac + Win | Mac 专属 | Mac + Win | Mac + Win |
| 实时协作 | 原生支持，无需插件 | 需第三方工具 | 有限支持 | 不支持 |
| 定价 | 免费套餐可用 | 订阅制，无免费版 | 订阅制 | 昂贵的永久授权 |
| 组件系统 | 强大的变体组件 | 支持 Symbol | 组件系统较弱 | 无原生组件 |
| 开发交付 | Dev Mode / Inspect / Export | 需 Zeplin 等工具 | 内置 | 只能导出 HTML |
| 学习曲线 | 平缓 | 中等 | 较平缓 | 陡峭 |
| 插件生态 | 极其丰富 | 丰富 | 一般 | 较少 |

**结论** ：Figma 是目前 UI/UX 设计领域*综合能力最强*的工具，尤其在团队协作和全平台可用性上有压倒性优势。2022 年 Adobe 以 *200 亿美元*的价格收购 Figma（后因反垄断监管告吹），足以说明其行业地位。

### Figma 的核心优势

**基于浏览器的架构** ：Figma 运行在 WebGL 和 WebAssembly 之上，这意味着你的设计文件存储在云端，任何设备打开浏览器即可工作，无需担心文件版本混乱。

**实时多人协作** ：就像 Google Docs 之于文档，Figma 实现了多人同时编辑设计稿，光标实时可见，评论直接标记在画布上。这彻底改变了设计团队的工作方式。

**设计即代码的哲学** ：Figma 的 Auto Layout（自动布局）、Constraints（约束）等特性与 CSS Flexbox、响应式布局的概念高度对应，*降低了设计稿转代码的沟通成本*。

## 二、安装与汉化：快速起步

### 两种使用方式

**网页版** ：直接访问 figma.com，注册账号即可使用，无需安装。适合轻量使用场景。

**桌面客户端** ：从官网下载安装包，Mac 和 Windows 均有对应版本。桌面版支持离线使用本地字体，推荐日常工作使用桌面版。

### 汉化方案

Figma 官方语言设置目前覆盖英语、日语、韩语、法语、德语、西班牙语和葡萄牙语（巴西）等语言，仍未提供简体中文界面。因此中文用户常见做法是使用浏览器翻译、第三方汉化插件，或直接熟悉英文界面。

1. 打开 Figma，进入任意文件
2. 点击左侧菜单 → **Plugins** → **Browse plugins in Community**
3. 搜索 **Figma Chinese** 等中文汉化插件
4. 安装后，通过快捷键 `Ctrl/Cmd + /` 运行插件即可切换语言

> 注意：汉化插件只修改界面文字显示，不影响功能和文件格式，团队协作时对其他人不可见。

如果你准备长期做 UI/UX 设计，建议最终过渡到英文界面：设计团队、插件文档、官方帮助和开发交付里的术语基本以英文为主，熟悉英文术语能减少沟通成本。

## 三、**界面总览**：看懂 Figma 的三大区域

打开任意 Figma 文件后，先不要急着画东西。下面这张图是我用真实 Google Chrome 打开的 Figma 空白文件截图，并在关键区域上加了编号。新版 Figma 的常用绘图工具主要放在底部浮动工具栏，左侧还有文件、资源、工具、变量等入口。

![[_posts/设计/Figma/media/ea8a77a71442ba4f9e04db83d38381f2_MD5.webp]]

你可以把界面理解成 5 个区域：左侧是工具入口和图层，中间是画布，右边改属性，底部负责画图工具，右上角负责预览和分享。

| 区域 | 你会看到什么 | 新手应该怎么用 |
| --- | --- | --- |
| 左侧工具入口 | File、Assets、Tools、Variables 等入口 | 新手先知道它们在哪，不用一开始全学 |
| 页面 / 图层面板 | Pages 和 Layers | Pages 管页面，Layers 看页面结构 |
| 中间画布 | 你的页面、组件、参考图都放在这里 | 用 `Space + 拖拽` 平移，用缩放快捷键查看全局或细节 |
| 右侧属性栏 | Design、Prototype、Dev Mode / Inspect | 选中元素后，在这里改尺寸、颜色、圆角、交互和开发参数 |
| 底部工具栏 | 移动、Frame、形状、钢笔、文字等工具 | 画东西前先记住 `V` 、 `F` 、 `R` 、 `T` 这几个常用工具 |
| 右上角操作区 | 预览、分享、缩放比例等 | 做完页面后，用这里预览和发链接给别人 |

刚开始学的时候，你只要记住一个顺序： **先选中元素，再看右侧属性栏** 。Figma 不是所有设置一直显示出来，而是你选中什么，它才显示对应的设置。选中文字，右侧就是字体和行高；选中矩形，右侧就是尺寸、填充、圆角；选中 Frame，右侧才会出现栅格、约束、自动布局等容器设置。

### 新手第一次打开文件，应该先看哪里

第一次进入 Figma 文件时，很多人会被满屏按钮吓住。实际上你只要按这个顺序看，就不会乱：

1. **先看左侧图层面板** ：确认当前文件里有哪些页面、画板、组件。图层面板就像 Photoshop 的图层树，也是后期维护文件的核心。
2. **再看中间画布** ：找到正在编辑的 Frame。手机 APP 页面通常是一个个竖向画板，网页设计通常是多个桌面宽度画板。
3. **最后看右侧属性栏** ：先选中一个元素，再看右侧属性变化。Figma 的右侧属性栏是“选中什么，就显示什么设置”。

![[_posts/设计/Figma/media/1e297a1168194e3333fa4e7d4b6def44_MD5.webp]]

看这张图时，新手先记住两件事： **Pages 决定你在哪个页面工作，Layers 决定你选中了哪个对象** 。如果你发现自己怎么都点不中某个元素，不要一直在画布上乱点，先回到左侧 `Layers` 找它；如果你发现自己改了半天没变化，先确认是不是选错了 `Page` 。

一个最简单的练习：

1. 新建一个 Design File。
2. 按 `F` ，在右侧选择一个手机尺寸，例如 iPhone 13/14。
3. 按 `R` ，在手机画板上画一个矩形。
4. 在右侧把矩形宽度改成 `343` ，高度改成 `48` ，圆角改成 `24` 。
5. 按 `T` ，输入“立即预约”。
6. 同时选中文字和矩形，按 `Shift + A` ，把它们变成自动布局按钮。

做完这个练习，你就已经接触到 Figma 里最重要的 4 件事：Frame、形状、文字、Auto Layout。

## 四、**工具栏**精讲：每个工具背后的设计逻辑

![[_posts/设计/Figma/media/31b646e8fa4ef48f57ff1cb6b58b8680_MD5.webp]]

新版 Figma 的常用工具集中在画布底部。刚开始不需要把每个图标都背下来，先抓住图里的 5 个入口： `1` 用来选择和移动， `2` 用来画页面容器， `3` 用来画矩形、圆形和图片占位， `4` 用来写文字或画自定义图形， `5` 后面会用于组件、原型和交付。

### 4.1 移动工具（Move / Select）

快捷键 `V` ，是最常用的工具。需要理解两种选择模式：

- **选择工具** （ `V` ）：点击选中单个元素；框选时只有完全被框住的元素才会被选中
- **深度选择** ：双击可进入 Frame 或组内部选择子元素
- **多选** ： `Shift + 点击` 追加选择； `Cmd/Ctrl + A` 全选当前层级的所有元素

新手常见问题是“我明明点了，为什么选不中里面的元素”。原因通常是这个元素被包在 Frame、Group 或组件实例里面。解决方法有三种：

- 双击进入内部选择。
- 按住 `Cmd/Ctrl` 点击，直接深度选中。
- 从左侧图层面板里找到对应图层再点击。

如果一个文件图层命名规范，左侧面板会非常好用；如果满屏都是“矩形 1、矩形 2、Group 23”，后期修改会很痛苦。所以从新手阶段开始，就要养成命名习惯。

### 4.2 Frame 工具

快捷键 `F` ，这是 Figma 最重要的概念之一（详见第六节）。

Frame 本质上是一个有固定尺寸的容器。在右侧属性栏可以直接选择预设尺寸（iPhone、iPad、桌面、各种社交媒体尺寸等），这极大地方便了多端设计。

新手可以把 Frame 理解成“页面”或“容器”。做手机 APP 时，一个手机页面就是一个大 Frame；做卡片时，一个卡片也是一个小 Frame；做按钮时，按钮也建议用 Frame。只要你希望某个东西有自己的背景、圆角、裁切、内边距或响应式行为，就优先考虑 Frame。

**不要用普通矩形当页面底板** 。页面底板应该是 Frame，因为只有 Frame 才能承载 Prototype 跳转、滚动、栅格、约束和自动布局。

### 4.3 形状工具

快捷键 `R` （矩形）、 `O` （椭圆）、 `L` （直线）、 `Shift + P` （多边形）。

关键技巧：

- 按住 `Shift` 绘制时保持正比（正方形、正圆）
- 按住 `Alt/Option` 从中心向外绘制
- 双击圆形或矩形可进入 **矢量路径编辑模式** ，直接操作节点

矩形的圆角可以在属性栏统一设置，也可以点击左上角小图标切换为 **四角分别控制** 模式，实现不均匀圆角（如对话气泡）。

新手画 UI 时，矩形是使用频率最高的形状。按钮、输入框、卡片、Banner、弹窗、底部导航，本质上都可以从一个矩形开始。建议一开始就用固定数值控制尺寸，而不是完全凭感觉拖：

| 元素 | 常用尺寸参考 |
| --- | --- |
| 手机页面左右边距 | 16px |
| 主按钮高度 | 44px 或 48px |
| 输入框高度 | 44px 或 48px |
| 卡片圆角 | 8px 或 12px |
| 头像 | 32px / 40px / 48px / 64px |
| 图标 | 16px / 20px / 24px |

这些数值不是绝对标准，但能帮助新手建立比例感。界面看起来“专业”，很多时候不是因为用了多复杂的效果，而是因为尺寸、间距、圆角都统一。

### 4.4 钢笔工具（Pen）

快捷键 `P` ，用于绘制自定义矢量路径，是绘制图标和复杂图形的核心工具。

操作模式：

- **直线段** ：单击创建锚点
- **曲线段** ：点击拖拽，拉出贝塞尔曲线控制手柄
- **闭合路径** ：点击第一个锚点完成闭合
- **编辑模式** ：选中矢量图形后按 `Enter` 进入节点编辑， `Esc` 退出

节点类型（在节点编辑模式下右键切换）：

- **Mirror Angle** ：两侧手柄角度始终对称（平滑曲线）
- **Mirror Length** ：角度和长度都对称
- **Disconnected** ：两侧手柄完全独立（用于急转弯）
- **None** ：直角节点

钢笔工具对新手来说不需要一开始就非常熟练。前期只要会两件事：

1. 用它画简单的折线、箭头和不规则形状。
2. 知道进入节点编辑模式后，可以移动点、删除点、调整曲线手柄。

如果你主要做 UI 页面，图标可以先用图标库或插件；等 Frame、组件、自动布局熟练以后，再回头练钢笔画图标，效率会更高。

### 4.5 文字工具

快捷键 `T` ，点击画布直接输入，或框选创建固定宽度文本框。

关键属性：

- **字体族 / 字重 / 字号** ：通过右侧属性栏设置
- **行高（Line Height）** ：设为 `Auto` 自动，或手动输入像素值
- **字距（Letter Spacing）** ：正值拉开字符间距，负值压缩
- **段落间距（Paragraph Spacing）** ：段落之间的额外空白
- **文本截断** ：固定宽高文本框中，超出内容的截断策略（剪切/隐藏/自动高度）

文字是 UI 设计里最容易被低估的部分。新手常犯的问题是字号太多、字重太多、灰色层级混乱。刚开始做 APP，可以先用这一套简单规则：

| 类型 | 字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面大标题 | 24 | Semibold / Bold | 首页、个人中心主标题 |
| 区块标题 | 18 | Semibold | 推荐、热门项目、订单标题 |
| 卡片标题 | 14 或 16 | Medium | 商品名、文章标题 |
| 正文 | 14 | Regular | 描述文本、列表内容 |
| 辅助说明 | 12 | Regular | 时间、标签、次要信息 |
| 底部 Tab 文案 | 10 或 11 | Regular | 底部导航 |

颜色层级也可以先固定为三档：主文字 `#1A1A1A` ，次文字 `#666666` ，辅助文字 `#999999` 。不要每个页面都临时取一个灰色，否则整体会显得不统一。

### 4.6 图片填充与蒙版

在 Figma 中，图片不是独立的图层类型，而是一种 **填充方式** 。选中任意形状，在右侧面板的 Fill（填充）中选择「图片填充」，即可将图片限定在该形状的轮廓内。

填充模式：

- **Fill** ：等比缩放填满容器（可能裁剪）
- **Fit** ：等比缩放至完全显示（可能留白）
- **Crop** ：自定义裁切区域
- **Tile** ：平铺重复

**蒙版（Mask）** ：选中底部的形状图层和上方的图片，右键 → Use as Mask，即可将形状作为遮罩，只显示形状区域内的图片内容。这与 CSS 中的 `clip-path` 和 `mask-image` 概念完全对应。

![[_posts/设计/Figma/media/d50bc4cc9c08d18016f5a563842cd44b_MD5.webp]]

上图是课程素材中的图片填充练习素材。实战时建议不要把图片直接堆在画布上，而是先画出 Banner、头像、卡片封面等容器，再把图片作为 Fill 放入容器，这样后续替换图片、调整裁切和套用组件都更稳定。

## 五、**属性栏**深度解析：设计的精确控制

![[_posts/设计/Figma/media/732bee38467e3fe95b3ab84c65521120_MD5.webp]]

右侧属性栏可以理解成 **“当前对象的设置面板”**。
- *没选中元素时*，它显示页面背景和文件级设置；
- *选中矩形时*，它会显示尺寸、填充、圆角、描边；
- *选中文字时*，它会显示字体、字号、行高；
- *选中 Frame 时*，它会显示布局、约束、栅格和自动布局。
新手最重要的习惯是： **先选对象，再看右侧** 。

### 5.1 位置与尺寸

- **X / Y** ：元素相对于其 **父容器** 左上角的偏移，不是相对于画布原点
- **W / H** ：宽度和高度，点击锁链图标约束宽高比
- **旋转角度** ：输入正值顺时针，负值逆时针，范围 -180° 到 180°

新手要特别理解“父容器”这个概念。比如一个按钮放在手机页面里，它的 X/Y 是相对于手机 Frame 的；如果按钮放在卡片 Frame 里，它的 X/Y 就是相对于卡片的。很多人拖来拖去对不齐，本质是没搞清楚当前元素属于哪个父级。

建议养成两个习惯：

- 移动元素时按住 `Alt/Option` 看距离，确认它离左右边距是不是 16px、离上一个模块是不是 12px 或 16px。
- 尽量用右侧数值输入微调，不要全靠鼠标拖。鼠标适合粗略摆放，数值适合精确对齐。

### 5.2 圆角与描边

- **圆角（Corner Radius）** ：最大值为宽高最小值的一半（即圆形）
- **描边（Stroke）** ：支持内描边、外描边、居中描边三种对齐方式
- **虚线描边** ：展开描边选项，设置 Dash（虚线段长）和 Gap（间隔长）

圆角不要随意乱用。一个项目里最好先定 3 到 4 个圆角等级：

| 圆角 | 用途 |
| --- | --- |
| 4px | 小标签、小输入提示 |
| 8px | 普通卡片、列表项 |
| 12px | 大卡片、弹窗、图片容器 |
| 999px | 胶囊按钮、圆形头像、圆形图标背景 |

描边也要克制。浅色界面中常用 `#EBEBEB` 或 `#E5E7EB` 作为分割线，不要用纯黑描边。描边太重，会让界面显得像线框图，不像成品设计。

### 5.3 颜色系统

Figma 支持四种填充类型：

1. **Solid** ：纯色，支持 HEX、RGB、HSB、HSL 多种输入模式，支持透明度
2. **Linear Gradient** ：线性渐变，可添加多个色标
3. **Radial Gradient** ：径向渐变（从中心向外扩散）
4. **Angular Gradient** ：锥形渐变
5. **Diamond Gradient** ：菱形渐变

颜色格式建议：Web 设计使用 HEX，与前端代码对应；需要透明度时使用 `rgba()` 。

新手做颜色时最容易出现“每个模块都很好看，但放在一起很乱”的问题。原因通常是颜色没有分工。建议先按角色分配颜色：

- **品牌色** ：主要按钮、选中态、关键入口，例如医美 APP 的粉色或青色。
- **强调色** ：促销、优惠、警示、活动标签，一般比品牌色更跳。
- **文字色** ：主文字、次文字、辅助文字。
- **背景色** ：页面背景、卡片背景、浅色图标背景。
- **反馈色** ：成功、错误、警告、提示。

一个新手可直接套用的配色结构：

| 颜色角色 | 推荐值 |
| --- | --- |
| 主色 | `#FF6B8A` |
| 强调色 | `#FFB020` |
| 页面背景 | `#F7F8FA` |
| 卡片背景 | `#FFFFFF` |
| 主文字 | `#1A1A1A` |
| 次文字 | `#666666` |
| 辅助文字 | `#999999` |
| 分割线 | `#EBEBEB` |
| 错误色 | `#FF4D4F` |
| 成功色 | `#52C41A` |

### 5.4 效果（Effects）

- **Drop Shadow** ：元素外阴影，参数含 X 偏移、Y 偏移、模糊半径、扩散、颜色
- **Inner Shadow** ：元素内阴影，用于模拟凹陷效果
- **Layer Blur** ：对当前图层应用模糊
- **Background Blur** ：毛玻璃效果，模糊当前图层下方的内容（iOS 风格常用）

阴影不要为了“高级”而乱加。专业 UI 的阴影通常很轻，目的是表达层级，不是让卡片飘起来。新手可以先用这两组：

| 场景 | 建议阴影 |
| --- | --- |
| 普通卡片 | `0 2 8 rgba(0, 0, 0, 0.05)` |
| 弹窗 / 浮层 | `0 8 24 rgba(0, 0, 0, 0.12)` |

如果一个页面到处都是阴影、渐变和模糊，用户反而不知道哪里最重要。界面越复杂，效果越要克制。

## 六、Frame vs 组：一个让新手困惑的核心概念

这是 Figma 最核心、也最容易混淆的概念之一。新手常以为 Group 和 Frame 只是命名不同，实际它们的 **行为机制完全不同** ，理解这一点是从入门到进阶的分水岭。

### 组（Group）：边界由内容决定

快捷键 `Cmd/Ctrl + G` 编组， `Cmd/Ctrl + Shift + G` 取消编组。

组的核心特征： **边界大小由子元素决定** 。调整任何子元素或移动它们，组的边界自动跟随调整。组本身不能设置背景、描边、圆角等容器属性。

**调整边界的行为细节** （这是面试常考点）：

- 用常规方法拖拽 Group 边界时，子元素的 **矢量图形** 会按比例缩放
- 但子元素的 **文字尺寸、描边粗细、效果（阴影/模糊）不会缩放**
- 如果希望文字、描边、效果也一起缩放，需要切换为 **缩放工具** （快捷键 `K` ）

**适用场景** ：

- 多个元素临时组合，但不影响子元素的独立可编辑性
- 希望在缩放时子元素能跟随等比缩放
- 利用智能排序（Tidy Up）调整元素间距

### Frame（画框）：独立边界 + 强大容器能力

快捷键 `F` 绘制，或选中元素后 `Cmd/Ctrl + Alt + G` 包裹成 Frame。删除 Frame 与取消编组同样用 `Cmd/Ctrl + Shift + G` 。

Frame 的本质：在其他设计工具中，你会想到 **artboard（画板）** 的概念，Frame 在 Figma 中正是承担画板的角色——但它又远不止画板。

Frame 的核心能力：

- **可设置完整的容器样式** ：背景填充、描边、圆角、阴影、内边距
- **边界独立于子元素** ：在 Frame 内重新定位或缩放子元素，Frame 自身的边界不会自动调整（这与 Group 完全相反）
- **支持 Constraints（自适应约束）** ：子元素可定义"顶/底/左/右/居中/拉伸"等响应规则，Frame 尺寸变化时子元素按规则自动调整位置和大小
- **支持 Clip Content（内容裁切）** ：超出 Frame 边界的内容会被裁剪
- **是 Auto Layout 和 Grid 的基础容器**
- **是 Prototype 中屏幕单位的载体**

**两个关键调整技巧** ：

- 如希望 Frame 尺寸自动适应内容，单击右侧属性面板的 **"调整边界大小以适应"** 按钮
- 调整 Frame 边界时 **临时忽略约束** ：拖拽时按住 `Cmd（Mac）/ Ctrl（Win）`

### Constraints 详解：响应式设计的开关

默认情况下，Frame 内子元素的 Constraints 是"顶部固定 + 左侧固定"。这意味着 Frame 缩放时，子元素位置不变。

正确的设置示例：

- **导航栏按钮** ：右侧固定（Right）+ 顶部固定（Top），无论屏幕宽度怎么变，按钮始终在右上角
- **底部 Tab Bar** ：左右拉伸（Left & Right）+ 底部固定（Bottom），自动适配不同宽度屏幕
- **居中 Logo** ：水平居中（Center）+ 顶部固定（Top）

> 设置 Constraints 是创建 **响应式组件** 的必要前提。这是 Group 永远做不到的事。

### 决策准则（终极版）

| 你的需求 | 选择 |
| --- | --- |
| 临时打包几个元素一起移动 | **Group** |
| 元素组合后希望整体缩放（含文字描边） | **Group** + 缩放工具 K |
| 独立控制容器尺寸，不影响子元素 | **Frame** |
| 需要响应式行为（自适应约束） | **Frame** + Constraints |
| 需要裁剪超出边界的内容 | **Frame** + Clip Content |
| 做手机/网页屏幕页面 | **Frame** (一定) |
| 嵌套滚动（水平轮播、可拖动地图） | **Frame** |
| 使用栅格布局 | **Frame** + Grid |
| 做组件 / Auto Layout | **Frame** (必选) |

### 一个实际例子：商品卡片

设计一个带"图片+标题+价格+按钮"的卡片：

你可以这样拆：最外层是一个 `Card` Frame，负责白色背景、圆角和阴影；上半部分是图片区域，单独放进 `Cover` Frame，并打开 `Clip Content` ；下半部分是内容区域，放标题、副标题、价格和按钮，并用垂直 Auto Layout 控制间距。

| 部分 | 建议设置 | 作用 |
| --- | --- | --- |
| Card | 200 × 280，圆角 12，白色背景，轻阴影 | 控制整张卡片的外观 |
| Cover | 高度 120，图片填充，顶部圆角 | 保证图片不会溢出卡片 |
| Content | padding 12，gap 8，垂直 Auto Layout | 控制文字和价格区域的排版 |
| PriceRow | 横向 Auto Layout | 让价格和按钮在同一行对齐 |

**全程没有用到一个 Group** ——这就是 Figma 设计系统的标准做法。

### 新手练习：把一个错误结构改成正确结构

很多新手会这样做商品卡片：

先画一个背景矩形，再把图片、标题、价格和按钮直接放在上面。这个做法短期看起来没问题，但它其实只是一堆散图层。背景不是真正的容器，图片、文字、按钮之间也没有布局关系；标题一变长，价格和按钮就不会自动下移。

正确做法是：

1. 选中所有元素，先用 `Cmd/Ctrl + Alt + G` 包成 Frame。
2. 给最外层 Frame 命名为 `ProductCard` ，设置白色背景、圆角和阴影。
3. 把图片放入单独的 `Cover` Frame，打开 `Clip Content` 。
4. 把标题、价格、按钮放入 `Content` Frame，按 `Shift + A` 改成垂直 Auto Layout。
5. 给 `Content` 设置 padding `12` ，gap `8` 。
6. 把按钮也改成 Auto Layout，让文字变化时按钮宽度自动适配。

改完以后，这个卡片才具备“真实项目可维护性”。后期标题变成两行、价格变长、按钮文案改成“立即咨询”，卡片也不会散架。

## 七、布尔运算：用逻辑拼出复杂图形

布尔运算让设计师可以将多个简单形状组合成复杂图形，是图标绘制的必备技能。

### 四种布尔运算

选中两个或多个形状，在顶部菜单或属性栏中选择：

**Union（并集）** ：合并所有形状的外轮廓，重叠区域合并为一体。颜色取最底层形状的填充。

**Subtract（差集）** ：用上层形状的区域从下层形状中"挖去"对应区域。常用于绘制空心图形。

**Intersect（交集）** ：只保留所有形状的公共重叠区域。

**Exclude（排除/异或）** ：保留所有形状，但将重叠区域变为空（透明）。

新手可以这样记：并集是“合到一起”，差集是“挖掉一块”，交集是“只留重叠处”，排除是“重叠的地方变空”。

### 布尔运算的可编辑性

布尔运算结果在 Figma 中是 **非破坏性** 的——在图层面板中展开布尔运算组，仍然可以选中并编辑原始的子形状。这与 Photoshop 的矢量蒙版行为类似。

### 实战：绘制一个通知图标

1. 绘制一个圆角矩形（铃铛主体）
2. 绘制一个小矩形（铃铛顶部挂钩）
3. 绘制一个圆形（铃铛底部圆弧）
4. 绘制一个更大的圆形与主体做 Subtract（挖出铃铛中空轮廓）
5. 用 Union 将所有部件合并

## 八、组件系统：设计的可复用单元

组件（Component）是 Figma 设计系统的基石，相当于开发中的 React 组件或 Vue 组件。

### 主组件与实例

- **主组件（Main Component）** ：原始定义，图标为实心菱形。修改主组件会同步影响所有实例。
- **实例（Instance）** ：主组件的复制品，图标为空心菱形。可以在实例上做局部覆盖（Override），不影响主组件和其他实例。

创建主组件：选中元素 → `Cmd/Ctrl + Alt + K` 。

新手可以先记住一句话： **重复出现 2 次以上的东西，就应该考虑做成组件** 。比如按钮、底部 Tab、卡片、头像、标签、列表项、弹窗关闭按钮，都不应该每次重新画。

做组件的基本流程：

1. 先画出一个最标准、最常用的版本。
2. 确认命名清楚，例如 `Button / Primary / Medium` 。
3. 选中最外层 Frame，按 `Cmd/Ctrl + Alt + K` 创建组件。
4. 从主组件复制实例到页面中使用。
5. 后续只改主组件，不要到处改散落的副本。

一个新手最容易犯的错误：复制了 20 个按钮，但没有创建组件。等到客户说“按钮圆角从 8 改成 24”，你就要手动改 20 次；如果一开始做成组件，只需要改主组件一次。

![[_posts/设计/Figma/media/277c7d87cfeb6b85a6eab0c707427c62_MD5.webp]]

这张图要看的是思路，不是某一个按钮样式。左边的 `Primary` 、中间的 `Secondary` 、右边的 `Disabled` 不应该散落成三个互不相关的按钮，而应该属于同一个 `Button` 组件集。以后页面里需要不同按钮时，只切换属性，不重新画。

### 变体组件（Component Variants）

变体（Variants）是 Figma 最强大的功能之一，允许将多个相关状态的组件合并为一个可切换的组件集合。

典型应用——按钮组件变体：

比如一个按钮组件，可以按“类型、尺寸、状态、图标位置”来拆。类型包含 Primary、Secondary、Ghost；尺寸包含 Small、Medium、Large；状态包含 Default、Hover、Pressed、Disabled；图标位置包含 None、Left、Right。

定义变体后，在实例的右侧属性栏可以用下拉菜单在各状态间切换，而无需手动更换组件，这大幅提升了交互原型的制作效率。

新手可以先从按钮变体练起，不要一开始就做复杂组件库。一个合格按钮组件至少要考虑这些状态：

| 维度 | 取值 | 为什么需要 |
| --- | --- | --- |
| 类型 | Primary / Secondary / Ghost | 区分主操作、次操作和弱操作 |
| 尺寸 | Small / Medium / Large | 适配表格、表单、页面主按钮 |
| 状态 | Default / Hover / Pressed / Disabled | 做交互原型和交付说明 |
| 图标 | None / Left / Right | 适配“搜索”“下载”“下一步”等按钮 |

不要把每个按钮都做成完全独立的组件。正确方式是把同类按钮放进一个组件集里，用属性切换；这样组件面板更干净，页面使用也更快。

### 组件属性（Component Properties）

Figma 较新版本引入了三种组件属性：

- **Boolean Property** ：控制某个图层的显示/隐藏（如图标是否显示）
- **Text Property** ：将文本内容暴露为可编辑属性
- **Swap Instance Property** ：允许在实例中快速替换嵌套组件（如替换图标）

这三种属性与 React Props 的概念高度类似，极大地降低了组件系统的使用复杂度。

举一个最容易理解的例子：做一个列表项 `ListItem` 。

这个组件可以把左侧图标设成 Boolean Property，控制显示或隐藏；标题和描述用 Text Property，方便在实例里直接改文字；右侧内容用 Swap Instance Property，可以在箭头、开关、文字之间切换。

这样你只需要维护一个 `ListItem` 主组件，就能生成“设置项”“消息项”“订单项”“个人中心菜单项”等多种样式。专业设计稿不是靠复制很多相似图层堆出来的，而是靠少量高质量组件组合出来的。

## 九、自动布局：响应式设计的基石

Auto Layout（自动布局）是 Figma 中与 CSS Flexbox 高度对应的布局机制，是做响应式设计不可绕过的核心功能。

### 创建自动布局

选中多个元素或一个 Frame → `Shift + A` ，即可将其转换为自动布局容器。

如果你之前用过 Word、PPT 或 Photoshop，可能会习惯手动拖动每个元素。但 Figma 的专业做法是：把有排列关系的元素交给 Auto Layout 管理。

比如一个按钮：

一个按钮里通常只有两个东西：图标和文字。把它们放进横向 Auto Layout，设置左右 padding 和中间 gap，按钮就能根据文字长短自动变化。

当 Label 从“确定”变成“立即预约”时，按钮宽度会自动变宽；当你隐藏 Icon 时，文字会自动居中；这就是 Auto Layout 的价值。

上图里的三个例子很适合新手练习：按钮适合横向 Auto Layout，列表项适合头像、文字、右侧箭头自动对齐，卡片适合让封面、标题、价格、按钮从上到下排列。只要内容之间有明确顺序，就优先考虑 Auto Layout，而不是手动一个个拖位置。

### 核心属性

**方向（Direction）** ：

- Horizontal：子元素横向排列（对应 `flex-direction: row` ）
- Vertical：子元素纵向排列（对应 `flex-direction: column` ）
- Wrap：自动换行（对应 `flex-wrap: wrap` ）

**间距（Gap）** ：

- 固定间距：所有子元素之间的间隔固定（对应 `gap` ）
- Auto：自动分配剩余空间（对应 `justify-content: space-between` ）

**内边距（Padding）** ：

- 四边统一设置，或展开为上下/左右分别设置（对应 `padding` ）

**对齐（Alignment）** ：

- 主轴：控制子元素在主轴方向的分布（start/center/end/space-between）
- 交叉轴：控制子元素在垂直于主轴方向的对齐（start/center/end/baseline/stretch）

**子元素尺寸** ：

- Fixed：固定尺寸
- Hug Contents：根据内容收缩（对应 `width: fit-content` ）
- Fill Container：填充父容器剩余空间（对应 `flex: 1` ）

### 自动布局的实际价值

没有 Auto Layout 时，文字变长后你要手动拖按钮宽度，再挪旁边元素；用了 Auto Layout 后，文字变长，按钮会自己变宽，周围元素也会按规则重新排列。

一个设计良好的 Auto Layout 组件，在不同语言、不同内容长度下都能自动适应，这正是前端工程师期望的设计稿表现方式。

### 新手最应该掌握的 3 个 Auto Layout 场景

**场景一：按钮**

按钮建议用横向 Auto Layout，padding 设为上下 12、左右 20，图标和文字之间的 gap 设为 8，圆角设为 24。这样按钮文字从“确定”变成“立即预约”时，宽度会自然变长。

按钮不要用“矩形 + 文字”散着放。正确做法是按钮本身就是一个 Auto Layout Frame，文字变长时按钮自动变宽。

**场景二：列表项**

列表项通常是横向 Auto Layout：左边放图标或头像，中间放标题和副标题，右边放箭头、开关或时间。外层 padding 可以设为 16，内部 gap 设为 12，高度可以固定为 56，也可以根据内容 Hug。

列表项是 APP 里最高频的结构之一。消息列表、设置列表、订单列表，本质都是这个结构的变体。

**场景三：卡片**

卡片通常是垂直 Auto Layout：上面放封面图，下面放内容区。外层 gap 可以设为 12，内容区再单独设置 padding 12 和 gap 8，这样标题、描述、价格、按钮之间会保持稳定间距。

卡片的图片、标题、描述、价格、按钮都应该有明确的层级关系。只要卡片内部用了 Auto Layout，后续加标签、删描述、换按钮，都不会破坏整体排版。

### Auto Layout 常见报错感受：为什么它“不听话”

新手经常觉得 Auto Layout 不听话，通常是这几个原因：

| 现象 | 原因 | 解决方法 |
| --- | --- | --- |
| 子元素不能随便拖 | Auto Layout 会接管排列顺序 | 在图层面板调整顺序，或修改方向和对齐 |
| 元素宽度不变化 | 子元素尺寸是 Fixed | 改成 Hug Contents 或 Fill Container |
| 内容挤在一起 | Gap 或 Padding 没设好 | 先设置统一间距，再微调 |
| 卡片宽度撑爆 | 子元素设成了 Hug，内容太长 | 父级固定宽度，子元素用 Fill |
| 文字换行后布局乱 | 文本框高度固定 | 文本高度改成 Auto Height |

记住一个判断原则： **内容决定尺寸，用 Hug；父级决定尺寸，用 Fill；完全固定不变，用 Fixed。**

## 十、布局约束与栅格：像素级的秩序感

### 布局约束（Constraints）

Constraints 定义了子元素在父 Frame 尺寸变化时的跟随行为，类似 CSS 中的 `position: absolute` + 定位属性。

水平约束：

- **Left** ：子元素距父容器左边缘保持固定距离
- **Right** ：距右边缘固定
- **Left & Right** ：左右边距都固定（元素宽度随父容器变化）
- **Center** ：保持在水平中心
- **Scale** ：按比例缩放

垂直约束：同理，替换为 Top / Bottom / Top & Bottom / Center / Scale。

**典型应用** ：设计一个全宽的 Header 导航栏时，左侧 Logo 设为 Left，右侧用户头像设为 Right，中间搜索框设为 Left & Right（拉伸填充）。当设备宽度变化时，导航栏自动适配。

### 栅格系统（Grid）

选中 Frame → 右侧属性栏 → 点击 Grid 右侧的 `+` ，可添加三种栅格辅助线：

**Grid（点阵格）** ：均匀分割的小方格，精确对齐像素使用。

**Columns（列栅格）** ：最常用的布局栅格，通常设置为：

- Web 设计：12 列，间距（Gutter）24px，内边距（Margin）各 24px
- 移动端：4 列或 6 列，间距 16px，内边距 16px

**Rows（行栅格）** ：定义垂直方向的基准线，常与 8px 基础网格配合使用。

## 十二、图标绘制四大技法：从扁平到 2.5D

图标绘制是衡量 Figma 技能水平的重要维度，以下四种技法覆盖主流图标风格。

### 12.1 磨砂玻璃图标（Frosted Glass）

磨砂图标是近年 iOS 和 macOS 风格的主流，核心在于背景模糊 + 半透明叠加。

**实现步骤** ：

1. 准备一个色彩丰富的背景图（渐变或照片）
2. 在背景上放置图标容器 Frame，填充白色，透明度 20-30%
3. 为容器添加 Background Blur（背景模糊），半径 20-40px
4. 添加白色内描边，透明度 40%（模拟玻璃边缘高光）
5. 添加轻微白色 Drop Shadow（扩散 0，模糊 20，透明度 20%）
6. 在容器内绘制图标符号，白色，透明度 80-90%

**关键参数** ：Background Blur 半径越大，磨砂效果越明显；白色填充透明度控制整体亮度。

### 12.2 微质感图标（Neumorphism / Skeuomorphism Lite）

微质感（新拟物）风格通过双阴影技术模拟从背景中凸起的效果。

**实现步骤** ：

1. 确定背景色（如 `#E0E5EC` ，偏灰白的柔和色调）
2. 图标容器使用与背景 **完全相同** 的颜色填充
3. 添加两层阴影：
	- 亮阴影：左上方，白色（ `#FFFFFF` ），模糊 10-15px，扩散 1px，透明度 70%
		- 暗阴影：右下方，深色（ `#A3B1C6` ），模糊 10-15px，扩散 1px，透明度 70%
4. 图标符号用中等深度的色彩，避免高对比度

**注意** ：微质感对背景色要求极高，只有在浅灰、米白等低饱和度背景上效果才理想，不适合深色或彩色背景。

### 12.3 旋转造型图标

利用 Figma 的旋转复制功能（ `Cmd + D` 复制后旋转）创造对称放射状图案。

**实现步骤** ：

1. 绘制一个基础形状（如水滴、叶片、扇形）
2. 设置旋转中心：使用 Pen 工具在目标中心点绘制参考，配合 Smart Alignment
3. `Cmd + D` 复制，旋转特定角度（如 45° 得到 8 份，30° 得到 12 份）
4. 继续 `Cmd + D` ，保持相同旋转增量，直至闭合一圈
5. 用 Union 合并所有形状，或保持分离为多彩版本

**技巧** ：每个扇形使用不同透明度或色相偏移，可产生渐变旋转的视觉效果。

### 12.4 2.5D 图标（等距轴测投影）

2.5D（也称轴测图、Isometric）是界于平面和 3D 之间的视觉风格，通过固定角度的透视模拟立体感。

**等距网格设置** ：

- 添加一个 Rows 栅格，高度 8px
- 利用 Transform 面板，将形状倾斜 30° 角（对应等距投影）
- 或使用 **Isometric** 插件自动生成等距辅助线

**绘制流程** ：

1. 先绘制正面（Front Face）：正常的矩形/形状，填充最亮色
2. 绘制顶面（Top Face）：倾斜变形，填充次亮色（约亮面亮度的 85%）
3. 绘制侧面（Side Face）：倾斜变形，填充最暗色（约亮面亮度的 70%）
4. 组合三个面，细节处用 Subtract 挖出结构线

**配色原则** ：使用同一个基础颜色，通过调整亮度（HSB 中的 B 值）区分三个面，不是混合其他颜色，保持色调纯净。

### 新手做 APP 项目的正确顺序

很多新手做项目的顺序是错的：先找好看的图，先画首页，先做视觉效果。这样很容易画到一半发现导航不合理、页面尺寸不统一、组件重复、内容放不下。专业项目更推荐按下面的顺序：

| 步骤 | 要做什么 | 产出物 |
| --- | --- | --- |
| 1\. 看竞品 | 截图并分析同类 APP 的首页、分类、详情、我的、消息 | 竞品截图板 + 分析表 |
| 2\. 定页面 | 列出这个 APP 至少需要哪些页面 | 页面清单 |
| 3\. 搭框架 | 先画低保真，不加复杂颜色和图片 | 低保真线框图 |

| 5\. 做组件 | 按钮、Tab、卡片、列表项、标签、头像 | 基础组件库 |
| 6\. 画首页 | 用组件拼首页，不要每个模块重新画 | 首页高保真 |
| 7\. 扩展页面 | 发现、消息、我的、详情、表单等 | 多页面高保真 |
| 8\. 做交互 | 用 Prototype 连主要流程 | 可点击原型 |
| 9\. 做交付 | 标注、切图、命名、整理文件 | 交付文件 |

新手可以把“首页”当成综合训练场，因为首页几乎包含了所有 UI 能力：导航、搜索、Banner、金刚区、卡片、列表、底部 Tab、图片填充、组件复用、滚动区域。

| Home Indicator | 34 pt | iPhone 底部手势区域，不建议放重要按钮 |

看这张图时，重点不是死记每个数字，而是理解“哪些区域不能乱放内容”。顶部状态栏和底部手势区属于系统区域，尽量不要放关键按钮；页面中真正用来承载 Banner、金刚区、列表和卡片的是中间内容区；底部 Tab 要固定在底部，不要跟着内容列表一起滚走。

**栅格设置** ：

- 选中 Frame → 右侧属性栏 Grid 区域 → 点击 `+`
- 添加 **Column** ：4 列 / Gutter 16 / Margin 左右各 16
- 添加 **Row** 辅助 8pt 基准（可选）

**为什么是 4 列？** 医美 APP 首页的金刚区入口典型是 **4 个一行** 或 **5 个一行** ，4 列栅格能让两种布局都对齐到栅格线。

**基础样式定义** （在动手之前）：

| 样式名 | 值 | 用途 |
| --- | --- | --- |
| `color/brand/primary` | `#00C8C8` （青色） | 主品牌色，借鉴新氧 |
| `color/brand/secondary` | `#FF6B9A` （粉色） | 强调色（活动、优惠） |
| `color/text/primary` | `#1A1A1A` | 一级文字 |
| `color/text/secondary` | `#666666` | 二级文字 |
| `color/text/tertiary` | `#999999` | 辅助说明 |
| `color/bg/page` | `#F7F7F7` | 页面背景 |
| `color/bg/card` | `#FFFFFF` | 卡片背景 |
| `color/border` | `#EBEBEB` | 分割线 |
| `text/h1` | SF Pro / 24 / Semibold | 页面标题 |
| `text/h2` | SF Pro / 18 / Semibold | 区块标题 |
| `text/body` | SF Pro / 14 / Regular | 正文 |
| `text/caption` | SF Pro / 12 / Regular | 标注 |

新手在这一阶段要特别注意：先不要追求页面丰富，先把“底层规则”定下来。比如所有页面左右边距都用 16，模块间距都用 12 或 16，卡片圆角都用 8，按钮高度都用 48。只要规则统一，页面即使简单，也会显得干净。

一个新手可执行的低保真搭建流程：

1. 新建 `Home` Frame，尺寸 375 × 812。
2. 画顶部状态栏区域，占位高度 44。
3. 画顶部导航区域，占位高度 56。
4. 画底部 TabBar，占位高度 83。
5. 中间剩余区域画一个 ScrollView Frame。
6. 在 ScrollView 里依次放 Banner、金刚区、推荐区、信息流。
7. 所有模块先用灰色块代替，不急着加图片和颜色。

低保真阶段的目标不是好看，而是确认信息结构。只要结构没问题，后面视觉美化才有意义。

### 13.2 导航栏与组件：搭好骨架

对应视频「 **02.导航栏和组件** 」。

**顶部导航（Top Bar）结构** ：

顶部导航可以分成 3 个区域：左边是城市定位，中间是搜索框，右边是消息入口。最外层用一个高度 56 的 Frame，左右 padding 设为 16，内部用横向 Auto Layout 排列。

| 区域 | 建议做法 | 细节 |
| --- | --- | --- |
| 城市定位 | 图标 + 城市名，宽度用 Hug | 例如定位图标加“上海” |
| 搜索框 | 宽度用 Fill，高度 36，圆角 18 | 放搜索图标和占位文案“搜索项目/医生/机构” |
| 消息入口 | 宽度用 Hug | 图标右上角可以加未读红点 |

**底部 Tab Bar** ——医美 APP 的核心导航。结合新氧和更美的实际产品，4 个 Tab 是最佳选择：

底部导航建议保持 4 个入口：首页、社区、商城、我的。每个入口由图标和文字组成，选中态用品牌色，未选中态用灰色。

**Tab Bar 组件变体设计** ：

| 变体属性 | 取值 |
| --- | --- |
| `state` | `default` / `active` |
| `tab` | `home` / `community` / `shop` / `profile` |

这样一个组件就能覆盖 8 种状态（4 Tab × 2 状态）。使用时只需切换变体属性，无需手动替换图标或文字。

**关键细节** ：

- TabBar 高度 49 pt + 底部 Home Indicator 34 pt = **总高 83 pt**
- 选中状态用主色（ `#00C8C8` ），未选中用 `#8A8A8A`
- 文字 10 pt 即可，避免与图标抢空间
- 顶部 1 px 分割线用 `color/border`

新手做导航栏时，最容易忽略“状态”。底部 Tab 至少要有选中和未选中两种状态；搜索框至少要有默认、输入中、搜索结果三种状态；消息图标可能有未读角标。你可以先不把所有状态都画出来，但组件设计时要给这些状态留位置。

一个合格的底部 Tab 组件可以这样做：

1. 先做单个 `TabItem` ，内部是 Icon + Label 的垂直 Auto Layout。
2. 做 `active=false` 和 `active=true` 两个变体。
3. 把 4 个 TabItem 放进 `TabBar` ，横向 Auto Layout，分布方式用 Space Between。
4. `TabBar` 高度设为 83，底部留出 Home Indicator 区域。
5. 在页面里固定到底部，不跟随 ScrollView 一起滚动。

### 13.3 快速入口（金刚区）：分三步实现

对应视频「 **03-06.快速入口 1/2/3 + 完成** 」，这是新手最容易翻车的环节，必须分步拆解。

#### 第一步：单个入口组件（视频 03）

单个入口是一个 **带图标和文字的垂直组合** ：

做单个入口时，先画一个 48 × 48 的圆形图标背景，再把 24 × 24 的图标放在正中间，下面放 12pt 的文字。整个入口用垂直 Auto Layout，图标和文字之间的 gap 设为 8。

**关键决策** ：图标容器是 **圆形** vs **圆角矩形** ？医美 APP 主流选择是 **圆形 48px** ——视觉更柔和、留白更舒服。新氧采用的就是这种方案。

#### 第二步：一行入口（视频 04）

将 4 个 QuickEntry 横向排列：

把 4 个入口放进同一行，父级 Frame 用横向 Auto Layout，分布方式选择 `space-between` 。每个入口本身保持 Hug，不要强行拉伸。

**为什么用 `space-between` 而不是 `gap`?** 因为入口数量可能变化（4 个 vs 5 个），用 `space-between` 配合 padding，可以自适应所有宽度，永远视觉均衡。

#### 第三步：多行金刚区（视频 05）

医美 APP 的金刚区通常是 **2 行 × 5 列 = 10 个入口** ，覆盖：

第一行可以放业务入口，例如面部轮廓、眼鼻整形、脂肪管理、皮肤美容、牙齿美白；第二行可以放转化和活动入口，例如 AI 测脸、视频面诊、直播间、限时秒杀、新人福利。

构建方式：

外层 `KingKongArea` 用垂直 Auto Layout，padding 设为 16，两行之间的 gap 设为 16。每一行再用横向 Auto Layout，让 5 个入口平均分布。

**色彩规律** （参考新氧）：

- 业务类入口（面部/眼鼻等）用相同的 **浅青色** 背景 + 主色图标
- 营销类入口（秒杀/福利）用 **橙红色渐变** 背景 + 白色图标，制造视觉差异引导点击

#### 完成校验（视频 06）

把整个金刚区放到首页里，对照 4 列栅格检查对齐。如果某个入口偏移，多半是 IconContainer 没有居中，或者 Auto Layout 的 align 设错了。

### 13.4 卡片设计：信息分发的核心

对应视频「 **07.卡片内容** 」。

医美 APP 首页流的卡片有三种类型，全部基于同一套基础组件变体衍生：

**1\. 项目卡片（商品）**

项目卡片建议固定宽度，比如 168。上方是正方形封面图，打开 `Clip Content` ，左上角可以放“热销”标签；下方是内容区，padding 设为 8，依次放项目标题、机构信息、价格和原价。标题最多显示 2 行，价格用品牌色和较粗字重，原价用灰色并加删除线。

**2\. 日记卡片（用户案例）**

医美的核心内容是「 **美丽日记** 」（术前 vs 术后对比图）：

日记卡片更像内容社区的帖子。顶部放头像、昵称和关注按钮，中间放 2 行以内的日记文字，再放术前/术后对比图，底部放项目标签、点赞数和评论数。图片比文字更重要，所以图片区域要给足空间。

**3\. 机构/医生卡片**

医生卡片的重点是信任感。左侧放 64 × 64 的圆形头像，右侧放姓名、职称、资质徽章和擅长项目，最右或底部放“立即咨询”按钮。这里不要过度装饰，信息清楚比视觉花哨更重要。

**统一规范** ：所有卡片 **圆角 8 pt** ， **间距 12 pt** ， **阴影 `0 2 8 rgba(0,0,0,0.05)`** ——通过 Effects 样式统一管理，一处修改全局生效。

### 13.5 完整首页拼装

对应视频「 **08.界面完成** 」。把前面所有组件按层级拼装：

首页拼装时，从上到下放：状态栏、顶部导航、可滚动内容区、底部 TabBar。可滚动内容区里再依次放 Banner、金刚区、限时秒杀、推荐标题、信息流。底部 TabBar 不放进滚动内容里，否则页面滚动时底部导航会跟着跑。

**Auto Layout 妙用** ：整个首页用一个垂直 Auto Layout 容器，所有区块按出现顺序加进去。任何区块的高度变化、新增/删除区块，整个页面自动重排， **不需要手动调一个像素** 。

新手拼首页时，可以按这个层级来做，别把所有东西平铺在一个页面下面：

更自然的命名方式是：最外层叫 `HomePage` ；顶部区域叫 `TopBar` ；中间滚动区域叫 `ScrollView` ；滚动区域里的模块分别叫 `BannerSection` 、 `QuickEntrySection` 、 `FlashSaleSection` 、 `RecommendSection` 和 `FeedSection` ；底部固定导航叫 `TabBar` 。

这样做的好处是：如果你要整体移动推荐区，只要选中 `RecommendSection` ；如果要隐藏限时秒杀，只要隐藏 `FlashSaleSection` ；如果要换首页顺序，只要在左侧图层面板拖动模块顺序。

![[_posts/设计/Figma/media/075ed50f57b3814cbdbf0f0a2cd13a3b_MD5.webp]]

完整项目图的价值在于帮助你检查「页面之间是否像同一个产品」。单页做漂亮不难，真正专业的项目要在首页、社区、医院列表、项目详情、预约表单、问答和个人中心之间保持统一的色彩、字体、圆角、图标风格和信息密度。

### 13.6 其他四个页面

参考 Part 2 课程「 **07-09 发现/消息/我的页面制作** 」。

**社区页（社区/发现）** ：

- 顶部 Segmented Control（推荐 / 整形 / 皮肤 / 牙齿）：用组件变体处理选中/未选中
- 内容用 **瀑布流（Masonry）** ：左右两列，每列内的 DiaryCard 错落排列
- 因为图片高度不一，必须用 **2 个垂直 Auto Layout 列** 而不是 Grid

**商城页** ：

- 顶部分类金刚区（与首页风格保持一致，但更密集）
- 排序选项（综合 / 销量 / 价格 / 评分）
- 商品卡片瀑布流（密度更高）

**消息页** ：

- 顶部「系统通知 / 评论 / 点赞 / 私信」四个金刚入口（每个带未读数角标）
- 消息列表：头像 48 + 内容 + 时间 + 未读角标
- 未读角标关键参数： **最小宽度 18** （一位数时显示圆形）/ **Hug Contents 横向** （两位数时变成胶囊）/ 红色 `#FF4D4F`

**我的页** ：

- 顶部用户信息块：头像 80 圆形 + 昵称 H2 + 等级标签
- 数据三列：发布 / 关注 / 粉丝 / 获赞，用 Auto Layout 等分
- 「我的订单」六个状态金刚入口：待付款 / 待消费 / 待评价 / 已退款 / 退换 / 全部
- 功能列表：每行「Icon + Label + RightArrow」用 ListItem 组件，避免重复劳动

## 十四、数据驱动设计：插件替换真实数据

手动填写每个设计元素的内容不仅低效，还容易导致设计与真实场景脱节。Figma 提供了多种数据填充方案。

### 方案一：谷歌表格插件

**Google Sheets Sync** 插件允许将 Google Sheets 中的数据直接映射到 Figma 组件。

**配置步骤** ：

1. 在 Google Sheets 创建数据表，列名为字段名（如 `name` 、 `avatar` 、 `price` ）
2. 在 Figma 中，将组件中的文字图层重命名为对应字段名（如图层名为 `{{name}}` ）
3. 运行 Google Sheets Sync 插件，粘贴 Sheet 的分享链接
4. 点击 Sync，插件会自动遍历组件实例，将对应字段数据填入对应图层

### 方案二：数据采集器（Data Populator）

对于本地 JSON 数据或不方便使用 Google Sheets 的场景，Data Populator 插件支持：

- 上传本地 JSON 文件
- 图片字段自动从 URL 抓取并填充
- 支持随机化和循环填充

**实际效果** ：30 个商品卡片，每个卡片有真实的商品图、商品名、价格、评分数据，一键填充，比手动操作节省 95% 的时间。

## 十五、组件库搭建：设计系统的核心工程

完整的组件库（Design System）是大型项目和团队协作的根基。

### 组件分层结构

组件库可以分成 4 层理解：先定基础规则，再做小组件，最后组合成页面模块。

| 层级 | 包含内容 | 例子 |
| --- | --- | --- |
| 基础层 Foundations | 颜色、字体、间距、圆角、阴影 | Color Tokens、Typography、Spacing、Shadow |
| 原子组件 Atoms | 最小可复用元素 | Icon、Avatar、Badge、Tag、Divider |
| 分子组件 Molecules | 由多个原子组合的小模块 | Button、Input、Checkbox、Switch、Toast |
| 业务组件 Organisms | 可以直接放到页面里的大模块 | Navigation Bar、Tab Bar、Card、Modal、List Item |

### 命名规范

良好的命名规范让组件库可被快速检索：

命名建议使用“类别 / 组件名 / 变体属性”的格式。例如 `Button / Primary / Large / Default` 表示大号主按钮的默认状态， `Input / Text / Error` 表示文本输入框的错误状态， `Card / Product / Horizontal` 表示横向商品卡片。

图层命名同样重要，保持与代码变量名一致，可以直接用作开发参考：

好的图层名应该像 `title` 、 `subtitle` 、 `thumbnail` 、 `price-tag` 这样清楚具体。不要保留 `矩形 1` 、 `Group 23` 、 `椭圆` 这种默认命名，自己过几天再打开都会看不懂。

### 颜色 Token 设计

避免直接在样式名中写颜色值，改为按语义命名：

比如 `#1677FF` 可以先归到 `color/blue/500` ，再映射成 `color/action/primary` ； `#FF4D4F` 可以归到 `color/red/500` ，再映射成 `color/feedback/error` ； `#52C41A` 可以归到 `color/green/500` ，再映射成 `color/feedback/success` 。

这样当品牌色变化时，只需修改语义 Token 的引用，所有使用该 Token 的组件自动更新。

![[_posts/设计/Figma/media/5a95303addabebc89dd18807ee7644a5_MD5.webp]]

视觉规范不是给作品集凑页面，而是保证多人协作和后续迭代不变形。课程项目里的规范至少覆盖颜色、字体、按钮、图标、列表项和页面示例；如果要交付真实团队，建议再补充间距 Token、圆角 Token、阴影样式、表单状态、空状态、加载状态和错误状态。

上面这类长图适合放在项目结尾，用来告诉别人“这个界面为什么长这样”。新手做作品集时，不要只放最终页面，也要把颜色、字体、按钮、图标、列表卡片和页面效果放在一起展示。这样面试官或客户能看出你不是只会临摹页面，而是在按一套规则做设计。

## 十七、交互演示与样机套用：让设计活起来

### 17.1 Figma Prototype 交互

在 Prototype Tab 中为 Frame 之间创建交互连线：

**基本交互** ：选中触发元素 → 点击右侧圆圈箭头拖拽到目标 Frame → 设置触发方式和动画：

| 触发方式 | 场景 |
| --- | --- |
| On Click | 点击触发（最常用） |
| On Hover | 鼠标悬浮触发（Web 设计常用） |
| On Drag | 拖拽触发（轮播图） |
| After Delay | 延时自动触发（加载动画后跳转） |

| 动画类型 | 效果 |
| --- | --- |
| Instant | 无动画瞬间切换 |
| Dissolve | 淡入淡出 |
| Smart Animate | 智能匹配相同图层做补间动画（最酷） |
| Slide In/Out | 滑入滑出，可设置方向 |
| Push | 推入效果（类似 iOS Navigation） |

**Smart Animate** 是 Figma 的招牌功能：两个 Frame 中有 **同名图层** 时，Prototype 播放时会自动计算该图层从 A 状态到 B 状态的过渡动画（位置、尺寸、颜色变化都能做补间），实现类似 iOS 共享元素过渡的效果，无需任何手动设置关键帧。

### 17.2 APP 套样机

将设计稿放入真实设备样机（Mockup）中，大幅提升汇报和展示效果。

**方法一：图片填充法** （Figma 原生）

1. 在样机素材中找到屏幕区域（通常是一个矩形或专用图层）
2. 将该区域的填充类型改为「图片填充」
3. 选择你的设计稿截图作为填充图片
4. 调整填充模式为 Fill 或 Fit

**方法二：Mockuuups Studio 插件**

1. 安装 Mockuuups Studio 插件
2. 选中设计好的 Frame
3. 运行插件，从 300+ 设备样机中选择
4. 插件自动将 Frame 渲染到样机的屏幕中，保持透视和倒影效果

**方法三：摹客平台** 摹客平台内置了常见设备样机模板，上传设计后可在线直接套用并导出。

## 十八、团队协作与组件推送管理

当团队规模扩大，设计文件不再是个人工作区，而是多人协作的共享空间。

### 组件库的团队发布

组织级别的共享组件库（Team Library）是 Figma 专业版的核心功能：

1. 在专属的 **Design System 文件** 中维护所有组件和样式
2. 点击左侧 Assets 面板顶部 → **Publish changes** ，将当前版本发布为团队库
3. 团队成员在自己的文件中打开 Assets → 点击团队库 → 启用对应库文件
4. 启用后，团队成员可以在任意文件中使用这些组件，无需手动复制

### 版本管理与变更通知

当设计系统组件更新时，使用该组件的团队成员会收到通知：

- 打开文件时，Figma 提示有更新的组件
- 可以选择 **全部更新** 或 **逐个审查后更新**
- 如果更新破坏了某个实例，可以通过 **Detach instance** 脱离连接，保留当前外观

### 分支与合并（Branch）

类似 Git 的 Branch 机制，Figma 允许在不影响主文件的情况下创建设计分支：

1. 文件菜单 → Create Branch
2. 在分支上进行探索性设计
3. 完成后提交 Merge Request，团队 Review 后合并到主文件

这个工作流特别适合大型重构或 A/B 测试方案的并行设计。

## 总结：Figma 全链路工作流回顾

完整的 Figma 工作流可以按 8 步走：先做需求分析，再画低保真线框图；接着搭设计系统，包括颜色、字体、间距和组件；然后进入高保真视觉设计，用组件系统填充真实内容；页面完成后做交互原型，发给团队评审；最后进入开发交付，用 Dev Mode / Inspect 或摹客查看标注、切图和代码参考。上线之后还要继续迭代，用 Branch 或版本记录管理新的设计方案。

Figma 的核心价值从来不只是画图——它是 **设计与开发之间最短的一条路** 。当设计师熟练掌握 Auto Layout、组件系统、Dev Mode / Inspect 交付等机制后，会发现自己与开发工程师的沟通效率产生质变：不再是"我觉得应该这样"，而是"这里的 padding 是 16px，用的是 `color/action/primary` ，组件叫 `Button/Primary/Medium` "——这才是现代 UI 设计师应有的专业表达。

## 附录 B：新手十大常见陷阱

总结自课程反复强调的避坑点：

1. **用 Group 做手机屏幕** —— 必须用 Frame，否则无法响应式、无法 Prototype
2. **不命名图层** —— `矩形 23` 这种命名让交付时开发抓狂，也让自己一周后看不懂
3. **不用样式库直接写颜色值** —— 改一次主题色要改几百处
4. **复制粘贴组件而不用 Instance** —— 改一处要改 N 处，丧失组件意义
5. **Auto Layout 嵌套过深** —— 超过 5 层后调试困难，建议拆分组件
6. **图标用 PNG 不用 SVG** —— 缩放失真，体积也大
7. **忽略 Constraints 设置** —— Frame 缩放时元素全乱跑
8. **滥用阴影和模糊** —— 性能差且视觉脏，统一在 Effects 样式中管理
9. **栅格不一致** —— 部分页面 4 列，部分页面 12 列，导致风格断裂
10. **交付时不清理文件** —— 用 Clean Document 插件清理隐藏图层和废弃元素

## 附录 C：学习路径推荐

第 1 周练基础工具：熟悉工具栏快捷键，掌握 Frame、Group、形状、钢笔和文字工具，并完成 5 个简单图标临摹。

第 2 周练进阶概念：重点学习布尔运算、组件、变体、Auto Layout 和 Constraints。尤其是 Auto Layout，要多做按钮、列表和卡片练习。

第 3 周做设计系统：整理颜色样式、文字样式和组件分层，尝试做一套 20 个以上组件的小型设计系统。

第 4 到第 6 周做项目实战：可以跟着本文的医美 APP，也可以换成电商 APP、SaaS 后台或个人项目。目标是完成至少 6 个页面，并做出能点击的交互原型。

### 新手最容易混淆的 5 组概念

**Frame vs Group**

Frame 是容器，Group 是临时打包。做页面、卡片、按钮，用 Frame；临时一起移动几个图层，可以用 Group。

**Component vs Instance**

Component 是源头，Instance 是复制出来用的版本。改 Component 会影响所有 Instance；改单个 Instance 只影响它自己。

**Hug vs Fill vs Fixed**

Hug 是跟随内容，Fill 是填满父级，Fixed 是固定尺寸。按钮通常宽度 Hug，列表中间文字区域通常 Fill，图标通常 Fixed。

**Fill vs Stroke**

Fill 是里面的颜色，Stroke 是边框。一个按钮可以有粉色 Fill，也可以有灰色 Stroke。

**Prototype vs Dev Mode**

Prototype 给产品、客户、老板看交互流程；Dev Mode 给开发看尺寸、颜色、代码和切图。

## 附录 E：7 天入门练习计划

如果你想像新手一样一步步练，不建议第一天就做完整 APP。下面这个 7 天计划更适合零基础。

### 第 1 天：熟悉界面和基础工具

目标：知道画布、Frame、图层、右侧属性栏分别是什么。

练习任务：

1. 新建一个手机 Frame。
2. 画 5 个矩形、3 个圆形、3 段文字。
3. 修改它们的颜色、圆角、尺寸和位置。
4. 学会用 `Alt/Option` 查看间距。

完成标准：你能说清楚 X/Y/W/H 分别代表什么，能用数值把元素放到指定位置。

### 第 2 天：做一个按钮和输入框

目标：理解 Frame、文字、Auto Layout 的基础用法。

练习任务：

1. 做一个主按钮，高度 48，圆角 24。
2. 按钮文字改成“立即预约”，按钮宽度自动适配文字。
3. 做一个搜索框，左侧放搜索图标，右侧放占位文字。
4. 把按钮和搜索框都创建为组件。

完成标准：按钮文字变长时，按钮不会散架。

### 第 3 天：做底部 TabBar

目标：理解组件变体和选中状态。

练习任务：

1. 做 4 个 Tab：首页、社区、消息、我的。
2. 每个 Tab 包含图标和文字。
3. 做选中和未选中两种状态。
4. 把它们组合成一个底部 TabBar。

完成标准：你可以快速切换某个 Tab 的选中状态。

### 第 4 天：做商品卡片

目标：理解卡片结构和图片填充。

练习任务：

1. 创建 `ProductCard` Frame。
2. 顶部放图片容器，使用图片 Fill。
3. 下方放标题、机构名、价格、标签。
4. 整个卡片用垂直 Auto Layout 管理。

完成标准：标题变成两行时，下面内容能自动下移。

### 第 5 天：临摹一个首页首屏

目标：把前 4 天的能力拼起来。

练习任务：

1. 选一张新氧或更美首页截图作为参考。
2. 只临摹第一屏，不要做完整长页面。
3. 包含顶部栏、Banner、金刚区、一个推荐模块、底部 Tab。
4. 尽量使用组件，不要每个元素都重新画。

完成标准：首页首屏结构完整，左右边距统一，模块间距统一。

### 第 6 天：整理视觉规范

目标：从“画页面”过渡到“做系统”。

练习任务：

1. 建立颜色样式：主色、文字色、背景色、分割线。
2. 建立文字样式：标题、正文、辅助说明。
3. 整理组件：Button、TabBar、ProductCard、ListItem。
4. 给每个组件命名。

完成标准：你能从 Assets 面板里找到并复用组件。

### 第 7 天：做简单交互和交付检查

目标：让设计稿可以演示、可以交给别人看。

练习任务：

1. 复制首页，做一个项目详情页。
2. 在 Prototype 里设置“点击商品卡 → 跳转详情页”。
3. 标记需要导出的图标或图片。
4. 用 Dev Mode / Inspect 查看按钮尺寸、颜色和间距。

完成标准：你能分享一个可点击原型链接，并能向开发说明一个按钮的尺寸、颜色、圆角和状态。

完成这 7 天后，再回头看完整 APP 项目，会轻松很多。你已经掌握了 Figma 最核心的工作方式：用 Frame 搭结构，用组件复用，用 Auto Layout 管排版，用 Prototype 做演示，用 Dev Mode 做交付。
