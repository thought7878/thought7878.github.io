Next.js 的渲染方式可以按 *Pages Router 经典模式* 和 *App Router 现代模式* 来理解。

`核心目标`是：在**不同页面/组件**上选择“**何时、何地、如何生成 HTML**”。

## 一、Pages Router 经典 4 种

| 渲染方式       | 何地（渲染位置） | 何时（生成时机）   | 优点          | 缺点        | 应用场景       | 常用 API                        | 特点                   |
| ---------- | -------- | ---------- | ----------- | --------- | ---------- | ----------------------------- | -------------------- |
| CSR        | 客户端      | 请求时/浏览器运行时 |             | 首屏慢、SEO 弱 | 适合后台/登录后页面 | useEffect、SWR、React Query     | 首屏慢、SEO 弱，适合后台/登录后页面 |
| SSR        | 服务端      | 请求时        | 实时数据、SEO 好  | 服务器压力大    |            | getServerSideProps            | 实时数据、SEO 好，但服务器压力大   |
| SSG        | 构建       | 构建时        | 可 CDN 最快    |           | 适合博客/文档    | getStaticProps、getStaticPaths | 最快、可 CDN，适合博客/文档     |
| ISR 增量静态再生 | 服务端      | 构建后按需/定时再生 | 静态速度 + 内容更新 | 可能短暂陈旧    |            | getStaticProps 返回 revalidate  | 静态速度 + 内容更新，可能短暂陈旧   |


## 二、App Router 现代模式


| 方式                      | 何地（渲染位置） | 何时（生成时机）   | 优点                              | 缺点     | 应用场景                                          | 常用 API                       |
| ----------------------- | -------- | ---------- | ------------------------------- | ------ | --------------------------------------------- | ---------------------------- |
| 服务器组件（RSC）              | 服务器      | 请求时        | 可直接访问数据库、文件系统。<br>不向客户端发送组件 JS。 |        |                                               |                              |
| 静态渲染（Static Rendering）  | 构建       | 构建时        |                                 |        | 动态路由可用 generateStaticParams 预生成。<br>适合内容稳定页面。 |                              |
| 动态渲染（Dynamic Rendering） |          |            |                                 |        |                                               |                              |
| 流式渲染（Streaming SSR）     |          |            |                                 |        |                                               |                              |
| 客户端渲染（CSR）              |          |            |                                 |        |                                               |                              |
| ISR 增量静态再生              | 服务端      | 构建后按需/定时再生 | 静态速度 + 内容更新                     | 可能短暂陈旧 |                                               | getStaticProps 返回 revalidate |
| 部分预渲染（PPR）              |          |            |                                 |        |                                               |                              |
| Edge Runtime            |          |            |                                 |        |                                               |                              |

App Router 默认使用 **React Server Components**，渲染方式更细粒度：

### 服务器组件（RSC）
   - 默认组件类型，在服务器执行。
   - 可直接访问数据库、文件系统。
   - 不向客户端发送组件 JS。

### 静态渲染（Static Rendering）
   - 构建时生成 HTML。
   - 动态路由可用 generateStaticParams 预生成。
   - 适合内容稳定页面。

### 动态渲染（Dynamic Rendering）
   - 每次请求时渲染。
   - 触发条件：使用 cookies()、headers()、searchParams、fetch(..., { cache: 'no-store' })，或 export const dynamic = 'force-dynamic'。
   - 适合个性化、实时数据。

### 流式渲染（Streaming SSR）
   - 基于 React Suspense。
   - 用 loading.tsx 或 \<Suspense\> 先返回骨架，再流式填充慢数据。
   - 提升首屏体验。

### 客户端渲染（CSR）
   - 使用 'use client' + useEffect / SWR / React Query。
   - 注意：客户端组件仍可能被服务端预渲染 HTML，再 hydration；CSR 主要指数据在浏览器获取。

### 增量静态再生（ISR）
   - export const revalidate = 60
   - fetch(..., { next: { revalidate: 60 } })
   - revalidatePath() / revalidateTag() 按需更新。

### 部分预渲染（PPR）
   - 实验性功能。
   - 静态 shell 立即返回，动态部分通过 Suspense 流式填充。
   - 需要 experimental.ppr。

### Edge Runtime
   - export const runtime = 'edge'。
   - 在边缘节点执行 SSR/流式渲染，降低延迟。

## 三、如何选择

- 博客、文档、营销页：**SSG / ISR**
- 电商列表、新闻：**ISR**
- 用户中心、实时数据：**SSR / 动态渲染**
- 后台系统、强交互：**CSR**
- 慢数据、大页面：**Streaming / PPR**
- 现代 Next.js 项目：**App Router + RSC 默认 + 按需静态/动态 + 缓存控制**

## 四、关键注意

- **RSC 不等于 SSR**：RSC 是组件模型，可静态也可动态渲染。
- **ISR 是 SSG 的扩展**，不是完全独立的新渲染。
- **Streaming 可与 SSR/SSG 结合**。
- Next.js 15 起 fetch 默认不缓存，GET Route Handler 默认也不缓存，静态/动态边界与缓存行为随版本变化，实际项目需按版本确认。

一句话总结：Next.js 提供了从 **CSR、SSR、SSG、ISR** 到 **RSC、Streaming、PPR** 的完整谱系，App Router 下默认以 Server Components 为基础，再通过动态 API 和缓存策略决定页面是静态、动态还是流式渲染。
