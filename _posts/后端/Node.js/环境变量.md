>详解 Node.js 的环境变量

在 Node.js 开发中，`环境变量`是非常重要的一部分。它常用于**配置程序运行时的外部参数，例如：**
- 服务端口
- 数据库连接信息
- 第三方服务密钥
- 当前运行环境
- 日志级别
- 功能开关

环境变量的**核心思想**是：
> **把配置从代码中剥离出来，让同一份代码可以在不同环境中运行。**

*例如*开发环境连接本地数据库，生产环境连接线上数据库，**只需要修改环境变量，而不需要修改代码**。

---

# 一、什么是环境变量？

环境变量是操作系统或运行进程提供的一组键值对。

例如：

```bash
PORT=3000
DB_HOST=localhost
NODE_ENV=development
```

在 Node.js 中，可以通过：

```js
process.env
```

访问当前进程的环境变量。

例如：

```js
console.log(process.env.PATH);
console.log(process.env.NODE_ENV);
```

---

# 二、`process.env` 是什么？

`process.env` 是 Node.js 提供的一个对象，里面保存了当前进程启动时继承到的环境变量。

例如：

```js
console.log(process.env);
```

输出类似：

```js
{
  PATH: '/usr/local/bin:/usr/bin:/bin',
  HOME: '/home/user',
  NODE_ENV: 'development',
  PORT: '3000'
}
```

你可以通过它读取环境变量：

```js
const port = process.env.PORT;
```

---

# 三、环境变量的值都是字符串

这是非常重要的一点。

在 Node.js 中：

> `process.env` 中的所有值最终都会被转换为字符串。

例如：

```env
PORT=3000
DEBUG=true
```

读取：

```js
console.log(typeof process.env.PORT);   // "string"
console.log(typeof process.env.DEBUG);  // "string"
```

即使写的是数字或布尔值，读出来也是字符串。

---

## 数字转换

```js
const port = Number(process.env.PORT) || 3000;
```

---

## 布尔转换

错误写法：

```js
if (process.env.DEBUG) {
  console.log("debug mode");
}
```

问题：

```js
process.env.DEBUG = "false";
```

字符串 `"false"` 仍然是真值，所以会进入判断。

正确写法：

```js
const debug = process.env.DEBUG === "true";

if (debug) {
  console.log("debug mode");
}
```

---

# 四、Node.js 如何获取环境变量？

假设系统中设置了：

```bash
export PORT=3000
```

Node.js 中：

```js
console.log(process.env.PORT); // "3000"
```

如果没有设置：

```js
console.log(process.env.PORT); // undefined
```

通常会配合默认值使用：

```js
const port = process.env.PORT || 3000;
```

# 六、设置环境变量的方式

环境变量的设置方式取决于操作系统、启动方式和部署平台。

## 临时设置，仅当前终端有效

```bash
export PORT=3000
export NODE_ENV=development
```

然后启动：

```bash
node app.js
```

---

## 一次性设置并运行

```bash
PORT=3000 NODE_ENV=development node app.js
```

Node.js 内部即可读取：

```js
console.log(process.env.PORT);       // 3000
console.log(process.env.NODE_ENV);   // development
```

---

# 2. Windows CMD 中设置

```cmd
set PORT=3000
set NODE_ENV=development
node app.js
```

---

# 3. Windows PowerShell 中设置

```powershell
$env:PORT="3000"
$env:NODE_ENV="development"
node app.js
```

---

# 4. 使用 `cross-env` 跨平台设置环境变量

在 `package.json` 脚本中直接写：

```json
"start": "PORT=3000 node app.js"
```

在 Windows 上可能不兼容。

可以使用：

```bash
npm install --save-dev cross-env
```

然后：

```json
{
  "scripts": {
    "start": "cross-env PORT=3000 NODE_ENV=development node app.js"
  }
}
```

运行：

```bash
npm start
```

# 七、使用 `.env` 文件管理环境变量

在实际项目中，最常见的方式是使用 `.env` 文件。

`.env` 文件用于存放本地环境变量，例如：

```env
PORT=3000
DB_HOST=localhost
DB_USER=root
DB_PASSWORD=123456
```

Node.js 默认不会自动读取 `.env` 文件，通常需要工具加载。

---

## 方式一：使用 `dotenv`

安装：

```bash
npm install dotenv
```

使用：

```js
require("dotenv").config();

console.log(process.env.PORT);
```

如果 `.env` 中有：

```env
PORT=3000
```

那么：

```js
process.env.PORT === "3000";
```

---

## 方式二：Node.js 20.6+ 内置 `--env-file`

从较新版本的 Node.js 开始，可以直接使用：

```bash
node --env-file=.env app.js
```

这样就不需要安装 `dotenv`。

示例：

```env
PORT=4000
```

启动：

```bash
node --env-file=.env app.js
```

代码：

```js
console.log(process.env.PORT); // 4000
```

# 八、`.env` 文件和环境变量的关系

很多人会混淆这两个概念：

## 环境变量

是操作系统或进程层面的键值对，例如：

```bash
export PORT=3000
```

---

## `.env` 文件

只是一个普通文本文件，用来方便地配置环境变量。

它本身不会自动生效，需要通过：

- `dotenv`
- `node --env-file`
- 其他框架内置机制

加载后，才会写入 `process.env`。

---

# 九、环境变量的优先级

通常来说，真实环境变量优先于 `.env` 文件。

例如：

系统中有：

```bash
export PORT=5000
```

`.env` 中有：

```env
PORT=3000
```

很多工具默认不会覆盖已经存在的环境变量，因此最终可能是：

```js
process.env.PORT === "5000"
```

具体行为取决于加载工具：

- `dotenv` 默认不覆盖已存在的环境变量
- 某些框架可能有自己的优先级规则

---

# 十、`NODE_ENV` 环境变量

`NODE_ENV` 是 Node.js 生态中最常见的环境变量之一。

它用于标识当前运行环境。

常见值：

```bash
development
test
production
```

---

## 示例

```js
if (process.env.NODE_ENV === "production") {
  console.log("生产环境，开启压缩、缓存等优化");
}

if (process.env.NODE_ENV === "development") {
  console.log("开发环境，输出详细日志");
}
```

---

## 设置方式

Linux / macOS：

```bash
export NODE_ENV=production
node app.js
```

或者：

```bash
NODE_ENV=production node app.js
```

Windows CMD：

```cmd
set NODE_ENV=production
node app.js
```

Windows PowerShell：

```powershell
$env:NODE_ENV="production"
node app.js
```

# 十一、在代码中修改环境变量

你可以给 `process.env` 赋值：

```js
process.env.PORT = "8080";
console.log(process.env.PORT); // 8080
```

但是要注意：

> 这只影响当前 Node.js 进程，不会影响系统环境变量，也不会影响已经启动的其他进程。

例如：

```js
process.env.NODE_ENV = "production";
```

只影响当前进程。

---

# 十二、删除环境变量

可以使用 `delete`：

```js
delete process.env.SECRET_KEY;
```

示例：

```js
process.env.SECRET_KEY = "abc";
console.log(process.env.SECRET_KEY); // abc

delete process.env.SECRET_KEY;
console.log(process.env.SECRET_KEY); // undefined
```

---

# 十三、环境变量配置封装

不建议在项目中到处写：

```js
process.env.DB_HOST
```

更好的方式是创建一个配置模块，例如 `config.js`：

```js
require("dotenv").config();

module.exports = {
  port: Number(process.env.PORT) || 3000,

  env: process.env.NODE_ENV || "development",

  db: {
    host: process.env.DB_HOST || "localhost",
    port: Number(process.env.DB_PORT) || 5432,
    user: process.env.DB_USER || "root",
    password: process.env.DB_PASSWORD || "",
  },

  jwtSecret: process.env.JWT_SECRET || "default-secret",

  debug: process.env.DEBUG === "true",
};
```

使用：

```js
const config = require("./config");

console.log(config.port);
console.log(config.db.host);
```

好处：

- 统一读取配置
- 统一类型转换
- 统一默认值
- 方便测试和维护

# 十四、环境变量校验

有些环境变量是必须存在的，例如数据库密码、密钥。

如果缺失，应该尽早报错，而不是运行到一半才失败。

---

## 简单校验

```js
if (!process.env.DB_PASSWORD) {
  throw new Error("环境变量 DB_PASSWORD 未设置");
}

if (!process.env.JWT_SECRET) {
  throw new Error("环境变量 JWT_SECRET 未设置");
}
```

---

## 使用 Zod 校验

安装：

```bash
npm install zod
```

示例：

```js
require("dotenv").config();
const { z } = require("zod");

const envSchema = z.object({
  PORT: z.string().default("3000"),
  DB_HOST: z.string().default("localhost"),
  DB_PORT: z.string().default("5432"),
  DB_USER: z.string().min(1),
  DB_PASSWORD: z.string().min(1),
  NODE_ENV: z.enum(["development", "test", "production"]).default("development"),
});

const parsed = envSchema.safeParse(process.env);

if (!parsed.success) {
  console.error("环境变量校验失败", parsed.error.format());
  process.exit(1);
}

const env = parsed.data;

module.exports = {
  port: Number(env.PORT),
  db: {
    host: env.DB_HOST,
    port: Number(env.DB_PORT),
    user: env.DB_USER,
    password: env.DB_PASSWORD,
  },
  nodeEnv: env.NODE_ENV,
};
```

这种方式在大型项目中非常推荐。

# 十九、环境变量与安全性

环境变量经常用于保存敏感信息，所以安全问题非常重要。

---

## 1. 不要把敏感信息提交到 Git

例如：

```env
DB_PASSWORD=123456
API_SECRET=abcdef
```

不要提交到仓库。

应该在 `.gitignore` 中忽略：

```gitignore
.env
```

---

## 2. 使用 `.env.example` 提供模板

`.env.example` 可以提交：

```env
PORT=3000
DB_HOST=
DB_USER=
DB_PASSWORD=
JWT_SECRET=
```

它只说明需要哪些变量，不包含真实值。

---

## 3. 生产环境使用密钥管理服务

对于敏感配置，可以考虑：

- AWS Secrets Manager
- Google Secret Manager
- Azure Key Vault
- HashiCorp Vault
- Kubernetes Secrets
- 云平台环境变量管理

---

## 4. 避免日志打印敏感变量

不要随便打印：

```js
console.log(process.env);
```

因为可能泄露密钥。

如果必须打印，应该过滤敏感字段：

```js
console.log({
  NODE_ENV: process.env.NODE_ENV,
  PORT: process.env.PORT,
});
```

# 二十二、常见问题与解决方案

---

## 问题 1：`process.env.PORT` 是 `undefined`

可能原因：

1. 没有设置环境变量
2. `.env` 文件没有被加载
3. 没有安装或引入 `dotenv`
4. `.env` 文件路径不对
5. 启动命令不在项目根目录执行

解决：

```js
console.log(process.cwd());
console.log(process.env.PORT);
```

确认当前目录和环境变量是否正确。

---

## 问题 2：`.env` 修改后没有生效

因为环境变量通常在进程启动时读取。

修改 `.env` 后，需要重启 Node.js 进程。

---

## 问题 3：布尔值判断错误

错误：

```js
if (process.env.DEBUG) {
  // 即使是 "false" 也会进入
}
```

正确：

```js
const debug = process.env.DEBUG === "true";
```

---

## 问题 4：数字比较错误

错误：

```js
if (process.env.PORT > 1000) {
  // 不推荐，因为 PORT 是字符串
}
```

正确：

```js
const port = Number(process.env.PORT);

if (port > 1000) {
  // ...
}
```

---

## 问题 5：生产环境读取不到 `.env`

很多生产环境并不使用 `.env` 文件，而是通过平台注入环境变量。

例如：

```bash
docker run -e DB_PASSWORD=secret myapp
```

这时容器内没有 `.env` 文件，但 `process.env.DB_PASSWORD` 仍然可以读取。

# 二十三、Node.js 环境变量的最佳实践

---

## 1. 所有配置尽量通过环境变量注入

例如：

```js
const port = process.env.PORT || 3000;
```

不要写死：

```js
const port = 3000;
```

---

## 2. 敏感信息不要硬编码

错误：

```js
const secret = "my-secret";
```

正确：

```js
const secret = process.env.JWT_SECRET;
```

---

## 3. 使用配置中心或配置模块

例如：

```js
module.exports = {
  port: Number(process.env.PORT) || 3000,
  nodeEnv: process.env.NODE_ENV || "development",
};
```

---

## 4. 必要变量启动时校验

```js
const requiredEnvVars = ["DB_HOST", "DB_USER", "DB_PASSWORD"];

for (const key of requiredEnvVars) {
  if (!process.env[key]) {
    throw new Error(`Missing required environment variable: ${key}`);
  }
}
```

---

## 5. `.env` 不要提交到 Git

```gitignore
.env
```

可以提交：

```gitignore
.env.example
```

---

## 6. 不要把整个 `process.env` 输出到日志

避免泄露敏感信息。

---

## 7. 区分开发、测试、生产环境

```env
NODE_ENV=development
```

```env
NODE_ENV=production
```

# 二十四、完整示例

```env
NODE_ENV=development
PORT=3000
```

```js
    throw new Error(`缺少必要环境变量：${key}`);

module.exports = {
  nodeEnv: process.env.NODE_ENV || "development",
  port: Number(process.env.PORT) || 3000,
  debug: process.env.DEBUG === "true",
  db: {
    host: process.env.DB_HOST,
    port: Number(process.env.DB_PORT) || 5432,
    user: process.env.DB_USER,
    password: process.env.DB_PASSWORD,
  },
};
```

---

## `app.js`

```js
const config = require("./config");

console.log("当前环境:", config.nodeEnv);
console.log("端口:", config.port);
console.log("数据库地址:", config.db.host);
console.log("调试模式:", config.debug);
```

```bash
node app.js
```

# 二十五、总结

Node.js 中的环境变量主要通过：

```js
process.env
```

访问。

它的核心特点：

| 特点 | 说明 |
|---|---|
| 来源 | 操作系统、启动命令、部署平台、`.env` 文件加载 |
| 访问方式 | `process.env.KEY` |
| 值类型 | 都是字符串 |
| 常见变量 | `NODE_ENV`、`PORT`、`DB_HOST`、`JWT_SECRET` |
| 推荐做法 | 配置与代码分离 |
| 安全要求 | 敏感信息不要提交到代码仓库 |

简单来说：

> **环境变量是 Node.js 应用配置外部化的标准方式。**
> 它让同一份代码可以在本地、测试环境和生产环境中以不同配置运行，同时避免把密码、密钥等敏感信息硬编码到源码中。
