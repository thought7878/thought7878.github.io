使用 **MongoDB 聚合管道（Aggregation Pipeline）**，主要是因为普通查询只能“取数据”，而很多业务场景需要对数据进行**统计、分析、转换、关联、分组、汇总**。聚合管道就是 MongoDB 中处理这类需求的核心工具。

---

# 一、**普通查询的局限**

如果只是简单查询文档，可以使用：

```javascript
db.orders.find({ status: "paid" })
```

但如果需求是：

- 每个用户的订单总金额是多少？
- 每个月销售额是多少？
- 哪些商品销量最高？
- 每个分类的平均价格是多少？
- 订单和用户信息如何关联？
- 如何统计去重后的购买用户数？

**这些需求用 `find()` 就很难完成**。

例如你想统计：

```javascript
每个用户一共消费了多少钱？
```

*用 `find()` 只能把所有订单查出来，然后在应用层代码里循环计算：*

```javascript
const orders = await db.orders.find({ status: "paid" }).toArray();

const result = {};

for (const order of orders) {
  if (!result[order.userId]) {
    result[order.userId] = 0;
  }

  result[order.userId] += order.amount;
}
```

**这样有几个问题：**
1. 大量数据被传送到应用层；
2. 应用服务器内存压力大；
3. 计算效率低；
4. 代码复杂；
5. 不如数据库内部处理高效。

**而聚合管道可以直接在数据库里完成：**

```javascript
db.orders.aggregate([
  {
    $match: { status: "paid" }
  },
  {
    $group: {
      _id: "$userId",
      totalAmount: { $sum: "$amount" }
    }
  }
])
```

---

# 二、聚合管道可以**在数据库层完成复杂计算**

聚合管道最大的价值是：**把数据处理逻辑交给数据库执行**。

例如统计每个用户的消费总额：

```javascript
db.orders.aggregate([
  {
    $match: { status: "paid" }
  },
  {
    $group: {
      _id: "$userId",
      totalAmount: { $sum: "$amount" }
    }
  },
  {
    $sort: { totalAmount: -1 }
  }
])
```

**数据库会完成：**

```text
过滤已支付订单
-> 按用户分组
-> 求总金额
-> 排序
-> 返回结果
```

**这比把全部数据查到程序里再处理更高效。**

---

# 三、聚合管道适合做**数据分析**

很多报表和分析需求都可以用聚合管道完成。

## 1. 分组统计

统计每个订单状态的数量：

```javascript
db.orders.aggregate([
  {
    $group: {
      _id: "$status",
      count: { $sum: 1 }
    }
  }
])
```

结果类似：

```javascript
[
  { _id: "paid", count: 120 },
  { _id: "unpaid", count: 30 },
  { _id: "cancelled", count: 10 }
]
```

---

## 2. 按时间统计

统计每个月销售额：

```javascript
db.orders.aggregate([
  {
    $match: { status: "paid" }
  },
  {
    $group: {
      _id: {
        year: { $year: "$createdAt" },
        month: { $month: "$createdAt" }
      },
      totalSales: { $sum: "$amount" }
    }
  },
  {
    $sort: {
      "_id.year": 1,
      "_id.month": 1
    }
  }
])
```

适合做：

- 日报
- 周报
- 月报
- 销售趋势
- 用户增长趋势

---

## 3. TopN 查询

查询销量最高的 10 个商品：

```javascript
db.products.aggregate([
  {
    $sort: { sales: -1 }
  },
  {
    $limit: 10
  }
])
```

---

## 4. 平均值、最大值、最小值

统计每个班级平均分：

```javascript
db.students.aggregate([
  {
    $group: {
      _id: "$classId",
      avgScore: { $avg: "$score" },
      maxScore: { $max: "$score" },
      minScore: { $min: "$score" }
    }
  }
])
```

---

# 四、聚合管道可以**减少网络传输**

如果不使用聚合管道，很多统计需要：

```text
数据库 -> 查询大量原始数据 -> 应用服务器计算 -> 返回结果
```

使用聚合管道后：

```text
数据库内部直接计算 -> 只返回统计结果
```

例如：

```javascript
db.orders.aggregate([
  {
    $group: {
      _id: null,
      totalAmount: { $sum: "$amount" }
    }
  }
])
```

数据库只返回：

```javascript
[
  { _id: null, totalAmount: 99999 }
]
```

而不是把所有订单都传给应用层。

这样可以显著减少：

- 网络传输量
- 应用层内存消耗
- 代码复杂度
- 接口响应时间

---

# 五、聚合管道**表达能力很强**

它不只是简单统计，还可以做很多复杂操作。

---

## 1. 条件计算

根据分数判断是否及格：

```javascript
db.students.aggregate([
  {
    $project: {
      name: 1,
      result: {
        $cond: {
          if: { $gte: ["$score", 60] },
          then: "及格",
          else: "不及格"
        }
      }
    }
  }
])
```

---

## 2. 字段重命名和计算

计算订单总金额：

```javascript
db.orders.aggregate([
  {
    $project: {
      _id: 0,
      orderAmount: "$amount",
      total: {
        $multiply: ["$price", "$quantity"]
      }
    }
  }
])
```

---

## 3. 数组展开

如果文章有多个标签：

```javascript
{
  title: "MongoDB 教程",
  tags: ["mongodb", "database", "backend"]
}
```

可以统计每个标签出现次数：

```javascript
db.articles.aggregate([
  {
    $unwind: "$tags"
  },
  {
    $group: {
      _id: "$tags",
      count: { $sum: 1 }
    }
  }
])
```

---

## 4. 关联查询

类似 SQL 中的 join：

```javascript
db.orders.aggregate([
  {
    $lookup: {
      from: "users",
      localField: "userId",
      foreignField: "_id",
      as: "user"
    }
  }
])
```

可以把订单和用户信息关联起来。

---

# 六、聚合管道比应用层处理更合适

假设订单表有 1000 万条数据，需求是统计每个用户消费总额。

如果在应用层处理：

```text
查询 1000 万条订单到应用层
应用层循环统计
内存压力大
速度慢
可能直接 OOM
```

如果使用聚合管道：

```text
数据库内部过滤
数据库内部分组
数据库内部求和
只返回每个用户的统计结果
```

这通常更稳定、更高效。

---

# 七、聚合管道比 MapReduce 更常用

早期 MongoDB 做复杂聚合可能会用 MapReduce。

但现在更推荐聚合管道，因为：

| 对比项 | 聚合管道 | MapReduce |
|---|---|---|
| 写法 | 简单直观 | 复杂 |
| 性能 | 通常更好 | 通常较慢 |
| 可维护性 | 更好 | 较差 |
| 适用场景 | 大多数统计需求 | 特殊复杂逻辑 |
| 推荐程度 | 高 | 低 |

所以大多数业务场景优先使用聚合管道。


这些都适合用聚合管道。

# 九、聚合管道的核心优势总结

使用聚合管道主要有以下原因：

## 1. 能做复杂统计

普通 `find()` 只能查，聚合管道能算。

---

## 2. 能减少数据传输

数据库直接返回结果，而不是把大量原始数据传给应用层。

---

## 3. 性能通常更好

配合索引、合理管道顺序，可以高效处理大量数据。

---

## 4. 代码更简洁

不需要在应用层写大量循环统计逻辑。

---

## 5. 表达能力强

支持：

```javascript
$match
$group
$sort
$project
$lookup
$unwind
$facet
$addFields
$count
$limit
```

可以完成很多复杂分析需求。

---

## 6. 适合报表和数据分析

比如：

```text
总销售额
订单数量
用户留存
商品排行
分类统计
时间趋势
多维分析
```

# 十、什么时候应该用聚合管道？

当你遇到这些需求时，通常应该考虑聚合管道：

```text
统计总数
求和
求平均值
最大最小值
分组统计
按日期统计
去重统计
排行榜
数据关联
数组展开
多维度报表
复杂数据转换
分页查询并返回总数
```

例如：

```javascript
每个用户消费总额是多少？
每个月销售额是多少？
哪个商品卖得最好？
每个分类有多少商品？
每个地区的订单量是多少？
今日新增用户是多少？
某个字段不同值的分布情况是什么？
```

这些问题都适合用聚合管道解决。

---

# 十一、什么时候不用聚合管道？

如果**只是简单查询**，不一定需要聚合管道。

例如：

```javascript
db.users.findOne({ email: "test@example.com" })
```

或者：

```javascript
db.users.find({ status: "active" })
```

这种普通查询用 `find()` 就够了。

但如果查询之后还要：

```text
分组
统计
求和
排序取 TopN
关联其他集合
转换字段结构
```

那就应该优先考虑聚合管道。

---

# 十二、一句话总结

**使用聚合管道，是因为它可以让 MongoDB 不只是“查数据”，还能在数据库内部完成复杂的统计、转换、关联和分析，从而提高效率、减少网络传输、简化代码。**

简单说：

```text
简单查询用 find()
复杂统计和分析用 aggregate()
```
