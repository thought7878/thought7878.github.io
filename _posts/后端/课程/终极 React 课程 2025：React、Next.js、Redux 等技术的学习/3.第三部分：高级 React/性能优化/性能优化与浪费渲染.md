## 一、 React 性能优化的三大方向与工具
讲师将 React 的性能优化分为三个主要领域，并列举了对应的内置工具和技术：

1. **防止浪费的渲染（Prevent Wasted Renders）**
   * 使用 `React.memo` 记忆化组件。
   * 使用 `useMemo` 和 `useCallback` 记忆化对象和函数。
   * 通过将元素作为 `children` 或普通 prop 传递，来避免子组件被不必要地重新渲染。
2. **提升应用速度与响应性（Improve App Speed & Responsiveness）**
   * 使用 `useMemo` 和 `useCallback` 优化计算和回调。
   * 使用 `useTransition` Hook 来处理非紧急的 UI 更新，保持界面流畅。
3. **减小打包体积（Reduce Bundle Size）**
   * 减少代码库中第三方包的使用。
   * 实现`代码分割（Code Splitting）` 和`懒加载（Lazy Loading）`。

*💡 讲师提示：这些工具不需要在所有地方盲目使用，它们是你的“工具箱”，只有在遇到特定性能瓶颈时才按需调用。*

## 二、 组件重新渲染（Re-render）的触发条件与常见误区
为了理解“浪费的渲染”，首先需要明确*组件在什么情况下会被重新渲染*。React 中组件实例重新渲染只有以下 **3 种真实原因**：

1. **State 改变**：组件自身的状态（State）发生变化。
2. **Context 改变**：组件订阅的 Context 值发生变化。
3. **父组件重新渲染**：当父组件重新渲染时，其所有子组件都会**自动**随之重新渲染。

**⚠️ 纠正一个常见误区：Props 改变会触发重新渲染吗？**
* **答案是：不会直接触发。** 
* 表面上看，当 Props 改变时组件确实重新渲染了，但这**本质上是因为父组件重新渲染了**。父组件重新渲染自然会触发子组件的重新渲染（即上述的第 3 点），并传入新的 Props。Props 改变本身并不是一个独立的触发条件。

## 三、 什么是“浪费的渲染”（Wasted Renders）？
* `核心定义`：组件函数被调用了，React 也执行了创建虚拟 DOM 和 Diffing（协调）的计算过程，但**最终没有产生任何实际的真实 DOM 更新**。
* `为什么叫“浪费”`：**因为所有的计算工作都做了，但对 UI 没有任何实质性改变，计算资源被白白消耗了**。
* `实际影响`：
	* 在大多数情况下，React 的运行速度极快，偶尔的浪费渲染**不会**造成问题。
	* 但是，如果重新渲染**过于频繁**，或者组件本身的渲染逻辑**非常复杂/缓慢**，就会***导致应用出现卡顿（laggy）和响应迟钝***（例如*用户操作后 UI 更新不及时*）。
