## 核心主旨
讲座详细解释了 **React 在状态更新时，如何通过 `虚拟 DOM (Virtual DOM)`、`协调器 (Reconciler / Fiber) `和 `Diffing 算法` 来高效、最小化地更新真实 DOM，而不是盲目地重新渲染整个页面**。

## 关于“渲染”的常见误区
* `渲染的本质`：`渲染阶段的渲染`（Rendering）并*不是直接向屏幕或 DOM 写入内容*，而仅仅是**调用组件函数并返回 React 元素**。
* `重新渲染的真相`：**当组件重新渲染时**，**React 并不会直接丢弃并替换整个真实的 DOM 实例，而是先在内存中生成新的结构**。

![[_posts/后端/课程/终极 React 课程 2025：React、Next.js、Redux 等技术的学习/2.第二部分：中级 React/React 原理/media/fb9bce115bdd6942fc424531d41c2dec_MD5.webp]]

## 虚拟 DOM (React Element Tree)
* `定义`：初始渲染时，**React 将整个`组件树`转换为一个巨大的 `React 元素树`（即 `Virtual DOM`）。它本质上只是一个普通的 JavaScript 对象**。
* `特点`：创建和销毁的成本非常低、速度快。*(注：React 官方文档现已较少使用“Virtual DOM”一词，更倾向于称其为“`React 元素树`”，但业界仍广泛使用该术语。)*

![[_posts/后端/课程/终极 React 课程 2025：React、Next.js、Redux 等技术的学习/2.第二部分：中级 React/React 原理/media/ffa6a3885a30f4e6ef51f12b2304118e_MD5.webp]]

### 构建 React Element Tree
* 当某个组件的状态更新，触发重新渲染时，**它的所有子组件也会被默认重新渲染**（无论它们的 props 是否发生变化）。
* *这听起来很低效，但这仅仅是在内存中重新生成 Virtual DOM（JS 对象）*，**并不意味着整个真实 DOM 都会被更新**。

## 协调 (Reconciliation) 与 Fiber 架构
* **为什么需要协调？** 
	* 直接操作真实 DOM 代价极其高昂。React 需要一种机制来**对比新旧状态，找出真正需要改变的最小部分**，从而复用现有 DOM。
* `协调器/Reconciler`（叫`Fiber`）：React 的核心引擎。它在渲染时**基于 Virtual DOM 构建出** `Fiber 树` (Fiber Tree)。
* Fiber 的特点：
	* 它是可变的 (mutable)，**不会被销毁，而是在后续渲染中不断被修改和复用**。
	* 它**存储了组件的实际状态、props、副作用和 Hooks 信息**。
	* **每个 Fiber 是一个“`工作单元 (unit of work)`”，通过*链表*结构（指向父节点和兄弟节点）连接，*便于遍历***。
	* ***支持异步渲染***：Fiber 架构**允许渲染工作被拆分、设定优先级、暂停、重用或丢弃**。这***避免了长任务阻塞浏览器主线程，并支撑了 React 18 的并发特性***（如 Suspense 和 Transitions）。

### 协调的过程
**Diffing 过程与副作用列表** (List of Effects)：
* 当状态改变生成新的 Virtual DOM 后，Fiber 会**将新的 Virtual DOM与当前的 Fiber 树，进行*逐层比较***，这个过程称为 `Diffing`。
* `渲染阶段的结果、协调的结果`：生成一个“**正在进行中的树 (work in progress tree)**”和一个 **副作用列表 (List of Effects)**。
* `智能更新`：即使某个子组件被连带重新渲染了，*如果 Diffing 发现其实际内容未变，就不会为其生成 DOM 更新操作*。**只有真正需要插入、删除或更新的节点才会被记录在副作用列表中**。

## 渲染阶段 vs 提交阶段 
* Render Phase（当前讲座主题）：纯粹在内存中进行计算、调用组件函数、生成新的 Virtual DOM 并通过 Fiber 进行 Diffing，最终得出“需要做什么 DOM 操作”的列表。**此阶段不会对真实 DOM 产生任何可见影响。**
* Commit Phase（下一讲主题）：将 Render Phase 计算出的“副作用列表”一次性应用到真实 DOM 中，完成最终的页面更新。

---

## 总结
React 的高性能秘诀在于：**“计算在内存，更新在真实”**。通过在内存中廉价地构建 Virtual DOM 并利用 Fiber 架构进行精细的 Diffing 协调，React 能够精准定位最小的 DOM 变更，避免了昂贵且低效的全量 DOM 重写。
