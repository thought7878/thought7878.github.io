这段字幕主要讲解了 **全栈 React 与服务端渲染（SSR）** 的基础概念，并为接下来学习 **Next.js** 做铺垫。

核心内容如下：

## 课程背景
   - 这一部分开始进入 **全栈 React** 和 **Next.js 的服务端渲染**。
   - 首先解释什么是服务端渲染，以及什么时候应该使用它。

## 从传统渲染到现代前端的发展
   - *早期网站*（如 PHP、WordPress）通常是*在服务端渲染*完成后，再把页面发送给浏览器。
   - 后来随着 Web *应用越来越动态和交互化，渲染逐渐转移到客户端*，出现了 Angular、Vue、Svelte、React 等框架。
   - 但*现在*，*前端又出现了一种回归服务端渲染的趋势*，尤其是通过 Next.js、Remix、Nuxt、SvelteKit、SolidStart 等全栈框架。

## CSR 与 SSR 的区别
   - **客户端渲染（Client-Side Rendering, CSR）**：
     - 浏览器先拿到一个比较*空的 HTML*（第一次请求）。
     - 然后*下载 JavaScript*（第二次请求）。
     - JavaScript 执行后才*渲染页面*。
     - *数据通常在组件挂载后开始请求*（第三次请求）。
   - **服务端渲染（Server-Side Rendering, SSR）**：
     - 服务端提前获取数据。
     - 服务端生成完整 HTML。
     - *浏览器收到时页面内容已经基本准备好*（第一次请求）。

### 客户端渲染的优缺点
   - **优点：**
     - 页面加载完成后*交互体验很好*。
     - *适合做单页应用*（SPA）。
     - 用户操作时*不需要频繁整页刷新*。
   - **缺点：**
     - *首次加载可能较慢*。
     - JavaScript 包可能很大。
     - *数据请求往往在组件挂载后才开始，形成“请求瀑布”*。
     - *对 SEO 不太友好*，因为搜索引擎可能一开始只看到空页面。

### 服务端渲染的优缺点
   - **优点：**
     - *首屏加载更快*。
     - *需要下载的 JavaScript 相对更少*（生成HTML的JS在服务端，不必加载到浏览器）。
     - *数据在服务端提前获取并直接放进 HTML*。
     - 更*有利于 SEO*。
     - 适合*内容驱动型网站*。
   - **缺点：**
     - 传统 SSR *页面切换时可能需要服务端重新渲染*。
     - 可能*导致整页刷新，交互体验不如 SPA*。
     - 但在 Next.js 这类现代框架中，这个界限已经变得模糊，*因为服务端渲染的页面也可以在客户端进行 hydration，从而变得可交互*。

## 何时使用 CSR 与 SSR
SEO 场景
   - 如果项目重视 SEO，比如：
     - 电商网站
     - 博客
     - 新闻网站
     - 营销官网
     - 内容平台
   - 那么服务端渲染通常是更好的选择。
   - 如果是不需要搜索引擎收录的内部系统、后台工具、登录后使用的应用，比如课程中的 “The Wild Oasis” 内部应用，那么传统客户端渲染 SPA 就足够。

## 服务端渲染的两种类型
### 静态渲染 / 静态站点生成（Static Site Generation, SSG）
 - HTML 在**构建时**生成。
 - **开发完成后**导出静态文件。
 - *服务器直接发送预先生成好的页面*。

### 动态渲染（Dynamic Rendering）：
 - *每次请求时服务端实时生成 HTML*。
 - 适合*数据经常变化*的场景。

讲者认为*两者都属于服务端渲染，因为它们都不是在客户端生成初始 HTML*。

## 页面加载时间线**对比**
   - 在客户端渲染中：
     1. 用户请求页面。
     2. 服务器返回空 HTML、CSS、JavaScript。
     3. 浏览器下载并执行 JavaScript。
     4. 应用开始请求数据。
     5. 数据返回后重新渲染页面。
     6. 最终用户看到完整内容。
   - 在服务端渲染中：
     1. 用户请求页面。
     2. 服务端先获取数据。
     3. 服务端生成完整 HTML。
     4. 浏览器直接收到包含内容的页面。
   - 因此，服务端渲染的 **Largest Contentful Paint（最大内容绘制）** 通常更早，首屏体验更快。

## 关于交互性
   - 服务端渲染页面并不是不能交互。
   - 服务端返回的页面通常仍然会包含 JavaScript。
   - 浏览器加载 JavaScript 后会进行 hydration。
   - **Hydration 的作用**是：*让服务端返回的静态 HTML 变成可交互的页面*。

## 本节课的三个关键结论
   - 服务端渲染中，数据获取通常在服务端提前完成。
   - 页面渲染工作*从客户端转移到了服务端*。
   - *因为内容更早出现，所以首屏性能和 SEO 通常更好*。
