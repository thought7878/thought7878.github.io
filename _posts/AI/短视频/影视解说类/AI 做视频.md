## 底层原理：只会输出文字的模型，怎么做出视频

先明确一点：Opus 5.5 可以看文字、看图片，但它的输出，只有文字。

视频模型，是直接生成画面，一个像素一个像素地画出来。Opus 走的是另一条路： **它写的是一份乐谱** ，第几秒、画面哪个位置、出现什么、怎么运动，全部写清楚。真正去演奏这份乐谱的，是浏览器。

视频本身，是一连串静止的画面。一秒 30 张，快速播放，就形成了运动。一条 2 分钟的视频，就是 3600 张图。

所以 Opus 写的网页里，会有一个关键函数： **输入一个时间，输出这一刻的画面** 。你问它第 90 张长什么样，它就画出第 90 张，结果只取决于这个时间。

![[_posts/AI/短视频/影视解说类/media/946e4d1f73aaa195e8b629d59c03907e_MD5.webp]]

左边是代码，右边是它画出来的那一帧

渲染的时候，程序会打开一个在后台运行的浏览器，从第一张问到最后一张，每画好一张，就截一张图。最后用 FFmpeg，把这几千张图编码成视频。

这里的关键是： **整个过程不是在「播放」，而是一张一张地计算。** 所以画面再复杂、电脑再慢，成片也不会掉帧。而且同一张图，不管渲染多少次，结果都完全一样，可以分给几个程序同时渲染，也可以只重新渲染改动的那一段。

要做到这一点，代码得守三条规矩：

- 不能读系统时间；
- 用随机数，必须带上固定的种子；
- 渲染到一半，不能再去加载新的东西。

只要违反其中一条，同一帧每次画出来，就可能不一样。

因为画面是代码生成的，文字永远清晰，想改哪里，改一行代码，重新渲染就行。配乐也一样：声音本质上是一段波形，可以直接用代码计算出来。

再加上第一节说的视觉能力，就形成了一个完整的闭环： **写代码、渲染、看画面、找问题，再回去改代码。** 它能自己把一条片子，一轮一轮打磨出来。

Anthropic 自己，10 月 8 号推出了 Claude Motion，用的也是这套思路：不用视频生成模型，由 Claude 写代码做动画，再导出视频。

说明 Claude 官方博客：「It doesn’t use a video generation model. Claude writes code that animates your text, charts, shapes, and images」

## 主流技术栈：各自能做出什么

主流的技术栈，主要就这几种。前五种都是在网页里画画：网页排版、画布、手绘笔刷、着色器和 Three.js；后两种不走网页：Manim 和 Blender。大致的规律是： **越往右，画面越有质感，但渲染越慢，也越难做。**

![[_posts/AI/短视频/影视解说类/media/3a77e77e8fa51b3185f2fa6eba04e559_MD5.webp]]

七种技术栈：网页排版、画布、手绘笔刷、着色器、Three.js、Manim、Blender

### 网页排版：HTML、CSS、SVG

最基础的，就是平时做网页用的 HTML、CSS 和 SVG。文字、图表、界面动效，用它做最清晰，产品介绍、数据讲解最常用。

### 画布：Canvas

最常用的是画布，也就是 Canvas。代码直接在上面绘制点、线、圆，几万个光点也能流畅运行。开头那些深色背景、满屏发光的视频，基本都是用它画的。

那种光晕是怎么来的？分三步：先把画面画好；再把亮的部分复制一层，缩小、模糊；最后叠加回原来的画面。越亮的地方，光晕就越大。

![[_posts/AI/短视频/影视解说类/media/38ae707139b664e5e4f2c9adc6a81173_MD5.webp]]

发光三步：线条层 → 复制一层缩小、模糊 → 叠回原来的画面

开头那头大象也不是画出来的。它是几十个圆一个套一个在转，最外面那个圆走过的轨迹，刚好是一头大象。这叫傅里叶级数，是代码精确计算出来的。

![[_posts/AI/短视频/影视解说类/media/b7007378f8ba5c9a603990314a19bbec_MD5.webp]]

几个圆一个套一个转，笔尖画出一头大象

### 手绘笔刷：p5.js + p5.brush

想要手绘感，就用 p5.js 加水彩笔刷，边缘会自然晕开，线条会轻微抖动，接近手绘动画的效果。开头那段水彩 MV，就是这么画的。

![[_posts/AI/短视频/影视解说类/media/cd6645a53b72896c453939da375b5d69_MD5.webp]]

开头那段水彩 MV（PDoom 的 Opus 5.5 版），就是 p5.js 加水彩笔刷画的

### 着色器：WebGL

想要光影质感，就加着色器。它让显卡同时给屏幕上的每一个像素计算颜色。下面这片浅水看起来像实拍，其实是在计算阳光穿过每一道波纹之后，落在水底形成的亮线。

![[_posts/AI/短视频/影视解说类/media/aefb86b14fc832695539322367a4f919_MD5.webp]]

WebGL 着色器做的浅水（Clearwater）

代价是渲染变慢：有人实测，同样 3 秒的画面，只用画布渲染 7 秒，加上一层着色器效果要 48 秒。

![[_posts/AI/短视频/影视解说类/media/162342154394ff9432466229896c38e8_MD5.webp]]

说明 Xilo《零基础入门 Opus 5.5 做视频》：「只有 Canvas 的版本渲染 7 秒，加上着色器以后是 48 秒」

### 3D 空间：Three.js

需要 3D 空间，就用 Three.js。它相当于在网页里搭一个摄影棚：模型、灯光、摄像机都用代码来摆，镜头可以在空间里自由移动。开头那条小船，本身就是一个可以操作的 3D 网页，最后录屏得到的，所以画面里能看到浏览器和鼠标。它的局限是，模型基本靠方块、球体这些基础形状拼出来，复杂的写实物体很难做。

![[_posts/AI/短视频/影视解说类/media/93adfb8e97ba9f4ad731e6d37a693b73_MD5.webp]]

Three.js 做的小船：画面里能看到浏览器窗口和鼠标

### 网页之外：Manim 和 Blender

Manim 是 3Blue1Brown 做数学动画的工具，公式和图形非常精确，适合讲数学和物理推导。有人做的一节 7 分多钟的导数课，提示词只有一句话。

![[_posts/AI/短视频/影视解说类/media/38bd4a3626c2b494cac7a6388ab3dda9_MD5.webp]]

说明 LinearUncle 的原帖，提示词就一句

Blender 是专业的 3D 软件，让 AI 直接操作它，画面最接近动画电影，但成本也最高：一个 10 秒的镜头，用了 35 分钟，按 API 价格算，大约 13 美元。

![[_posts/AI/短视频/影视解说类/media/0f669af217d4f144d849c59fc4855b8d_MD5.webp]]

说明 Stefan 的原帖：「Opus 5.5: 35 min, 199.6k output tokens, about $13.3 in API terms.」

### **现成的框架**：Remotion、HyperFrames、Claude Motion

这些画笔，可以自己从头写，也可以用现成的框架。*框架把时间线、配音、字幕这些通用的部分搭好了，你只管画面*。

- **Remotion** ：最老牌，用 React 写视频，按帧控制，成熟、生态完善。有人用它做了一条 3 分钟的 AI 简史，代码有 7400 多行。需要注意：公司商用需要购买授权。
- **HyperFrames** ：HeyGen 开源的框架，写普通的网页就能渲染成视频，从设计上就面向 AI 使用。HeyGen 自己的产品宣传片就是用它做的。
- **Claude Motion** ：官方出的，也属于这一类，不过目前只开放给团队版和企业版。

### **怎么选**

很简单：看你想要什么效果。

| 想要的效果        | 用什么                    |
| ------------ | ---------------------- |
| 排版、图表、界面动效   | 网页排版（HTML + CSS + SVG） |
| 粒子、光效、深色电影感  | 画布（Canvas 2D）          |
| 水彩、彩铅、手绘感    | 手绘笔刷（p5.js + p5.brush） |
| 水、光、流体这类光影质感 | 着色器（WebGL）             |
| 3D 空间、镜头穿行   | Three.js               |
| 公式和几何推导      | Manim                  |
| 电影级 3D       | Blender                |

一条片子里，也经常是几种一起用。后面实操的提示词，就是按这张表来选的。

## **做好的关键**：同样用 Opus 5.5，为什么别人做得更好

### 一句话出片：能做，但内容你控制不了

先说「一句话出片」。能不能做？能。有人统计过 233 条刷屏视频，66% 确实是一句话做出来的。

![[_posts/AI/短视频/影视解说类/media/b431aee9f896bed2f1679841144f6254_MD5.webp]]

说明 claude-motion-playbook 的统计：一句话 prompt 154 条（66%）

但一句话的问题也很明显： **内容全靠它自己发挥，你控制不了。** 最火的那一句提示词，被一字不差用了 33 次，结果配色、网格、结尾的 logo 都很像，大量撞脸。

![[_posts/AI/短视频/影视解说类/media/267b1a3d5d39ef7b6852eefa285445ff_MD5.webp]]

说明 「make a dynamic 15-second motion graphics video … go all out」这句一字不差出现了 33 次，来自 33 个账号

所以一句话出片，适合拿来炫技，试试模型的上限。真想讲清楚一件事，提示词就要写详细：公开出来的提示词，长的有一万七千多个字符（17,664 个英文字符），逐秒的分镜、笔触的方向都写死了。

![[_posts/AI/短视频/影视解说类/media/f97e7f6f880e28c02f08e96dc2204425_MD5.webp]]

说明 athemeroy 的报告：长的提示词约 17,664 个英文字符，逐秒分镜

### 我自己的一次复刻

我自己也试过一次。发给它一条 30 秒的宣传片，只说了一句话：你能复刻出这种视频吗。

严格来说，这句话背后带了一条参考片。 **很多所谓的一句话出片，背后都带着参考视频、人物设定图，或者早就装好的 skill。**

它先把原片逐帧拆开，总结出 9 个让人惊艳的手法；再定下做法：3D 和渐变用着色器，像素点阵用画布，卡片用 CSS 3D，每一帧都由时间决定。最后交出来一条 31 秒的复刻版，12 个镜头和转场，基本都复原了。

![[_posts/AI/短视频/影视解说类/media/768c88611cde4a5de5315709e31e0731_MD5.webp]]

我和它的对话：9 个手法、它定的做法、交付

![[_posts/AI/短视频/影视解说类/media/fef4f095d2ccfe548f9687a6c0bf7e5d_MD5.webp]]

左边参考片，右边 Opus 5.5 的复刻版

形式上很惊艳，但仔细看，有两个问题。

**第一，原片里的人像和房间，是 AI 生成的照片。** 它没有生图工具，只能用代码搭的 3D 来代替，真实感明显弱了一截。想要真实感，就要先用生图或视频模型做素材，再用代码做动效。

![[_posts/AI/短视频/影视解说类/media/90b3fc1fd0b5b66a637aca4446884cbc_MD5.webp]]

同一个镜头：参考片里是 AI 生成的照片，复刻版是代码搭的 3D

**第二，它只复刻了形式。** 片子里介绍的是一个虚构的产品，没有真正的内容。

这就是一句话出片的本质： **好看的形式，它能帮你做；但要讲什么，还是要你自己想清楚、写清楚。**

### 社区里验证过的**四个做法**

真正有用的，是做法。社区里验证过的，主要有四个：

1. **先定方向，再开渲。** 先让它出分镜和几张静帧，你确认了，再做整片，避免方向错了白跑一个小时。
2. **拿参考片拆帧。** 就像上面那样，找一条你喜欢的片子，让它拆成画面，逆推出配色、字幕和节奏，写成规范照着做。
3. **让它当挑剔的导演。** 把关键帧拼成一张图，让它自己打分，改到 8 分以上再继续。
4. **用音乐或配音当时钟。** 先分析音乐的节拍，或者先出配音，画面的每一个动作，都卡在拍子或者字上。

### 提示词的结构

这份提示词的结构，参考了收藏数最高的那几条：用标签把不同的内容分开，这也是 Anthropic 官方推荐的写法。

## 提示词全文（可以直接复制）

用法：

1. 在 Claude 桌面端的 Code（或 Claude Code）里选一个空文件夹，模型选 Opus 5.5；
2. 有配乐就把音乐文件一起拖进去；
3. 把下面整段复制进去， `<inputs>` 里能填的先填，填不了的空着，它会反过来问你。

提示词 · 空白模板（Opus 5.5 · Claude Code）

```js
<role>
你是一位动态设计导演，也是一位创意程序员。你用写代码的方式做视频：每一帧画面都由代码画出来，不用视频生成模型，最后交付 mp4。
</role>

<inputs>
下面这些，我能填的先填了。空着的，开工前一次性问我：每个问题给 2 到 3 个选项，标出你推荐的那个。我没回答的用你推荐的，但事实不许自己编。
1. 主题：【】
2. 看完以后，希望观众记住的一句话：【】
3. 想要的效果：【用一两句话描述画面；有参考视频或截图就一起发给你】
4. 时长和画幅：【60 秒，1920×1080，30 帧】
5. 声音：【用我上传的音乐 / 用代码合成配乐】；旁白：【不要】
6. 明确不想要的：【】
</inputs>

<style_to_stack>
按我想要的效果选技术，可以组合，但要说明理由：
- 深色背景、发光粒子、电影感的知识短片 → Canvas 2D，叠一层辉光和胶片颗粒
- 干净的排版、图表、界面动效、产品宣传 → HTML + CSS + SVG，用弹簧动画
- 3D 空间、镜头穿行、立体文字 → Three.js
- 水彩、彩铅、手绘笔触 → p5.js + p5.brush
- 水、光、流体、老电视这类质感 → 在 Canvas 或 Three.js 上加 WebGL 着色器（渲染会慢）
- 像素风 → 很小的 Canvas 画布整数放大，关掉平滑
- 公式和几何推导 → Manim
- 写实的人物、产品照片 → 代码画不好，告诉我需要准备什么素材
</style_to_stack>

<plan>
问完以后，先给我 2 个方向，差别要拉开。每个方向写清：
- 一句话风格、用哪几种技术、配色（3 到 4 个色值）和字体；
- 逐镜头分镜表：镜头｜起止秒｜画面｜屏幕上的字｜动作和镜头运动｜音效｜怎么转到下一个镜头；
- 各渲 1 张关键帧给我看。
要用到的事实逐条列出处；没把握的写进 NOTES.md，宁可不写也不要猜。
</plan>

<direction>
- 整片一套风格、一套配色，同一个元素在每个镜头里样子一致。
- 第 1 秒就要有画面和字，不能黑屏；每 2 到 4 秒画面上要有新变化，不能有静止的空拍；每 10 到 15 秒一个转折。
- 一个镜头只讲一件事。屏幕上的字少而大，每段至少停 2.5 秒，放在安全区里，不被画面挡住。
- 动作用缓动或弹簧，不用匀速；转场从画面内容里长出来（比如一条线变成下一个场景的地平线），不用通用的淡入淡出，也不要硬切。
- 镜头跟着内容推、拉、跟随，主体在画面里要够大；每个画面都有前景、中景、背景。
- 禁止：居中大字加渐变背景的默认画面、所有元素一起淡入、满屏小字、光晕过曝发白、半透明层叠得发灰、角落里多余的标签和边框、任何看起来像模板的东西。
</direction>

<build>
1. 先准备环境：无头 Chromium、ffmpeg、Python 的 numpy 和 scipy。画面里有中文的话，先确认有中文字体，没有就装思源黑体或思源宋体，不然会出方块字。
2. 写一个 HTML 页面，暴露 window.draw(t)，画出第 t 秒。画面只由 t 算出来：不读系统时间，不用 requestAnimationFrame 和计时器，随机数带固定种子，帧和帧之间不保存状态。字体和素材全部加载完再开始截图。
3. 有音乐的话，先用 numpy 分析节拍，镜头切换和关键动作落在拍子上；截取完整的乐句凑满时长，结尾淡出。音效用代码合成，放在动作发生的那一帧。最后整体限制峰值，防止爆音。
4. 用无头浏览器逐帧调用 draw(t) 截图，ffmpeg 合成 mp4。帧按编号存盘，中途断了能从断点接着渲。
</build>

<review>
每做完一个镜头，先渲 3 张静帧自己看。渲整片之前，先渲 9 个关键时刻拼成一张图，站在严格的动效导演角度挑毛病，别替自己说好话：
- 六项各打 1 到 10 分：前 2 秒抓不抓人、缩到手机大小看不看得清、动作自不自然、画面变化够不够、构图、声音和画面对不对得上；
- 列出最严重的 3 个问题和时间点，改完重新出图和分数，直到每项都在 8 分以上；
- 然后出一段 15 秒样片给我看，我说可以，再渲全片。
</review>

<gotchas>
- 你听不到声音：把音频的波形和响度画成图检查，确认没有爆音、没有空白。
- 用了着色器的话，先渲一帧确认它真的生效了。
- 发光：把亮部复制一层、缩小、模糊，再叠加回去；控制强度，别把亮的地方烧成一片白。
- 在变形、缩放的容器里切换文字，新旧文字要各有进场和出场时间，不然会叠在一起。
- 一帧里画的东西太多会拖慢渲染：粒子数先估算好渲染时间再定。
</gotchas>

<deliver>
交付：mp4、一张抽帧总览图、一段简短的创作说明（风格、技术栈、你做的关键决定），还有 NOTES.md。
</deliver>

<start>
先问我 inputs 里空着的问题。在我回答、选好方向、确认分镜之前，不要写任何代码。
</start>
```

这份提示词参考了这几样：收藏榜第一的「纯代码 UI 动效」（@twoclipping）的「先问我要什么」和禁止清单；Xilo《零基础入门 Opus 5.5 做视频》的标签分块和严格打分；kimmonismus 的《AI 简史》提示词里「没把握的事实写进 NOTES.md」；观默公开的 vibe 知识大赏提示词里「先渲 9 个关键时刻自查」；HeyChengC 引擎文档里的「容易踩的坑」；还有我自己复刻时踩到的「写实照片代码做不出来，要提前说清需要什么素材」。

## 我的看法

最后，跟大家随便聊聊。

先说说我对这股风的看法。我觉得用 AI 写代码做视频，上限其实很高。模型越来越强，它能理解内容，自己运镜、自己卡点，做出来的东西只会越来越好看。

但我不太建议大家一窝蜂跟风。这种风格，看多了很容易腻。配个音乐，用顶级模型随手做几条，一开始大家会被惊艳到，时间一长，也就看习惯了。就像 GPT Image 2 刚出来那会儿，所有人都被它的生图能力震住，现在呢，大家已经见怪不怪了。

说回我自己。其实我的视频，也是用 Opus 做的，包括这一期。这个我不藏着掖着，也不觉得有什么不好。在我看来，AI 就是个工具，能帮你省很多事，但真要说替代人，至少我觉得，还替代不了。

不怕大家笑话，我剪辑其实不太行。这种动画科普、测评类的视频，我很早就想做了。最早我用 Remotion、HyperFrames 试过，做出来效果真的很一般，token 烧了不少，成品却拿不出手。后来 GPT-6 出来，我又从头试了一遍，还是达不到我想要的样子。

直到 Opus 5.5 出来，才算真正做成了。但这中间的坎坷，说起来也挺有意思。就说视频里的配音，我前前后后换了好几个，一直都不太满意，这期才刚换上。画面也一样，每一期都要来回改很久。

所以我也很清楚，这一期还有不少不足。大家有什么建议，都可以告诉我，我会认真听取大家的意见，争取把这个频道的内容，做得越来越好。
