## 一、它长什么样

真实页面（632 KB）里的形态是：

```html
<script async="" data-script-src="modern-inline">_ROUTER_DATA = {"loaderData":{...},"errors":null}</script>
```

注意三个细节，都是解析时的问题：

| 细节             | 说明                                                                            |
| -------------- | ----------------------------------------------------------------------------- |
| 无 window. 前缀 | 是裸变量 _ROUTER_DATA =，不是 window._ROUTER_DATA。项目正则 (?:window\.)? 是为了兼容两种写法 |
| = 两侧有空格      | 必须 \s*=\s*，写死 ={ 会漏                                                         |
| 数据段 21,578 字符  | 整页 63 万字符，数据只占 3%，其余是 HTML 和运行时脚本                                             |

**18 处 _ROUTER_DATA 里只有第 1 处是真数据**，其余分别是 _ROUTER_DATA.r = ...、initRouterData(...) 之类的运行时函数。所以不能用 indexOf('_ROUTER_DATA') 再截到 </script>——那会截到一段 JavaScript。必须定位第一个 {，再用括号深度和字符串状态机配平。项目里的 readRouterData 就是这么做的。

## 二、完整结构树

```
_ROOTER_DATA
├── loaderData
│   ├── detail_layout : null                    ← 常为 null，find 时必须跳过
│   └── detail_page   : object(5)
│       ├── req               : object(16)      ← 运行时配置，与剧无关
│       ├── recommendations   : object(0)       ← 实测为 {}，空
│       ├── seriesDetail      : object(14)      ← 剧集主数据
│       ├── seriesSocialInfo  : object(4~7)     ← 评分/评论/点赞
│       └── isSuccess         : boolean
└── errors : null                               ← 加载失败时的错误集合
```

## 六、req（16 字段，运行时配置，不该透出）

| 字段 | 类型 | 说明 |
|---|---|---|
| webID | string(34) | 本次请求追踪 ID，每次不同 |
| userAgent / hostname / domain / reqName | string | 请求环境；hostname 是内网 IP |
| isSSRPage / isEnableCache / isInside / encryptedBrowserAllowed | boolean | 渲染与缓存开关 |
| uuid | string(19) | 访客标识 |
| cpaConfig | object(3) | 投放配置 {enabled, channelSources, pageStartedAt} |
| semDeliveryConfig | object(2) | 广告投放配置 |

req 是全站通用配置，跟具体剧集无关，还含内网 IP 和追踪 ID，**不应对外暴露**。项目没透出它是对的。

## 七、类型规律（比字段表更重要）

| 规律 | 表现 | 处理 |
|---|---|---|
| 数字有两种写法 | episode_cnt 是 number，series_like_count 是 "108000" | 统一 Number() + 有限性校验 |
| 时间戳全是**秒级字符串** | "1792995384"、"1793104166" | <1e12 时 ×1000 转毫秒 |
| ID 一律字符串 | 19 位，超 JS 安全整数 | 绝不转 Number |
| 可选字段直接缺键 | rating 在部分剧中不存在 | ?? null，不能假设存在 |
| 空容器形态不一 | detail_layout: null、recommendations: {}、celebrities: [] | 判空要覆盖三种 |

## 八、映射到接口输出

| 上游 | 接口输出 | 转换 |
|---|---|---|
| seriesDetail.series_id | 仅用于身份校验 | 与请求 ID 比对 |
| seriesDetail.episode_right_text | episode_label + completion_status | trim、截 80、正则推导 |
| seriesDetail.first_visible_time | published_at | 秒 → 毫秒，未来值置 null |
| seriesSocialInfo.rating / rating_count | rating / rating_count | Number + 有限性 |
| series_like_count / series_favorite_count | like_count / favorite_count | Number |
| reviews.total_count | reviews.total | Number |
| reviews.reviews[] | reviews.items[] | 改名 + 过滤 + 截断（6 字段全保留） |
| episodeSocialInfo.* | episode_reviews / episode_like_count | 仅 /player 页存在 |
| series_name / cover / intro / tags / vid_list 等 11 个 | **未透出** | 需要时改 parsePublicDetails |
| req | **未透出** | 含内部信息，建议永不透出 |

## 九、三个实测确认的注意点

1. **accessible_episode_cnt 会变**：同一部剧两次抓取分别是 3 和 30，跟限免/权限有关。任何基于它的判断都要放在实时请求上，不能缓存或写死。
2. **reviews.reviews 只有 9 条**，而 total_count 是 21。热度榜剧是 3836 / 9、907 / 9——官网详情页固定渲染约 9 条，翻页接口不存在。
3. **errors: null** 是正常态；非 null 时表示 loaderData 有段落加载失败，此时 isSuccess 可能仍是 true，要单独看 errors。
