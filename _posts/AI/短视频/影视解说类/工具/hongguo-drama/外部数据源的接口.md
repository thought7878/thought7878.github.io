## 3 个维护时必须注意的问题

**1. 高清下载 100% 依赖 App 签名。** `fetchPlayUrlSingle` 只在 `quality === 'auto'` 时走「官网→App→旧接口」三级降级；用户选定 720P/1080P 时官网明文 MP4 被主动跳过。签名一旦失效，标清还能看，高清直接全挂。

**2. 签名失效会伪装成“空响应”。** 服务端不返回 4xx，而是 `200 + 0 字节`（`EMPTY_RESPONSE`）。这是整个项目最难定位的故障形态，排查时不要只看 HTTP 状态码。

**3. 护栏有缺口。** `main.requestMedia` 只对 `source === 'web' || 'custom'` 注入 `webMediaRequestOptions`，河马和西饭的 mp4 直链只有“必须 HTTPS、无账号密码”的静态校验，不走 DNS 内网拦截。如果上游被投毒返回 `https://10.0.0.1/x.mp4`，会被放过。HLS 路径因为统一走 `remuxHls`，反而完全受保护。

### 9.5 双通道优先级（红果自有源）

| 维度 | 官网通道（优先） | App 通道（回退） |
|---|---|---|
| 分集 | B2 `/player/{sid}` 或 `/detail?series_id=` | A10 `multi_video_detail/preload/v1` |
| 播放 | B3 `/player/{sid}/{vid}` | A8 `multi_video_model/v1` → A11 旧接口 |
| 签名 | 无 | 五件套签名 |
| 返回 | `source:'web'`、`spadeA:null` | `source:'app'`（带 `variants`）/ `'api'`（带 `spadeA`） |
| 加密 | 无 CENC，直接可播 | 有 `spade_a` → `deriveKey` → CENC-AES-CTR 解密 |
| 回退触发 | — | web 抛错 / 解析失败 / `vids` 为空 / `protectedPlayback` / `SECURITY_BLOCKED` / `failedWebMedia` 命中 / **`quality !== 'auto'`** |


> **重要**：`fetchPlayUrlSingle` 仅在 `quality === 'auto'` 时走三级降级。用户选定 720p/1080p 时**直接走 App 签名接口**，官网明文 MP4 完全不被尝试 —— 这是刻意的「清晰度可信度」取舍，代价是高清下载对签名可用性 100% 依赖。

## 11. 维护提示

### 11.1 改接口时的检查清单

1. **新增出站域名** → 同步更新 1.2 域名表 + A1 白名单（`fqnovel.com`/`snssdk.com`）+ C7 `validateSource` 校验规则。
2. **新增 HTML 抓取** → 必须用 `readRouterData` 式**括号配平解析**，禁止 `eval` / `new Function`，禁止执行远端脚本。
3. **新增媒体地址** → 必须过 G1；若为自有源，确认 `main.requestMedia` 的护栏注入条件是否需要扩展。
4. **新增缓存** → 只在成功路径写入；容量要有上限（防止长会话内存泄漏）。
5. **新增错误** → 归入 9.4 错误码字典，文案必须是可操作的中文，不暴露签名 URL / 设备指纹。
6. **新增 IPC** → 经统一包装层注册，写操作通道加入 `UPDATE_BLOCKED_CHANNELS`。

### 11.2 已知风险点

| 风险 | 影响 | 位置 |
|---|---|---|
| **签名静默失效** | 签名算法漂移时服务端返回 `200 + 0 字节`（`EMPTY_RESPONSE`），而非 4xx，最难定位 | A2/A4/A7 |
| **高清下载 100% 依赖 App 签名** | `quality !== 'auto'` 时官网通道被跳过，签名一挂高清就全挂 | `hongguo.fetchPlayUrlSingle` |
| **hema/xifan 媒体直链无 DNS 护栏** | 上游投毒返回内网地址时静态校验会放过 | `main.requestMedia` |
| **hema 强依赖 SSR 结构** | `__NEXT_DATA__` + `props.pageProps` 改版即失效；`maxRedirects: 0` 使 301 域名直接失败 | C1/C3 |
| **自定义源恒用 `ac=detail`** | 标准 MacCMS 通常要求 `ac=videolist`，兼容性隐患 | C7/C8 |
| **第三方源无缓存** | 每次进详情都打一次上游，`fetchPlayUrlSingle` 每次都重拉权限态 | `hongguo.fetchEpisodeList` |
| **公告无本地兜底** | `announcements/*.json` 未纳入 `build.files`，断网时紧急公告无法展示 | F1/F2 |
| **公告/更新走主进程 axios 不遵循应用内代理** | 必须走代理才能出网的环境下，`get-proxy-status` 显示 `effective: true` 但这两条仍会直连失败 | F1/F3、`test-proxy` |
| **更新检查未处理 GitHub 配额语义** | 无 `X-RateLimit-*`、无 ETag，靠网页 302 规避；属可用但非显式的策略 | F3/F4 |
