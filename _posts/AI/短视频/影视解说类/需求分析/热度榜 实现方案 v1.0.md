**核心判断**：热度榜唯一的风险是被当成“红果榜截图”。所以它的差异化来自**三换原则**：换分母（拆赛道、做新剧榜）、换分子（按周涨幅排，不按绝对热度排）、换解释（每部一句归因）。

**关键设计**：

1. **评分公式**（100 分制）
 `100 × (0.28 体量 + 0.32 周涨幅 + 0.18 追剧转化 + 0.12 互动密度 + 0.10 新鲜度)`
 涨幅权重高于体量，因为榜单要告诉观众“下一步看什么”；体量保留 28%，是为了让观众看到熟悉的剧名。

2. **数据地基是日快照表**，只追加、不覆盖。这带来一个必须提前想清楚的**冷启动问题**：算涨幅要 14 天历史，但账号第 1 周就要发。解法是前 3 期发“静态热度榜”并**明说**：“今天先看谁最火，从第 4 期起给你看谁在往上冲”——把数据积累期变成追更理由。

3. **关键工程约束**：`hot_score` 只有 App 批量 meta 能拿到，官网 SSR 没有热度值。但 2,900 部 ÷ 20 部一批 = **每天 150 请求**，和“123 万部全量”差 8000 倍，这个量级可接受（只用批量 meta，不碰播放直链）。

4. **双轨校验**：平台热度口径不透明且会变，自算 `H_self = 0.5·log(ΔP7) + 0.3·log(F) + 0.2·log(D+C)` 做交叉，排名差 >15 名就标“口径背离”，人工复核。

5. **一次采集，三种切法**：总榜 TOP10（周一主发）+ 新剧榜 TOP5 + 黑马榜 TOP3（加速度最高），边际成本≈0，内容密度 ×3。

6. **与口碑榜的边界**：热度榜只回答“多少人在看”，绝不回答“好不好看”。两者背离（热度第 1、口碑垫底）往往是最好的选题，并非事故。

7. **两条硬 KPI**：TOP10 每期新面孔 ≥3 个；与平台榜重合度 ≤70%。这两个数掉下来，就说明你在做搬运。

落地 P0–P5 约 **9 个工作日**到首期上线（数据积累 14 天可与开发并行）。建议先做 **P0 口径定档**——写 300 字公开版口径，念给一个不看短剧的人，他能复述出“按什么排的”，再动代码。

# 热度榜实现方案 v1.0

> 对应《影视排名 1.0》第 2.1 节「榜单类型矩阵」中的**热度榜**一行  
> `定位`：每周一发布 · 蹭流量 / ***拉新主力***  
> 编制日期：2026-10-28　｜　数据源：红果短剧（hongguoduanju.com + App meta 批量接口）  
> 一句话结论：**热度榜不是「排行榜」，是「注意力流向的周报」。照搬平台榜 = 搬运；换分母、换分子、换解释 = 内容。**

---

## 一、设计目标与定位

### 1.1 先明确一件事：热度榜卖的不是排名，是「变化」

*红果首页已经有无数的「热播榜」「飙升榜」*。如果我们的 TOP10 和平台榜 TOP10 有 8 个重合，那观众看你就是在看一个二手截图——**这是热度榜唯一的死法**。

所以热度榜的设计核心是*一条差异化的三换原则：*

| 换什么       | 平台怎么做          | 我们怎么做                                       | 带来的内容价值                        |
| --------- | -------------- | ------------------------------------------- | ------------------------------ |
| **换分母**   | 全站混排，大 IP 永远霸榜 | 拆赛道：总榜 / 新剧榜（上架 ≤30 天）/ *分类型榜*（AI 剧、漫剧、真人剧） | *「大 IP 之外的剧才有机会被看见」——这是观众的刚需*  |
| **换分子**   | 给「此刻的热度」绝对值    | 给「一周涨了多少」加速度                                | *观众第一次能看到「谁在往上冲」，而不是「谁已经冲上去了」* |
| ***换解释*** | *只给排名数字*       | **每部一句「为什么涨」的归因**                           | **排名是信息，归因是观点——观点才是账号**        |

### 1.2 四层定位

1. **账号层**：拉新主力。`热度榜`是四条内容线里**唯一自带平台流量红利的（*蹭热点、吃搜索*），预期*承担 40–50% 的新增粉丝***。
2. **内容层**：唯一「零主观」栏目。口碑榜靠口味，场景榜靠策展，只有热度榜是纯数据——它的作用是**对冲**：当有人在评论区骂你「凭啥说这剧烂」，热度榜就是你的信誉背书（「我骂它烂，但我照样把它排在热度第一，我没双标」）。
3. **数据层**：其他三榜的**候选池供给方**。热度榜 TOP50 是口碑榜、场景榜的选片范围，一次采集喂四条内容线。
4. **资产层**：可年度化、可工具化。52 期快照沉淀下来就是「2026 年度热度总榜」和小程序榜单的地基。

### 1.3 五条可验收的设计目标

| 编号  | 目标       | 量化验收标准                                   |
| --- | -------- | ---------------------------------------- |
| G1  | **可复现**  | 任何人按公开口径 + 同样的数据，能算出与发布结果误差 ≤1 名的榜单      |
| G2  | **可解释**  | 每个名次能用一句话说清「为什么是它」，不能出现「数据就是这样」          |
| G3  | **可自动化** | 单期从取数到出片，人工介入时间 ≤15 分钟                   |
| G4  | **可回溯**  | 任意历史期可复算，快照不覆盖、只追加                       |
| G5  | **有差异**  | 与红果站内榜 TOP10 的重合度 ≤70%，每期 TOP10 新面孔 ≥3 个 |

**G5 是硬指标**。低于 70% 说明你在输出平台没有的信息；高于 70% 说明你在做搬运，用户迟早会去平台自己看。

### 1.4 明确不做什么

- 不做「全网最全热度榜」——123 万部剧的绝对值排名，平台比你权威，做了就是自曝短板。
- 不做无来源的「热度值」——所有数字必须标注采集口径与截止时间。
- *不做纯截图搬运*——即使数据全对，没有归因就是搬运。
- *不接「帮我上热度榜」的商单*——这是唯一能一次毁掉账号的单子。

## 二、数据指标与评分口径

### 2.1 指标分三层：原子 → 派生 → 复合

#### 原子指标（红果日采集，字段来自《按 ID 取数实现分析》实测）

| 字段                           | 含义        | 采集通道                                             | 备注                                       |
| ---------------------------- | --------- | ------------------------------------------------ | ---------------------------------------- |
| `hot_score`                  | 红果热度值（综合） | App 批量 meta（`multi_video_detail/preload`，20 部/次） | **这是热度榜的主指标**；官网 SSR 拿不到                 |
| `series_play_cnt`            | 累计播放量     | 同上                                               | 与 hot_score 是两个数，别混（实测 4015 万 vs 8686 万） |
| `followed_cnt`               | 追剧/收藏人数   | 官网 SSR 也有                                        | 转化率分子                                    |
| `digg_cnt` / Σ`digged_count` | 剧级/分集点赞   | 官网 SSR 有分集值                                      | 互动密度分子                                   |
| Σ`comment_count`             | 分集评论数求和   | 官网 SSR 有分集值                                      | 互动密度分子                                   |
| `episode_cnt`                | 总集数       | 两边都有                                             | 集均归一用                                    |
| `create_time`                | 上架时间（秒级）  | App meta                                         | 算 age、新剧榜                                |
| `series_status`              | 1=完结      | 两边都有                                             | 准入过滤                                     |
| `category_schema`            | 分类/题材     | 两边都有                                             | 分赛道榜                                     |

> **关键工程约束**：`hot_score` 只有 App 签名详情接口能拿到。但注意量级——候选池 3000 部、20 部/批 = **150 请求/天**，与「123 万部全量」差 8000 倍。这个量级不构成「规模化规避技术措施」，属于可接受的自用研究范畴。但仍建议：只用批量 meta，不碰播放直链，不下载正片。

#### 派生指标（榜单真正的信息量在这里）

| 指标             | 公式                                  | 回答什么问题                     |
| -------------- | ----------------------------------- | -------------------------- |
| 周播放增量 `ΔP7`    | `P_t − P_{t−7}`                     | 这周多了多少人在看                  |
| **周热度涨幅 `g7`** | `(H_t − H_{t−7}) / max(H_{t−7}, 1)` | **谁在往上冲（榜的核心）**            |
| 追剧转化率 `rate_f` | `F_t / max(P_t, 1)`                 | 看了之后愿不愿意追下去                |
| 互动密度 `idr`     | `(D + 3C) / max(P/10000, 1)`        | 每万播放产生多少互动（评论权重 ×3，因为成本更高） |
| 集均热度 `H_ep`    | `H_t / episode_cnt`                 | 剔除「千集长剧」的体量碾压              |
| 加速度 `accel`    | `g7(本期) − g7(上期)`                   | 黑马探测器：从 20 名冲到 5 名的那种      |
| 上架天数 `age`     | `(T − create_time)/86400`           | 新鲜度、新剧榜准入                  |

#### 复合指标：HeatScore（100 分制）

```
HeatScore = 100 × ( 0.28·S_体量 + 0.32·S_增速 + 0.18·S_转化 + 0.12·S_互动 + 0.10·S_新鲜 )
```

各自定义（**必须写进公开口径文档，这是 G1 可复现的前提**）：

| 分项     | 计算                           | 归一方式         | 为什么这么定                                 |
| ------ | ---------------------------- | ------------ | -------------------------------------- |
| `S_体量` | `log10(hot_score + 1)`       | 候选池内 min-max | 取 log 是为了压住千集大剧的绝对优势；不做分位是因为要保留「差距感」   |
| `S_增速` | `g7`                         | 候选池内**分位**   | 分位抗极端值：有新剧一周涨 30 倍，不会把其他剧全压成 0         |
| `S_转化` | `rate_f`                     | 候选池内分位       | 追剧率是「内容留人」的最硬信号                        |
| `S_互动` | `idr`                        | 候选池内分位       | 点赞评论密度                                 |
| `S_新鲜` | `clamp(1 − age/45, 0.15, 1)` | 直接公式         | 45 天以上的剧最高只能拿 1.5 分（10×0.15），保证榜面向「现在」 |

**权重设计的逻辑（要能对外讲）**：

- **增速 32% > 体量 28%**——榜单的价值是告诉观众「下一步看什么」，如果只是重复平台已经说过的「谁最火」，那这条内容没有增量。增速权重最高，保证每期榜都在动。
- **体量保留 28%**——不能让大剧完全消失。观众点进来要看到熟悉的剧名，否则会觉得「你排的这些都是啥」，信任建立不起来。
- **新鲜度只给 10%**——它是调味，不是主菜。给太高就变成「新剧榜」了，而新剧榜是独立栏目。
- **总量 100 分**，对外只讲「综合热度分」，不讲单项分——单项分留给「评分标准详解」那一期。

#### 缺数据的处理（很重要）

上架不足 7 天的剧没有 `H_{t−7}`，不能算 `g7`。做法：

```
g7_est = (H_t / H_first − 1) × 7 / max(age, 1)
```

`H_first` = 该剧首次入池快照的热度。标记 `est=true`，榜单页脚注明「*新剧采用首周折算涨幅」。

### 2.2 候选池与准入规则

**候选池（分母）定义**——必须在每期视频里公示，这是公信力的关键：

```
池 = ① 红果各榜单 TOP200 去重
   + ② 4 个分类页 × 前 34 页（SEO 上限 800/类）
   + ③ 近 45 天新上架剧
   + ④ 上期榜单 TOP50 强制保留（防止掉榜后失联）
≈ 3,000 部，去重后约 2,400–2,900 部
```

**准入（必须全部满足）**：

- `status = 1`（正常上架）、未下架
- `episode_cnt ≥ 20`（低于 20 集的样本噪声太大）
- `age ≥ 2`（上线首日热度是运营推的，不是观众选的）
- `play_cnt ≥ 100,000`（过小的样本分位失真）
- 有备案号 `record_info.record_number`（合规项，无备案不碰）

**剔除**：付费占位剧、审核异常、涉敏感题材（医疗/时政/擦边）。

### 2.3 双轨交叉校验（防平台改口径）

平台 `hot_score` 的算法不透明，且会随版本调整（参考《可行性方案》第 5.2 节：接口月级漂移）。所以必须有一套自算热度做交叉验证：

```
H_self = 0.5·log10(ΔP7 + 1) + 0.3·log10(F + 1) + 0.2·log10(D + C + 1)
```

校验规则：

| 情况                           | 处理                              |          |                                 |
| ---------------------------- | ------------------------------- | -------- | ------------------------------- |
| \`                           | rank(hot_score) − rank(H_self)  | > 15 名\` | 标记「口径背离」，人工看这 5–10 部，视频里不提其具体名次 |
| `hot_score` 字段为空 / 为 0       | 用 `H_self` 排名兜底，卡片名次加 `*` 并脚注说明 |          |                                 |
| 某剧 `hot_score` 单日跌 >50% 且非下架 | 疑似口径调整或数据异常，**暂停该期发布**，人工核对     |          |                                 |
| 全池 `hot_score` 集体缩水 >30%     | 平台口径变了。当期降级为「自算热度版」，并在视频里说明     |          |                                 |

### 2.4 **对外展示**口径（视频里只说三个数）

内部算 5 个分项，**对外只展示 3 个数**。观众记不住公式，记不住五个维度，但记得住「涨了 47%」。

**榜单卡片字段（固定模板）**：

```
[ 03 ]  剧名
        玄幻 / 系统 / 异界　·　全 81 集　·　漫剧
        热度 8,686 万　↑ 47%（近 7 日）
        一句话：为什么涨（一个具体归因，≤20 字）
```

**片尾固定角标**：

> 数据来源：红果短剧站内公开数据　｜　采集截止：10 月 26 日 24:00　｜　候选池 2,847 部  
> 完整评分口径见置顶评论

这三行必须在**每一期**出现，同一个位置、同一个字号。这是 G1 可复现的落地形式。

## 三、榜单生成与更新机制

### 3.1 时间轴（先有数据，后有榜）

热度榜最大的工程陷阱是：**它需要历史快照才能算增量，但账号第 1 周就要发内容**。所以时间轴必须按「先攒数据」来排。

```
T-14  开始每日快照（此时还没发任何热度榜内容）
T-7 … T-1   每日 06:00 采集（候选池 2,900 部 / 20 部一批 = 145 请求 ≈ 8 分钟）
T     周一 07:00  自动生成榜单
      周一 09:00  人工复核（15 部：TOP10 + 5 个存疑）
      周一 12:00  发布（午休档，工作日次高峰）
      周一 21:30  补发小红书图文版（清单体 + 搜索词标题）

数据窗口：自然周（上周一 00:00 — 上周日 24:00）
```

**为什么用自然周不用滚动 7 日**：观众听不懂「滚动 7 日」；「上周」是所有人共享的时间框架；自然周还能直接年度化（52 期 = 一年）。

### 3.2 存储设计（SQLite 三表）

```sql
-- 主表：最新态
series(series_id TEXT PK, title, category, episode_cnt, create_time,
       status, cover_url, record_number, first_seen, last_seen)

-- 日快照：榜单的地基。只追加，永不覆盖
snapshot(series_id TEXT, snap_date DATE,
         hot_score INT, play_cnt INT, followed_cnt INT,
         digg_cnt INT, comment_cnt INT, is_interp BOOL,
         PRIMARY KEY(series_id, snap_date))

-- 榜单留档：可回溯
ranking(issue_no INT, board_type TEXT, rank INT, series_id TEXT,
        heat_score REAL, g7 REAL, snap_date DATE,
        PRIMARY KEY(issue_no, board_type, rank))
```

三条纪律：

1. `snapshot` 只 INSERT 不 UPDATE。重算只写新行，历史永不改写。
2. 字段缺失写 `NULL`，**绝不填 0**（下游必须能区分「0 播放」和「没抓到」）。
3. `is_interp=1` 表示插值补的，榜单里这类剧不进 TOP10。

### 3.3 生成算法（伪代码，可直接改写成 Python）

```python
def build_ranking(T, pool):
    for s in pool:
        h0 = snap(s.id, T - 7); h1 = snap(s.id, T)
        if h0 is None:                       # 新剧
            s.g7, s.est = (h1.hot / s.first_hot - 1) * 7 / max(s.age, 1), True
        else:
            s.g7, s.est = (h1.hot - h0.hot) / max(h0.hot, 1), False

        s.vol   = log10(h1.hot + 1)
        s.rate  = h1.followed / max(h1.play, 1)
        s.idr   = (h1.digg + 3 * h1.comment) / max(h1.play / 1e4, 1)
        s.fresh = clamp(1 - s.age / 45, 0.15, 1.0)

    S = {k: normalize(pool, k) for k in ("vol", "g7", "rate", "idr")}   # vol=minmax, 其余=分位
    for s in pool:
        s.score = 100 * (0.28*S.vol[s] + 0.32*S.g7[s] + 0.18*S.rate[s]
                         + 0.12*S.idr[s] + 0.10*s.fresh)

    top = sorted(pool, key=score, desc=True)[:30]
    new_cnt = len([x for x in top[:10] if x.id not in last_issue_top10])
    if new_cnt < 3: warn("换血率不足，权重需复查")   # G5 的自动守门
    return top
```

**参数外置**：5 个权重、45 天新鲜度衰减、准入阈值全部放 `config.yaml`。调参不碰代码——这是 P2 的验收标准。

### 3.4 一次采集，三种切法（内容量 ×3，成本 ≈0）

| 榜型           | 口径                      | 位置           | 作用          |
| ------------ | ----------------------- | ------------ | ----------- |
| **总榜 TOP10** | 全池 HeatScore            | 主发（周一 12:00） | 拉新主力        |
| **新剧榜 TOP5** | `age ≤ 30` 的全池          | 视频中段「新剧区」    | 差异化核心，平台榜没有 |
| **黑马榜 TOP3** | `accel` 最高（本周涨幅 − 上周涨幅） | 结尾「本周最大意外」   | 钩子素材，可单独剪一条 |

三个榜共用一套数据、一个脚本，边际成本几乎为零，但内容密度翻三倍——这是热度榜最被低估的价值。

### 3.5 异常与止损

| 情况     | 触发条件                     | 处理                                         |
| ------ | ------------------------ | ------------------------------------------ |
| 单日快照缺失 | `snapshot` 当日行数 < 池的 95% | T-8 与 T-6 线性插值，标 `is_interp`，该剧不进 TOP10    |
| 采集失败率  | > 5%                     | 当期降级「静态热度榜」，视频开头 15 秒说明                    |
| 字段漂移   | 核心字段连续 50 条为 NULL        | 立即停抓，人工核对（照《可行性方案》P5）                      |
| 风控     | 429 / 110001 / 验证码       | 熔断 6 小时，当期顺延一天发布，不硬刚                       |
| 口径突变   | 全池热度集体缩水 >30%            | 切 `H_self` 口径，并在视频里公开说明这件事（**这是加分项，不是丢脸**） |

### 3.6 冷启动的三期策略（必须提前想清楚）

前 3 期没有 `Δ`，讲不了「涨了多少」。三种做法，推荐第 3 种：

| 做法                | 问题                                                   |
| ----------------- | ---------------------------------------------------- |
| 硬编一个涨幅            | 一旦被扒出来就完了，绝对不做                                       |
| 前 3 期不发热度榜，改发别的   | 浪费周一档期，且拉新主力缺席                                       |
| **✅ 发「静态热度榜」并明说** | 「今天是第一期，我先给你看现在谁最火；从第 4 期开始，我给你看谁在往上冲——这比『谁最火』有用得多。」 |

第 3 种做法把「数据积累期」变成了**追更理由**。观众第一次听到「下期开始我给你看谁在涨」的时候，你的更新时间就进他脑子里了。

## 四、**与选题库其他榜单的差异**与协同

### 4.1 **四榜正交矩阵**（这张表要贴在工作台前）

| 维度      | **热度榜**      | 口碑 / 避雷榜              | 场景清单榜               | 期待 / 前瞻榜               |
| ------- | ------------ | --------------------- | ------------------- | ---------------------- |
| `回答的问题` | *有多少人在看*     | *值不值得看*               | 什么时候看               | 会不会火                   |
| 时间指向    | 现在（*过去 7 天*） | 过去（*已播完*）             | 现在（可立即消费）           | 未来（*未播/待播*）            |
| `数据来源`  | 站内量化指标（全自动）  | *评分 + 完播 + 评论情绪*（半自动） | 人工策展 + 集数/时长结构（全人工） | 预告物料 + 预约量 + 前作表现（半人工） |
| 客观性     | 最高（零主观）      | 中（含口味判断）              | 低（策展）               | 中（含预测）                 |
| `内容作用`  | **拉新**       | **涨粉** / 立人设          | 收藏 / 完播             | 搜索占位 / 系列化             |
| `时效强度`  | 强            | 弱                     | 中                   | 强（节点）                  |
| `主要风险`  | 被认为「搬运平台榜」   | 被认为「主观引战」             | 被认为「水文」             | 预测翻车                   |
| 更新      | 周更（周一）       | 周更（周三）                | 周更（周五）              | 月更                     |
| `视频形态`  | 快节奏盘点 + 数据卡片 | 观点输出 + 对比             | 清单 + 适用人群           | 预告剪辑 + 期待值             |

### 4.2 一句话边界（写在口径文档第一行）

> **热度榜只回答「有多少人在看」，绝不回答「好不好看」。**

这条边界守住了，四榜就不会互相打架；守不住，热度榜就会变成第二个口碑榜，四条线塌成两条。

### 4.3 四条数据协同流

```
热度榜 TOP10  ──①──>  口碑榜必评池（周三从这 10 部里挑 3 部深评）
热度榜「高开低走」──②──>  避雷榜头名（热度体量前 5，但周涨幅为负）
热度榜「新剧入榜」──③──>  期待榜的验证样本（上期预测的剧，这周真上榜了吗）
热度榜 TOP50  ──④──>  场景榜筛选池（按时长/集数/标签切「下饭」「一口气刷完」）
```

逐条说清怎么用：

**① 给口碑榜供片**：周三不可能评全站，评谁？就从周一热度榜 TOP10 里选。这样两条内容天然咬合——观众周一看到的剧，周三就有人给判断。

**② 给避雷榜供钩子**：「热度第 3，但这周跌了 22%」——这种剧是避雷榜最好的开场。它自带冲突：全网在追 vs 它在跌，观众立刻想知道为什么。

**③ 给期待榜做复盘**：期待榜最怕「预测完就没人管了」。用热度榜验证：「上个月我押的 3 部待播，现在 2 部进前 20 了，1 部扑了，我认。」——预测敢复盘，公信力直接上一个台阶。

**④ 给场景榜做筛选**：场景榜完全人工策展，但选片范围应该是热度榜 TOP50，而不是全站瞎逛。这样场景榜不会推没人看的剧，转化率更高。

### 4.4 「打架」怎么处理——这是最好的内容，不是事故

必然会出现：热度榜第 1 名，口碑榜垫底。**这不是矛盾，这是账号最值钱的一期内容。**

处理规则（第一期就要立）：

1. 视频里明确区分两个词：**「热」= 多少人在看，「好」= 我判断它多好**。这两个数在现实里经常背离，指出背离本身就是专业性的证明。
2. 允许并鼓励做这种选题：「全网都在追，我为什么把它排进避雷榜第 1 名」——原方案 2.1 节的反差公式，最好的素材来源就是热度榜和口碑榜的差值。
3. 话术模板：**「它热度第一，这我没意见，数据摆在这；但它口碑第 9，这也是数据。你可以两个都信。」**——不否定任何一方，只呈现背离。

### 4.5 排期咬合（用热度榜给口碑榜导流）

```
周一 热度榜结尾：「这 3 部，周三我告诉你哪部不值得看。」
周三 口碑榜开头：「周一热度榜第 2 的那部，今天我要泼冷水。」
周五 场景榜：「这周热度榜前 20 里，只有这 5 部适合下饭。」
```

每条视频结尾都给下一条留钩子。这是四条内容线从「四个栏目」变成「一个节目」的关键动作——**观众追的是节奏，不是单条**。

## 五、落地思路与分步执行方案

### 5.1 总体思路：先有口径，再有数据，最后有内容

顺序不能反。绝大多数榜单号死在第 3 期，原因都是「先拍视频，口径后补」——被质疑一次就再也圆不回来了。所以：

```
P0 口径定档 → P1 采集管道 → P2 榜单引擎 → P3 内容生产 → P4 发布 SOP → P5 迭代校准
 （先立规矩）   （先攒数据）    （先能重算）   （先做样片）    （先跑四周）    （再调权重）
```

### 5.2 分阶段执行表

| 阶段            | 工时  | 产出物                                                                                                           | 验收标准                              |
| ------------- | --- | ------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| **P0 口径定档**   | 1 天 | ①《热度榜评分标准 v1.0》**公开版 300 字**（能念给外行听懂）②内部版公式表 ③数据来源声明文案 ④候选池定义                                                 | 把口径讲给一个不看短剧的人听，他能复述出「按什么排的」       |
| **P1 采集管道**   | 2 天 | 复用《可行性方案》档位 A：sitemap 清单 + 分类页 + `/metrics/batch` 批量 meta；建 `series` / `snapshot` / `ranking` 三表；首轮灌满 2,900 部 | 成功率 ≥98%；单日全流程 ≤10 分钟；连续 3 天快照可复现 |
| **P2 榜单引擎**   | 2 天 | `score.py` + `config.yaml` + 输出 `ranking.json` 与卡片素材（名次/剧名/热度/涨幅/集数/标签/一句话）                                   | 改权重只改 yaml，3 分钟内重算全部历史期           |
| **P3 内容生产**   | 3 天 | 90 秒脚本骨架 + 卡片模板（AE/剪映）+ 封面模板（大字报）+ 两期样片                                                                       | 单期从数据到成片 ≤3 小时                    |
| **P4 发布 SOP** | 1 天 | 周一 09:00 定稿 → 12:00 主发 → 21:30 小红书图文；周日 30 分钟复盘表                                                              | 连续 4 期按点发布，零延期                    |
| **P5 迭代校准**   | 持续  | 权重回归 + 站外声量补采 + 年度化                                                                                           | 第 8 期起榜单质量 KPI 达标                 |


**合计 ≈ 9 个工作日到首期上线**（不含 14 天数据积累，可与 P0–P3 并行）。

### 5.3 P0 的具体动作（最重要，别跳过）

写两份文档，一份对外一份对内：

**对外版（300 字，放视频简介 + 置顶评论）**：

> 热度榜怎么排的？
> 候选池：红果在架的 2,800 余部短剧（含全部榜单 TOP200、四个分类页、近 45 天新剧）。
> 综合分 = 热度体量 28% + 周涨幅 32% + 追剧转化 18% + 互动密度 12% + 新鲜度 10%。
> 数据来自红果公开页面，每期采集截止周日 24:00，来源与时间都会打在片尾。
> 我们只排「多少人在看」，不排「好不好看」——后者看周三的口碑榜。
> 榜单每周一中午更新，排名有误请在评论区指出，下期开头更正。

**对内版**：完整公式、归一方法、准入门槛、剔除规则、异常处理、双轨校验阈值。

### 5.4 90 秒主榜脚本骨架

```
[0-3s]   钩子（用数据制造冲突）
        「上周全网红果，掉得最狠的是那部 8000 万热度的剧。」
[3-8s]   价值预告 + 口径一句话
        「本期热度榜，我用『一周涨了多少』排，不是用『现在多火』排。」
[8-20s]  名次 10-6（每部 2-3 秒，快速过，只报数字和标签）
[20-70s] 名次 5-2（每部 12 秒：名次 + 剧名 + 涨幅 + 一句归因 + 适不适合你）
[70-82s] 第 1 名（12 秒，讲透，这里是留人的关键）
[82-90s] 新剧区 TOP3 快闪（10 秒）+ 结尾钩子
        「这 3 部里有 2 部周三会被我泼冷水，关注我，剧荒不慌。」
```

结构要点：**前 5 名慢、6-10 名快**。观众只记得住 3 部，但看到「10 部完整榜单」会觉得信息量大——用速度差同时满足「记得住」和「内容足」。

### 5.5 每周固定动作（SOP）

| 时间 | 动作 | 耗时 |
|---|---|---|
| 周一 07:00 | 脚本自动跑采集 + 生成榜单 | 0（自动） |
| 周一 09:00 | 人工复核 15 部（TOP10 + 5 个存疑），改「一句话归因」 | 30 min |
| 周一 10:00 | 生成卡片素材 + 录口播 | 60 min |
| 周一 11:30 | 剪辑 + 封面 | 60 min |
| 周一 12:00 | 抖音 / 视频号主发 | 5 min |
| 周一 21:30 | 小红书图文版（清单体 + 搜索词标题） | 20 min |
| 周日 20:00 | 复盘：完播、互动、涨粉、搜索占比；记录换血率与平台重合度 | 30 min |

### 5.6 榜单质量 KPI（不是流量 KPI）

流量 KPI 看的是视频表现，榜单 KPI 看的是**榜本身值不值得信**。两个都要记：

| 指标 | 目标 | 不达标怎么办 |
|---|---|---|
| 换血率（TOP10 新面孔数） | ≥3 / 期 | 增速权重上调，或新鲜度衰减从 45 天缩到 30 天 |
| 与平台榜重合度 | ≤70% | 加大新剧榜权重，或改做分类型榜 |
| 数据出错次数 | 0 | 出错必须下期开头 15 秒更正，不删视频 |
| 评论区质疑率 | <5%（质疑/总评论） | 超 5% 说明口径没讲清，加一期「评分标准详解」 |
| 搜索占比 | 逐期上升 | 「XXX 值不值得看」类标题固定加一条 |

### 5.7 P5 权重校准的具体方法（第 8 期开始）

不要凭感觉调权重。用数据调：

1. 记录每期 30 部入榜剧，各自对应的「剪辑素材点击率」（你在成片里给它的镜头时长 vs 观众留存曲线）。
2. 做一次简单回归：`留存提升 ~ w1·体量 + w2·涨幅 + w3·转化 + w4·互动`。
3. 系数归一后作为新权重，但**单次调整幅度不超过 5 个百分点**——口径要稳，微调可以，大改等于换榜，观众会发现。

> 口径可以优化，但**不能为了某期数据好看而改**。改一次就要公开说明一次，这是唯一不会掉粉的改法。

## 六、风险与红线

| 风险 | 表现 | 应对 |
|---|---|---|
| **被认为搬运** | 「这不就是红果榜截图吗」 | 换血率 KPI + 新剧区 + 周涨幅三招；每条视频明示「我们和平台榜的差别在哪」 |
| **数据出错** | 名次算错、热度值抄错 | 下期开头 15 秒更正 + 置顶评论；**不删视频**（删改伤权重），更正透明反而加分 |
| **平台口径变更** | 热度值集体缩水 | 双轨校验 + 快照可回溯；公开说明「平台调整了口径，本期起改用自算热度」 |
| **合规** | 抓取、版权、备案 | 只用公开元数据；不碰播放直链、不下载正片；封面缩略标注来源；无备案剧不进榜；不对外提供数据服务 |
| **个人信息** | 评论含用户名 | 榜单不采集评论用户信息，评论情绪分析只做聚合 |
| **商单诱惑** | 「帮我上热度榜」 | 一律拒绝。可接「宣发向合作」但必须标注「安利向」，且**不进榜、不改分** |
| **预测翻车** | 新剧榜推的剧扑了 | 下期主动认账，这是加分项。榜单号最怕的不是错，是装作没错 |

## 七、一页速查

```
定位：注意力流向周报，不是排行榜
三换：换分母（拆赛道）· 换分子（看涨幅）· 换解释（给归因）
公式：100 × (0.28 体量 + 0.32 涨幅 + 0.18 转化 + 0.12 互动 + 0.10 新鲜)
分母：约 2,900 部候选池，每期公示总数
窗口：自然周（周一 00:00 — 周日 24:00），周一 12:00 发布
地基：日快照表，只追加不覆盖，攒够 14 天才发首期
差异：与平台榜重合 ≤70%，每期新面孔 ≥3 个
边界：只答「多少人在看」，不答「好不好看」
协同：TOP10 喂口碑榜 · 高开低走喂避雷榜 · 入榜剧验证期待榜 · TOP50 喂场景榜
红线：不编涨幅 · 不接上榜单 · 不删视频 · 口径改动必公开
```

---

**一句话总结**：热度榜是四条内容线里唯一能全自动跑的，也是唯一会被质疑「你是不是搬运」的。它的护城河不在数据，在**口径**——口径公开、可复算、不双标，搬运号永远追不上；口径模糊、随期调整，你比搬运号死得更快。
