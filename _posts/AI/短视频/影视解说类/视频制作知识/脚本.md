>制作视频的脚本是什么？为什么要使用脚本？怎么使用脚本？

---

## 一、脚本是什么

**定义**：视频`脚本`是拍摄/制作前写好的*执行文档*，把「*要说什么、画面长什么样、每个片段多长*」提前固定下来。它是*视频的施工图纸——观众看到的是成片，团队照着干活的是脚本*。

**核心组成**（5 个要素）：

| 要素      | 内容                        | 作用             |
| ------- | ------------------------- | -------------- |
| `主题`    | 视频核心观点，一句话说清              | 防止跑题           |
| `受众`    | 拍给谁看，他们的痛点和语言习惯           | 决定语气、术语深浅、节奏快慢 |
| `旁白/台词` | *每一段要说的话*（`口播稿`）          | 内容本体，直接决定信息量   |
| `画面描述`  | *对应每句话的视觉呈现*（实景、录屏、动画、字卡） | 声画对位，避免画面和话对不上 |
| `镜头与时长` | 镜号、景别/运镜、每段秒数             | 控制总时长和节奏       |
| 字幕/花字提示 |                           |                |
| 背景音乐与音效 |                           |                |
| 转场方式    |                           |                |
| 素材来源标注  |                           |                |

常见补充项：字幕/花字提示、背景音乐与音效、转场方式、素材来源标注。

**常见形式**：

1. **文字大纲式**——*只有分段要点和口播稿*，适合口播类、知识类短视频。
2. **分镜表（Storyboard Table）**——*表格*列「*镜号 / 时长 / 画面 / 台词 / 备注*」，*最通用*，广告和剧情类标配。
3. **故事板（Storyboard）**——每格配*手绘草图*，适合*剧情、动画、复杂运镜*。
4. **双栏式（AV 格式）**——左栏画面、右栏声音，宣传片和纪录片常用。
5. **交互/课程脚本**——分支剧情、章节结构，用于互动视频和网课。

## 二、为什么必须先写脚本

一句话：**没脚本的视频，靠现场即兴和后期补救，质量靠运气。**

1. **内容规划**：*脚本逼你先想清楚「这条视频到底要说一个什么观点、给谁看、看完得到什么」*。*先定框架再填肉，能砍掉所有和主题无关的内容*——信息密度是写出来的，不是剪出来的。

2. **叙事节奏**：*时长在脚本阶段就被分配好了*——*开头*几秒抓人、*中段*几个论点各占多少秒、*结尾*怎么收。**短视频前三秒流失率最高**，*钩子*必须在脚本里设计，不能指望剪辑时灵光一现。*旁白*念一遍计时，就能预估成片长度，避免「想讲 1 分钟，录出来 3 分钟」。

3. **镜头安排**：脚本*提前列好每个镜头的景别、机位、素材需求*，拍摄时一次把素材拍全。否则回来剪辑才发现缺一个特写、缺一段录屏，只能补拍或用废镜头凑。

4. **团队协作**：有脚本，*出镜、拍摄、剪辑、配音、审稿的人拿到的是同一份指令*。*台词*改在第 3 版脚本上，改一处全链路同步；没有脚本，沟通全靠口述和微信截图，版本必然混乱。

5. **降低返工成本**：*改脚本是改一行字，改成片是重录重剪*。脚本阶段的评审（自己读一遍、给别人看一遍）成本几乎为零；成片阶段发现「逻辑不通、超时、画面缺素材」，返工成本是脚本阶段的几十倍。**前期多花 1 小时写脚本，后期省 1 天剪片。**

## 三、怎么写并使用脚本

**第一步：先定四个前提**（写脚本前必须回答）：

- **目标**——这条视频要达成什么？*涨粉、转化、还是讲清一个知识点*？目标决定 CTA（引导关注/点击/购买）。
- **受众**——给谁看？他们已知道什么、在乎什么？决定用词和举例。
- **时长**——平台和内容类型倒推：口播干货 1–3 分钟，产品宣传 60–90 秒，课程单节 5–10 分钟。时长定了，才能算出每部分配几秒。
- **发布场景**——*抖音/视频号竖屏 9:16*、*B 站横屏 16:9*；*抖音节奏快钩子前置，B 站可以铺垫*。场景决定画幅、节奏和字卡样式。

**基本流程**（6 步）：

1. `定主题` → 一句话核心观点。
2. `列大纲` → 拆成 3–5 个部分，标每部分时长。
3. `写口播稿` → *按大纲逐段写台词，口语化*，念一遍计时。
4. `配画面` → 每段台词旁*写画面描述和素材需求*（拍什么/找什么素材）。
5. `排分镜` → *编镜号、定景别和运镜*，核对总时长是否超标。
6. `执行与复盘` → 拍摄照脚本拍，剪辑照脚本剪；成片后回看脚本，记录哪些段节奏不对，反哺下一版。

**注意事项**：

- **钩子前置**：*前三秒必须给价值承诺或冲突*，别用「大家好」开场。
- **一段一意**：每个镜头只讲一件事，台词和画面严格对应。
- **口语化**：台词写完读出声，拗口的删掉；*书面语观众听不懂*。
- **留冗余**：预计时长打（的） 90% 写脚本，*留出呼吸感和转场空间*。
- **可量化**：每段标秒数，超时先砍内容而不是加快语速。
- **版本管理**：脚本改版加日期或 v2 标记，团队只认最新版。

**脚本结构示例**（60 秒口播干货视频）：

| 镜号  | 时长     | 台词（旁白）                                 | 画面               | 备注       |
| --- | ------ | -------------------------------------- | ---------------- | -------- |
| 1   | 0–5s   | 学 React 三个月，我踩过的 3 个坑，第 2 个几乎人人中招      | 主播出镜 + 大字卡「3 个坑」 | 钩子：数字+悬念 |
| 2   | 5–20s  | 坑一：直接上手写组件，不先想状态怎么划分……                 | 屏幕录制 + 标注圈划      | 术语保留英文   |
| 3   | 20–35s | 坑二：useEffect 里塞了不该塞的逻辑……               | 代码对比（错/对）        | 红绿对比强调   |
| 4   | 35–50s | 坑三：过早优化渲染性能……                          | 字卡 + 主播口播        | —        |
| 5   | 50–60s | 这 3 个坑避开，你的 React 至少少走半年弯路。关注我，下期讲状态管理 | 主播 + 字卡引导        | CTA 收尾   |

这就是**最小可用的脚本骨架：** 镜号 + 时长 + 台词 + 画面 + 备注。复杂项目*在此基础上加 BGM、转场、字幕样式*列即可，不必一上来就写分镜故事板。
