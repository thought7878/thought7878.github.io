### 0.3 先理解这个 skill 是干什么的

它**不是**一个"一键生成视频"的按钮，而是一套**有严格纪律的流水线**，把「口播稿 + 配音」变成「有动效的成片」。

核心链路：

```
口播稿 → 配音预剪 → 字级时间戳 → 语义标注 → 素材采集
   → SHOTBOOK 分镜 → Remotion 实现 → 渲染 → 三重验收 → 交付
```

八个环节每一步都有**机器可验的闸**（preflight / beat_lint / card_lint / motion_check / sfx_check）。**闸报 FAIL 就停下来查原因，不要硬改**——这是这个 skill 最核心的使用纪律，下面每一步都会重复强调。

它负责**合成侧**，不负责：写稿、TTS 出声（可选接 Fish Audio）、人物视频生成、素材拍摄。

**方案 B（省事）** —— faster-whisper，首跑自动下 460MB：

```bash

# 用的时候加 --backend whisper
```

**两者选型对比**（官方实测，110s 中英混合 20 句，对照 GPU ForcedAligner）：

| 配置                        | 字符偏移中位 | p95   | 最大        | match 误报 | 模型体积  |
| ------------------------- | ------ | ----- | --------- | -------- | ----- |
| **FireRedASR2-CTC int8**  | 40ms   | 100ms | **200ms** | **0**    | 767MB |
| faster-whisper small/int8 | 20ms   | 140ms | 413ms     | 2 句边缘    | 464MB |

**选型判词**：30fps 一帧 33ms，中位差异无感，**尾部才是风险**（动效挂错字）。FireRed 尾部最稳且零误报 → 推荐。whisper 装最轻但尾部 12 帧。

> 30fps 下最大 200ms = 6 帧，肉眼可能看出动效挂错字。**这是选型的真正理由**，不是中位数。

## 3. 输入素材要求

### 3.1 口播稿

**格式**：`script.json`（推荐）或每行一句的纯文本。

```json
{"sentences": ["第一句。", "第二句。", "第三句。"]}
```

**硬性要求**：

| 要求              | 原因                                  | 违反后果                 |
| --------------- | ----------------------------------- | -------------------- |
| **数字一律写汉字**     | 时间戳按文本逐字锚定，`197747` 无法与"十九万七千"的读音对位 | 该句锚点全丢，`match` 暴跌    |
| 每句一个信息点         | 分镜按语义段落切                            | 一句塞三件事 → 镜头塞不下，排版预算爆 |
| 钩子在第一句（数字/冲突）   | 前 3 秒决定完播                           | 平淡开场 → 掉一半           |
| 13 句 ≈ 95 秒     | 经验节奏                                | —                    |
| 英文品牌词直接写        | 中英混合对齐已验证                           | —                    |
| 事实先核实，列「事实红线清单」 | 不可说错的数字不能引用                         | 播出事故                 |

**长度建议**：初学者先做 **90–120 秒 / 12–16 句**。这个体量能跑完整条链路，又不会在第一次就撞上长音频的 ASR 分段问题。

### 3.2 配音音频

**核心原则：配音是「一条完整音频 + 与之逐字一致的口播稿」**。

| 项       | 要求                      |
| ------- | ----------------------- |
| 格式      | wav / mp3 都行（脚本内部重采样）   |
| 必须是最终那条 | 预剪后、后续处理都基于它            |
| 与稿子逐字一致 | 稿子是**真值**——预剪靠它判定哪些是口水词 |

**时长必须与最终成片逐帧对齐**。人物视频（录播/数字人）的时长和配音要一致，口型才对得上。

### 3.3 人物素材（可选但强烈建议）

| 项   | 规格                                                                        |
| --- | ------------------------------------------------------------------------- |
| 形式  | 绿幕 mp4（推荐，抠像自己做）或已抠好的 alpha WebM（VP9，`-pix_fmt yuva420p -auto-alt-ref 0`） |
| 帧率  | **必须等于成片 fps**。不等时优先把成片 fps 定为素材 fps（动效是生成的，改帧率零成本）                       |
| 时长  | 与配音逐帧一致（差 >1 帧就是口型漂）                                                      |
| 宽高比 | 用 `ffprobe` 量真实比例，**不要按容器/期望值算几何**（按错会把人压扁）                               |

> ❗ **禁止靠简单重复帧混入改帧率**：25→30 的重复帧让人物每秒卡 5 次，旁边原生帧率的动效丝般顺滑，对比之下更扎眼。
>
> 先看 `r_frame_rate` 与 `avg_frame_rate` 是否一致 —— 不一致是 VFR/丢帧，先 `-fps_mode cfr -r <avg 就近标准帧率>` 重出。

**抠像配方**（全 CPU，ffmpeg）：

```bash
ffmpeg -i greenscreen.mp4 -vf "format=rgba,\
geq=r='r(X,Y)':g='g(X,Y)':b='b(X,Y)':a='255-clip((g(X,Y)-max(r(X,Y),b(X,Y))-6)*24,0,255)',\
despill=type=green:mix=0.18:expand=0.1,boxblur=0:0:0:0:1:1" \
  -c:v libvpx-vp9 -pix_fmt yuva420p -auto-alt-ref 0 -b:v 0 -crf 30 -an host.webm
```

despill 的 `mix` 只能 0.18 上下，0.5 会把白 T 染粉。**首次用新素材先裁 3s 样片验证边缘再跑全片**。

### 3.4 B-roll / 图片素材

**这是必需项，不是可选项**。全片零 B-roll / 图片 = 只有动效 + 口播人物 = 观众看到的是"讲 PPT"。

`preflight.py` 的判定口径：

- **零 V / 图镜头 → 直接 FAIL**
- V / 图镜头占比 < 1/3 → WARN（要在 SHOTBOOK 给依据，比如证据类题材以截图为主）

| 类型   | 规格                                                  | 落盘目录                                   |
| ---- | --------------------------------------------------- | -------------------------------------- |
| 视频   | Pexels `video_files[]` 里 height ≥1080 的 HD/UHD      | `assets/broll/` 候选 → `public/broll/`   |
| 图片   | Pexels photos **取 `original`**（`large2x` 只有 1880 宽） | `assets/stills/` 候选 → `public/stills/` |
| 网页截图 | Playwright **全页 2× 长截图** + 同一会话 DOM 实测的坐标 JSON      | `public/pages/`                        |

> ⚠️ Pixabay 免费档图片长边上限 1280，**只够 720p / 竖屏 / 配角小图**，不够缓推。
>
> ⚠️ **全部素材下载到本地**，禁止渲染时拉远程（Pixabay URL 有 24h 缓存条款，且远程会导致渲染不确定）。

### 3.5 真图硬规

话题存在可截的真实页面时（产品官网 / GitHub / 文档 / 画廊）：

- 成片中的浏览器/页面类镜头**禁止用代码 mock 冒充截图**
- 真图上的标注坐标**一律机器实测，禁目测**（页面元素用 DOM `getBoundingClientRect`）。目测偏 ±30px 就会把环框到别的元素上
- 会滚动/移动的真图，标注必须钉在**内容坐标系**上随内容动，钉屏幕固定位就是错位根源

### 3.6 单视频镜头的边框规则

镜头里唯一主体是一段视频时，**禁止裸贴满幅、禁止裸放白卡、也不装假播放器**（进度条/播放键/时间码一律不要——不是真播放器就是在撒谎）。必须包一层 `template/components/theme-frame.tsx` 的 `<ThemeFrame kind>`，八式选一，**一片只用一式**。

例外只有两种：视频当**底床**不当主体、产品界面卡（chat-gpt / claude-code 类，皮即内容）。

## 4. 执行流程（八步）

### 步骤 ⓪ 开工体检

```bash
cd ~/.workbuddy/skills/video-talkcraft/runtime && bash check-runtime.sh
```

**必须看到 `[runtime] OK`** 才往下走。

同时定两件事，全流程引用：

- **画幅**：默认横屏 1920×1080；明确要发抖音/竖屏才用 1080×1920
- **视觉语言**：用户点了风格就按用户的；没点则**先从口播稿判定领域**，派生本片风格档（底色策略/accent/字体气质/材质/图表语言/能量档），写进 SHOTBOOK §0 `G0 风格档`

> **制作中途不升级依赖** —— 母版段缓存按依赖版本失效不了，混版本渲出的段会不一致。

### 步骤 ① 口播稿

按 3.1 的要求写。先列「事实红线清单」。

### 步骤 ②-0 配音预剪（真人录音必做）

**顺序不可换：预剪 → 时间戳 → 一切后续**。时间戳做完再动音频 = timing/beats 全体错位。

```bash
# 第一步：只出报告，不改文件
python3 scripts/voice_trim.py audio/raw.wav script.json --dry-run --words-out audio/asr_words.json

# 第二步：用户认可后落盘
python3 scripts/voice_trim.py audio/raw.wav script.json --words audio/asr_words.json --out audio/full.wav \
    [--video dh/host_raw.mp4 --video-out dh/host.mp4]
```

**判定原则**：

- 稿子是**真值**，宁漏勿错
- 只剪 ASR 里**稿子没有的插入段**：口水词（嗯/呃/那个…）、结巴重说
- **ASR 听错稿子里的字永不剪**（剪它就剪掉了那个字的真实发音）
- 稿外改了措辞的重说**只报告**，`--cut-unmatched` 才剪

**停顿处理**：≥0.7s 的静音压到 0.35s；首尾留白 0.25 / 0.5s。切点先找能量谷、再吸附 30fps 帧网格。

> ⚠️ **dry-run 报告必须给用户过目再落盘**。标了「切点未落在静音里，听一下」的条目要人耳确认。

TTS 只需压气口，可跳过这一步。

### 步骤 ② 字级时间戳

```bash
# 方案 A（已有录音，本机 CPU）
python3 scripts/timestamps_cpu.py audio/full.wav script.json audio/timestamps.json

# 备选（免手动下模型）
python3 scripts/timestamps_cpu.py audio/full.wav script.json audio/timestamps.json --backend whisper

# 转成 timing.json
python3 scripts/make_timing.py audio/timestamps.json remotion/src/timing.json
```

**方案 B（可选，Fish Audio 一键出配音+时间戳）**：

```bash
python3 scripts/tts_fishaudio.py script.json audio/full.wav audio/timestamps.json --timing-out remotion/src/timing.json
```

**输出 schema**（任何对齐工具产出同 schema 都能替换）：

```json
{"sr": 24000, "total": 95.2,
 "sentences": [{"i": 0, "text": "…", "start": 0.0, "end": 3.2, "match": 1.0, "ok": true,
                "words": [{"text": "今", "start": 0.1, "end": 0.35}]}]}
```

**质检口径**：每句 `match` = CJK 锚点覆盖率，**< 0.90 标 `ok=false`，必须人工听那一句**。

**长音频注意**：FireRed 整段喂入有硬上限（193s 能跑，210s 起崩），脚本默认按静音切 ≤75s 段再识别后加回偏移。`--chunk-sec 0` 关闭切段。

> ⚠️ **不要给 whisper 传 `initial_prompt`** —— 喂口播稿进 prompt 会让前几段整段幻觉错位。

### 步骤 ②-1 语义标注（必做）

这是 2026-09-22 起的硬性环节。**为什么不能跳**：没有它，选卡只剩「输入类型」一道过滤，剩下几十张卡靠印象挑 —— 曾经「我是万里」就是这样拿到了全库能量最低的文字卡，而人名条卡明明在索引里写着"也用于自我介绍"。


```bash
# 1. 生成骨架（从时间戳出，带词法提示）
python3 scripts/semantic_annotate.py --init

# 2. 逐句填字段：sem / weight / entities / need
```

### 5.6 `motion_check.py`（画面健康闸）

```
python3 scripts/motion_check.py <video> [dur=0.8] [noise=0.003] [--window t,W:H:X:Y] [--anchors anchors.json] [--baseline 素材] [--baseline-crop W:H] [--baseline-offset t]
```

| 参数 | 含义 |
|---|---|
| `dur` | 静止判定时长窗口（秒），默认 0.8 |
| `noise` | 判定阈值（逐帧平均像素差），默认 0.003 |
| `--window` | 抖动检测窗。格式 `t,W:H:X:Y`（时刻、裁剪区宽:高:偏移X:偏移Y）。**人物区窗必加** |
| `--anchors` | 锚点表，每个锚点在 `t+0.6s` 加一窗 |
| `--baseline` | 同窗量源片，素材自带的噪声降 WARN。**有人物素材的片必给** |
| `--baseline-offset` | 源片对应时刻偏移 |

> `--window` 不给时默认裁剪区是 `1200:120:150:150`（标题带区域，本套版式大标题所在处）。**测人物区必须显式给窗**，否则量的是标题带不是人。

### 5.7 `sfx_check.py`（音效闸）

```
# 独奏模式：查在场
python3 scripts/sfx_check.py <sfx-solo.wav> <cues.json>

# 混音模式：查可听
python3 scripts/sfx_check.py --mix <video.mp4> <voice.wav> <cues.json> [--timestamps timestamps.json]
```

| 参数 | 含义 |
|---|---|
| `--mix` | 混音模式。测的是 `[t−0.05, t+0.45]` 0.5s 窗 |
| `--timestamps` | 数句间气口。UNMASKED 门槛不超过气口数，并打印"不可达"原因 |

**良品口径**：MASKED > 50% 或 UNMASKED 少于 `max(3, 片长/30s)` 即 FAIL。
> "81/81 在场但全被人声掩蔽"是典型翻车 —— **在场 ≠ 可听**。

### 5.8 `beat_lint.py`（词落点闸）

```
python3 scripts/beat_lint.py <beats.json> <timestamps.json> [--tol 0.10] [--tail 0.5] [--shots shots.json] [--anchors anchors.json]
```

| 参数 | 默认 | 含义 |
|---|---|---|
| `--tol` | `0.10` | 词落点允许偏差（秒）。超出 FAIL |
| `--tail` | `0.5` | 镜尾保护带（秒）硬底线 |
| `--shots` | `None` | 镜头表，用于查镜尾 |
| `--anchors` | `None` | 锚点表 |

`label` 只许 `[A-Za-z0-9_-]`（要进文件名 / JS 字符串）。

### 5.9 `freeze_probe.py`（静止探针）

| 参数 | 默认 | 含义 |
|---|---|---|
| `--shots` | `shots.json` | 镜头表 |
| `--points` | `3` | 每镜几个时点 |
| `--noise` | `0.003` | 判定阈值，与 freezedetect 同款 |
| `--scale` | `1.0` | 静帧缩放。<1 会平均掉噪声让 mafd 偏小（多报），校准口径是 1 |

| `--browser` / `--entry` / `--comp` / `--props` / `--fps` | — | Remotion 渲染参数 |

### 5.10 `render_shots.mjs`（分段渲染）

| 参数 | 含义 |
|---|---|
| `--shots` | 镜头表 `shots.json`（`[{id,start,end}]`） |
| `--all` | 渲全部镜头 |
| `--only s01,s02` | 只渲指定镜 |
| `--changed s14` | 只渲改动镜（±邻段，lead/tail 交叠会波及邻镜边缘） |
| `--parallel 4` | 段间并行度 |

### 5.11 `card_lint.py`（卡片保真）

```
python3 scripts/card_lint.py <src目录> [slug1,slug2,...]
```

逐 slug 校验存在性与相似度（≥0.55）。**改 CONFIG / 文案在容忍内，改运动就掉下去** —— 0.55 这个阈值就是给蒙皮留的余量。

### 5.12 `beat_gap_check.py`（空台预检）

| 参数 | 默认 | 含义 |
|---|---|---|
| `beats` / `shots` | 必填 | 节拍表 / 镜头表 |
| `--gap` | `2.0` | 空窗阈值（秒） |
| `--ok` | `""` | 声明有持续运动、可跳过的镜号（逗号分隔） |

### 7.4 渲染 / 验收阶段

| 症状 | 原因 | 处理 |
|---|---|---|
| 画面闸报静止 FAIL | 该窗没有可见运动 | **先读闸怎么量的**：`freezedetect n=0.003 d=0.8`，逐帧平均像素差 >0.3% 才算动。平滑渐变 / 漂背景 / 纯透明度呼吸都不产生像素变化，**只有相机缩放才改每个像素** → 加 CameraRig 推拉 |
| 抖动闸 FAIL | 先查重复帧签名 | 人物区周期性近零差 = 素材帧率病（处方在 preflight，`--concurrency=1` 治不了），再查并发光栅 |
| 音效全被掩蔽 | 句间气口太短 + 电平上限 | **有些是"输入决定、不是本片可修"** —— 气口 <0.3s 且音效上限 −22dB 时 UNMASKED 数学上不可达，这种结论要早下，别硬调 |
| 音画错位 | 违反三条硬纪律之一 | 音轨整条不分段 / 段边界取整同规则 / 帧数断言 |
| 音轨缓存没复用 | 指纹变了 | 改的是 `beats.json` / `cues.json` / `src/sfx.ts` / `timing.json` → 重渲；若是音量常量写在组件里，用 `--force-audio` |
| beat_lint 词落点超差 | 手敲了近似秒数 | 从 timing.json / `atChar()` 查真值 |
| 镜尾动效被吞 | 落点距出点 <0.7s | 提前或挪进下一镜（机器闸查 ≥0.5s） |
| 评审自证闭环 | 用 fork 出来的评审 | **必须派全新上下文的 subagent**，禁止 fork 制作对话 |

## 8. 深入：本次安装踩到的两个真坑

### 8.1 WorkBuddy 沙箱 broker 打断 npm ci

**症状**：`Cannot find module '@rspack/core'` → 检查发现 97 个包目录存在但缺 `package.json`。

**根因**（不是磁盘、不是网络）：
- `broker-ipc-client.cjs:17` — `MAX_QUEUED_REQUESTS = 8192`
- `node-brokered-fs-shim.cjs` 通过 `NODE_OPTIONS` 预加载，把**每一次** fs 读写都转发给 broker
- npm 解包上万个文件必然突破 8192 上限，剩余请求被丢弃 → 目录存在但内容缺失

**换新 broker 会话无效** —— 上限对任何单次 `npm ci` 都成立。

**解法**：执行 npm 前清掉 `NODE_OPTIONS`（一次性移除 safe-delete + brokered-fs 两个 hook），Node 改用原生 fs。

```bash
env -u NODE_OPTIONS npm ci --no-audit --no-fund
```

安装时间从 11 分钟无果 → **27 秒完成，零 broker 错误**。

> **后续在这个目录跑 npm 操作（尤其官方 `check-runtime.sh --upgrade`）都沿用这招**，否则会再次触发 8192 上限。

### 8.2 磁盘空间不足导致静默截断

第一次安装时磁盘只剩 7GB，npm 在解包过程中被截断，**没有报错**，只是留下残包。

**教训**：装之前先 `df -h /System/Volumes/Data`，**至少留 2.5GB**。装完立刻跑完整性校验：

```bash
cd ~/.workbuddy/skills/video-talkcraft/runtime && node -e "
const fs=require('fs');const l=require('./package-lock.json');
let miss=[];
for(const k of Object.keys(l.packages)){
  if(!k.startsWith('node_modules/'))continue;
  if(!fs.existsSync(k+'/package.json'))miss.push(k.replace('node_modules/',''));
}
console.log('缺失数:',miss.length);
console.log(miss.filter(x=>x.includes('darwin')).join('\n'));  // 只看本机平台
"
```

**只统计 darwin 平台**：其他平台的 optional 依赖（win32/linux 等二进制）被 npm 主动跳过是**正常**的。

## 10. 首次上手建议路径

给第一次用的哥哥一条最短路径：

1. **今天**：装依赖 + 跑 `check-runtime.sh` 看到 `[runtime] OK`（本指南 2.x）
2. **第一支片**：做 **90 秒 / 13 句**的短片，别碰长音频
3. **口播稿**：数字全写汉字，第一句放个钩子
4. **配音**：用手上的成品录音，或让 Fish Audio 出
5. **预剪 → 时间戳 → 语义标注**：严格按顺序，`match < 0.9` 的句子人耳听一遍
6. **SHOTBOOK**：先写 2–3 镜的小表试水，`preflight` 过了再扩
7. **实现**：只做样板镜 → 渲单镜预览 → 确认 → 做其余
8. **验收**：机器闸全过 → 独立 subagent 审片 → 修 P0/P1 → 交付

**最容易翻车的三个点**（提前知道能省很多时间）：

| 坑 | 后果 | 防线 |
|---|---|---|
| 稿子里数字没写汉字 | 整句锚点丢失 | 写稿时就用汉字 |
| 漏跑 `--sync-shots` | 覆盖闸全部空转 | ④ 写完立刻回填 |
| 手写"神似"卡片 | 回弹/密度/取景框全丢 | 从 `template/cards/` 复制改 CONFIG |
