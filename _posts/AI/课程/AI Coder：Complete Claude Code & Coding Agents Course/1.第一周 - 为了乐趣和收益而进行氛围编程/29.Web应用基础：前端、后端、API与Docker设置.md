# 总结
这段内容是*对课程受众的定位*以及*一些基础概念的快速讲解*，为后续构建项目做准备。主要包含以下几个方面：

## 受众说明  
   课程学员中既有想深入*学习 agentic 工程*的技术人员，也有非技术背景、希望借助 vibe coding 生成代码的新手。本次先*针对新手做基础铺垫，老手可快进跳过*。

## 前端与后端的概念  
   - **前端**：*运行在浏览器中*，由 HTML、CSS 和 JavaScript 组成，**负责页面展示和交互**。  
   - **后端**：*运行在服务器上*，**处理业务逻辑、访问数据库、调用 LLM、存放密钥（如 .env 文件）等**。  
   - 两者通过 **API** 连接：*前端发起 API 请求，后端返回数据或处理结果*。

## 本周项目技术栈变化  
   - 第 1 天和第 3 天：纯前端。  
   - 昨天：有后端，但也是 JavaScript。  
   - 今天：前端用 JavaScript，后端用 **Python**（*这是 LLM 相关开发最常用的后端语言*）。

## 前端框架简介  
   - 从基础 HTML/CSS/JS 到 jQuery 等库，再到 React、Vue、Angular、Svelte 等框架。  
   - `单页应用（SPA）`很常见，整个前端加载一次，各组件通过 API 更新。  
   - `Next.js`（Vercel 出品）是*更高层的框架*，*集成了路由、数据获取、客户端/服务端渲染等*。  
   - 作者不擅长 React/Next.js，但 LLM 和编码代理非常擅长生成这类代码，是救命稻草。

## LLM 生成前端的局限与人工价值  
   LLM 生成的网站往往千篇一律，看起来像“slop”。*UX/UI 人员的价值在于优化信息组织和用户体验*，让产品独特且有效。*因此即使 LLM 能生成不错的前端，仍需人工介入打磨*。

## Docker 简介  
   - `Docker` *相当于“电脑中的电脑”，提供隔离、安全的运行环境*，类似轻量级虚拟机。  
   - **优点**：*隔离保护宿主系统，且可移植性强，一次构建多处运行*。  
   - 三个核心概念：  
     - `Dockerfile`：*构建镜像的配方/指令文件*。  
     - `Image（镜像）`：*由 Dockerfile 构建出的快照/蓝图*。  
     - `Container（容器）`：*根据镜像创建的运行中实例*，一个镜像可启动多个容器。  
   - 此外还有 `Volumes` 等概念，用于*持久化存储*。

## 安装 Docker Desktop  
   - 访问 docker.com，下载 Docker Desktop。  
   - 接受默认设置，PC 上建议使用 WSL。  
   - 可能需要重启电脑以更新环境变量。  
   - 安装后打开 Docker Desktop，可在左侧看到 Containers、Images 等板块。
