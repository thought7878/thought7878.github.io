## 一、避免被“智能体编程”的炒作冲昏头脑

- 作者虽然非常看好 LLM 对软件开发的推动作用，但也承认目前存在一些不合理的炒作。
- **LLM 的加速效果因任务类型差异很大：**
  - ***样板代码类任务**（如 React 前端、CRUD 后端、原型项目）**提升巨大***，可能从几天缩短到几分钟，达到数量级提升。
  - ***高度创新、大型代码库、复杂项目**中，提升往往只是渐进式的，有时甚至因为需要排查 LLM 产生的细微错误而**变慢***。
- *总体来看，LLM 对作者来说是效率倍增器，但**并不是 10 倍**的提升*。
- 我们应当***客观看待***：既不盲目追捧，也不因负面经历而走向反 AI 的极端，而是*要学习、使用这些工具，并如实说明其优缺点*。

  - **Claude Opus 4.5**：作者的首选，尤其配合 Claude Code 使用时编码效率很高。
  - **GPT-5.2 Codex**：更偏向编码的变体。
  - **Gemini 3 Pro**：谷歌最新最强模型之一。
- **2025 年 11 月**是一个重要拐点，模型在可信任度和智能体编码能力上有明显跃升，但一些人还停留在旧印象中。
- 值得关注的开源模型：**GLM-4.7**（来自中国 AI 初创公司智谱 Z.ai），在工具使用方面表现非常突出。
- 网站还提供前沿模型智能随时间变化的图表，作者预测未来仍有提升，但不会一直急剧上升。
