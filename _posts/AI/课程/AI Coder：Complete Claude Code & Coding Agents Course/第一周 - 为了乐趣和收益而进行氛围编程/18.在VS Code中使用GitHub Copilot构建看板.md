# 总结
这段内容主要演示了*从 Cursor 切换到 GitHub Copilot*，并*使用 Copilot 在 VS Code 中重新构建看板项目*的过程，重点包括*环境准备、构建流程、遇到问题、调试方法*。

**1. 项目目录整理**
- 回到 Cursor 的 Instant 项目，退出 Kanban 项目。
- 用 `mv` 命令将之前构建的 `kanban` 目录重命名为 `cursor_kanban`，保留旧成果。
- 重新 `git clone` 同一个仓库，得到一份全新的 `kanban` 目录，只包含 `agents.md` 文件，供 Copilot 使用。

**2. 认识 GitHub Copilot**
- Copilot 是 GitHub 推出的热门 AI 编码助手，有免费层，每月提供一定请求数。
- 主要通过 VS Code 使用（Cursor 本身也是 VS Code 的衍生版本，界面相似）。
- 第一步安装 VS Code，然后在扩展市场搜索并安装 “GitHub Copilot” 插件。

**3. 在 VS Code 中准备项目**
- 打开新窗口，打开克隆好的 `kanban` 项目。
- 登录 GitHub 账号（左下角头像）。
- 使用快捷键（Mac: Command+Shift+I / PC: Ctrl+Shift+I）打开 Chat 面板，里面包含模型选择、计划模式等熟悉功能。
- 可在面板中查看 Copilot 使用量。

**4. 使用 Copilot 构建看板**
- 将 Agent 设置为计划模式，输入“please plan the task at hand”，Copilot 自动读取 `agents.md` 并生成计划。
- 点击 “Start implementation” 开始实现，期间需允许终端命令执行，类似 Cursor 的 YOLO 模式。
- 构建过程中出现一些波折：一开始目录错误、多次修复，最后卡住以为服务器没启动。

**5. 测试与问题发现**
- 手动运行 `npm run dev` 后，看板页面正常打开，界面和拖拽功能不错，没有报错。
- 但发现“删除卡片”功能失效。
- 第一次反馈后，Copilot 声称已修复，但实际并没有解决问题，它只是猜测并声称成功。

**6. 调试的正确方法**
- 作者强调：*不要轻信 Agent 自称已修复，必须要求它“复现问题 → 证明根因 → 修复 → 证明已修复”*。
- 第二次给出明确指令后，Copilot 成功修复删除功能。
- 这是一个重要教训：作为主导者，要推动 Agent 采用严谨的调试流程。
