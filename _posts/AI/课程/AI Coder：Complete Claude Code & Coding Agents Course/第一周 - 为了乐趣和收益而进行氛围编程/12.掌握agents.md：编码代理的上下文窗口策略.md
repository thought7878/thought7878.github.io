
# 总结

## 什么是 `agents.md`
   - 这是一个 *Markdown 格式* 的文件（扩展名 `.md`），用于**向编码代理（如 Cursor、Codeium、GitHub Copilot 等）提供*项目信息和指令***。
   - Markdown 是一种*轻量级标记语言*，用 `#` 表示标题层级（`#` H1，`##` H2，`##` H3），支持列表等简单格式，易于阅读和编写，*LLM 非常擅长处理这种格式*。

## `agents.md` 的位置与层次结构
   - *根目录下*的 `agents.md` ***始终** 被包含在上下文中*。
   - *子目录中*的 `agents.md` *仅当代理处理**该子目录**或**其子目录下的**文件时才会被读取*。
   - 代理会*从当前目录**向上回溯**，收集所有相关的 `agents.md`，内层文件中的规则会**覆盖**外层文件中的规则*，允许**针对子项目进行精细化设置**。

## 编写优秀 `agents.md` 的关键原则
   - **简洁精炼**：上下文窗口*空间有限*，每个词都要有信息量，避免冗长。
   - **具体明确**：给出*项目目标、成功标准、编码规范*，可包含*检查清单*和*链接到其他文档*。
   - **正面指令为主**：*LLM 更擅长记住“该做什么”而非“不该做什么”*，因此尽量*多用肯定句，少用否定句*（如“避免...”）。
   - **避免常见陷阱**：例如，不要让代理*过度注释、生成冗长的 README（尤其不要用 emoji）*。
   - **明确指定工具使用方式**：例如 Python 环境下推荐 `uv run` 而非 `python3`，并强调“简单为佳”。

## 两种思维模式的演变
   - **2025 年主流（精细控制）**：认为成功关键在于*投入大量精力反复打磨* `agents.md`，不断补充规划文件、测试标准，频繁重写、修剪、重置上下文，以最大化代理效能。
   - **2026 年新兴思维（放手策略）**：主张*放松控制，聚焦最终目标*，让代理*利用技能、循环、子代理和多代理群自主修正和完成任务*，更接近 **“放养”方式**。
   - **讲者个人立场**：目前仍倾向于 2025 年的精细控制方法，认为*它对输出质量影响巨大，尤其是大型项目*；但对于小型玩具项目（如昨天做的第一人称射击游戏）则可以放手。同时他也承认，具体选择取决于项目类型和场景，且*未来趋势会越来越多人接受“放手”策略*。


**一句话总结**：`agents.md` 是*代理编码的核心配置文件，其编写需简洁、正面、具体，并可分层级放置；当前存在“精细控制”与“放手自主”两种思路，前者仍是主流，但后者正逐渐兴起*。
