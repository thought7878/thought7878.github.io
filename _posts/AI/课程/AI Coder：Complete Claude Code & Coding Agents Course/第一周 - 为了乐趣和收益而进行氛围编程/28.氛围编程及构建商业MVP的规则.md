# 总结
这段内容是一堂*关于“vibe coding”课程的开场与核心要点回顾*，主要内容如下：

## 课程目标  
   今天要**遵循规则**，用 vibe coding *构建一个可商业化的 MVP*，而*不是像昨天那样随意“YOLO”、不关注过程*。

## 对 Andrej Karpathy 系列推文的梳理  
   - 提出“vibe coding”概念：完全跟随感觉、拥抱指数级进步、甚至忘记代码存在，因为 LLM 已经足够强。  
   - **工作流转变**：*从过去 80% 手动补全 + 20% 代理，变为现在 80% 代理 + 20% 修改润色*。  
   - 对“不再需要 IDE”、“agent swarm”等炒作持谨慎态度，认为*模型会犯错，重要的代码必须像鹰一样盯着*。  
   - 代理非常坚韧，不知疲倦、不会气馁。  
   - *生产力提升很难用“10x”或“2x”衡量，更多是产出范围的扩展，而不是单纯速度提升*。  
   - 编码乐趣出现分化：*有人喜欢写代码，有人喜欢构建产品；代理承担了苦差事，让构建者更享受*。  
   - **风险**：*技能萎缩*——自己可能逐渐失去写代码的敏锐度。  
   - 对“LLM slop”泛滥的担忧，并预测 2026 年会出现对低质量代码的抵制。

## 成功 vibe coding 的规则  
   - *做“老板”（掌控全局），维护好 AGENTS.md* 或类似文件。  
   - *简洁说明规格、风格、成功标准*。  
   - *从简单开始，增量开发，持续测试和验证*。  
   - 不要偷懒，要挑战、要求证据，像鹰一样盯着过程。  
   - 遇到挫折时，退一步换种方式解决（如，第一次有问题，提示修改第二、三次还有问题，*代码回滚重新开始*）。

## 对不同人群的建议  
   - **初级工程师**：像非技术管理者一样，*通过提问、要求解释、保持怀疑来学习和监督代理*。  
   - **高级工程师**：*转向“少编码、多构建”，利用自己的专业经验去监督和挑战，找到新的工作乐趣*。

## 总体态度  
   保持健康、平衡的心态，期待混合结果，*不要被“10x”或“完全自动构建产品”的炒作迷惑；增量、现实地推进，才能真正享受这个过程*。
