# 总结
这段内容主要演示了*使用 OpenAI 的 Codex 作为 VS Code 扩展来重新构建看板项目*的过程，并*与之前的 Cursor、GitHub Copilot 进行对比*。

**1. 项目目录准备**  
- 退出 VS Code 后回到 Cursor 的 Instant 项目，进入上级 `projects` 目录。  
- 将 Copilot 生成的 `kanban` 文件夹重命名为 `Copilot_kanban` 作为存档。  
- 再次 `git clone` 同一仓库，得到全新的 `kanban` 文件夹，里面只有 `agents.md`。

**2. 安装 Codex 扩展**  
- Codex 本身主要是 CLI 工具，但也提供 VS Code 扩展。  
- 在 VS Code 扩展市场搜索 “Codex”，安装 OpenAI 官方的 Codex 扩展。  
- 安装后左侧会出现 Codex 图标，点击即可打开 Codex 面板。

**3. 配置 Codex**  
- 需要登录 OpenAI 账号（通常需要 ChatGPT 订阅计划）。  
- 可选择 Agent 模式：将 “Agent” 改为 “Agent full access”，类似 YOLO 模式。  
- 选择模型（作者使用 GPT-5.2 Codex），并可设置推理强度（reasoning effort），作者选择 “high”。  
- Codex 没有单独的计划模式，但会读取 `agents.md` 并先进行规划。

**4. 构建过程与结果**  
- 在 Kanban 项目中输入 “Please go ahead”，Codex 自动读取 `agents.md` 并开始工作。  
- 构建持续约 15 分钟，上下文窗口使用 16%（42,000/258,000 tokens）。  
- 完成后报告显示服务器已运行，共修改 74 个文件。

**5. 功能验证**  
- 打开 localhost:3000，界面美观，应用名为 “Kanban Studio”，宣传语为 “1 board, 5 columns, 0 clutter”。  
- 测试拖拽、重新排序、删除卡片、重命名列，全部正常工作。  
- 作者认为*这是目前三个工具中效果最好的*，且是“零样本”（zero-shot）构建：只给指令，没有额外反馈或提问。

**6. 重要反思**  
- 作者坦诚自己并不擅长写前端代码，但依然能通过 Codex 构建出漂亮的应用。  
- 强调*即使不懂技术细节，也可以像管理者一样通过反馈来协作*。
