# 总结
这段内容主要围绕“*成功进行 vibe coding 的五大原则*”展开，并*针对不同背景的工程师给出建议*，最后分享了*对 AI 编码工具生产力提升的平衡*看法。

**1. *五大核心原则*（Be the boss）**  
- **写好 agents.md**：*内容要简洁，明确三件事——要做什么、用什么风格做、怎样才算成功*。  
- **项目起步要简单**：*先构建最基础的 MVP，测试通过后再逐步增加复杂度，避免一开始就过于复杂导致失控*。  
- **增量式工作**：*每一步都进行测试和验证，确保每个里程碑都成功，出错时能及时回头*。  
- **不要偷懒**：即使之前成功过，也*不能盲目信任模型*。在调试时，如果模型声称已修复问题，一定要它提供证据，确认根因、修复和测试结果。  
- **管理挫折**：模型会反复犯错，这是它的局限。要学会检测、应对这些局限，把处理挫折当作过程的一部分。

**2. 对 YOLO 模式的态度**  
- 作者并不特别推崇 YOLO，即使使用 YOLO 也要保持怀疑，*做到“信任但验证”*，回来后仔细检查所有内容。

**3. 给不同背景工程师的建议**  
- **初级工程师**：把使用 AI 当作学习机会，主动提问、理解原理，不要只让模型代劳；保持健康怀疑，即使模型很自信也要验证。  
- **高级工程师**：这类工具最适合有经验的人，因为能辨别模型是否在胡编。要看到它带来的新能力，比如快速构建前端、写 DevOps 脚本，从而享受更高效构建的乐趣。

**4. 对生产力提升的平衡看法**  
- **有时是革命性的**：例如构建一个 Next.js 看板，几分钟就能完成原本需要数天的工作。  
- **有时只是增量提升**：大型遗留项目、复杂后端改动时，提升有限。  
- **有时反而降低效率**：如果涉及训练数据中没有的新技术，模型可能反复出错，反而比手写更慢。  
- **总体结论**：使用顶级编码智能体总体是正面的、有价值的，但提升倍数取决于任务类型、个人技能、项目规模等因素；小型绿地项目 MVP 提升最显著，其他情况多为速度改善而非 10 倍神话。
