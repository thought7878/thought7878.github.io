---

### 1. 发起全面代码审查
- 作者先提交了 `Claude.md` 文件，然后**让 Claude Code 对整个仓库做一次彻底的代码审查，并将结果写入 `docs/code-review.md`**。
- Claude Code *并行运行了三个代理：* 后端代码质量、前端、基础设施与配置。

### 2. 发现一个典型的 LLM 幻觉错误
- 审查报告中*最严重的两个问题*都声称：**OpenAI API 密钥暴露在 Git 中，需要轮换并移除 `.env` 文件**。
- 但作者指出这是**完全错误的**：`.env` 早已加入 `.gitignore`，从未被 Git 跟踪。
- 这展示了 LLM 会**非常自信地输出错误结论**，因此*所有 AI 生成的结果都必须经过人工核实*。
- Claude 后来承认错误并修正了报告，还试图把责任推给“探索代理”，作者认为这很讽刺。

### 3. 审查发现的其他真实问题
- 后端依赖未锁定版本（未使用 `uv`，没有 lock 文件）。
- 测试可能只跑了单元测试，未跑集成测试。
- Playwright 被硬编码为仅在 Mac 上运行。
- 存在 SQL 注入风险和缺少输入验证。
- **`main.py` 是一个巨大的单体文件，难以维护和测试**（作者最希望修复的问题）。
- 其他小问题：前端可访问性缺失、缺少健康检查、Docker 以 root 运行、缺少文档字符串等。

### 4. 让 Claude 修复问题
- 作者要求它修复所有**严重、高、中优先级**的问题。
- 大约 5 分钟内完成，所有测试通过。
- 但 Claude **自主决定推迟重构 `main.py`单体文件**，因为它认为改动成本大于收益——它没有盲目服从指令。
- 作者坚持要求重构，Claude 随后将 `main.py` 拆分为多个模块（config、models、database、AI 依赖、routes 等），结构清晰。
- *重构后所有前后端测试通过，文档也自动更新*。

### 5. 上下文管理与状态查看
- 完成大量工作后，上下文已满。作者手动*执行了 `/compact`，压缩对话历史，保留摘要，避免在任务中途自动压缩*。
- 压缩后上下文干净，但*可能丢失部分信息，因此建议更新 `Claude.md` 确保关键信息常驻*。
- 最后用 **`/status`** 查看了版本、配置和用量（使用了 7% 日配额、2% 周配额，模型为 Opus 4.5）。
