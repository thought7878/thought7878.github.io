# 总结
这段内容演示了在 VS Code 中首次使用 Claude Code CLI 的完整操作流程，并穿插了关键概念和注意事项。

**1. 启动与准备**  
- 打开上周的 PM 项目，先提交未保存的更改（`git add .` + `git commit -m "Part 10 complete"`）。  
- 在 VS Code 新终端中输入 `claude` 启动 Claude Code CLI，界面是复古的命令行风格，交互原始直接。  
- 首次使用需执行 `/login`，通过浏览器登录 Anthropic 账号。

**2. 项目初始化与 `Claude.md`**  
- Claude Code 使用 `Claude.md`（而非上周的 `agents.md`）作为项目记忆文件。  
- 可以手动编写，也可运行 `/init` 让 Claude 自动分析目录并生成。  
- 演示中 Claude 读取了已有的 `agents.md`，创建了包含项目概览、命令和开发指南的 `Claude.md`。  
- 作者提醒：通常建议自己写 `Claude.md`，因为这是人类监督者最需要掌控的部分；自动生成可作为初稿再修改。

**3. 编辑确认机制**  
- Claude Code 在每次编辑前会询问：`1` 确认本次编辑，`2` 确认并允许本次会话所有编辑（Shift+Tab 快捷键），`3` 拒绝。  
- 还可以按 Tab 追加评论，如“可以，但请考虑……”。

**4. 上下文管理（`/context`）**  
- `/context` 命令可视化当前上下文窗口（200k tokens）的使用情况。  
- 分为 memory（含 `Claude.md`）、messages（对话消息）、free（剩余空间）和 buffer（用于压缩/compaction 的缓冲）。  
- 强调要时刻关注上下文消耗，Anthropic 有意让用户精细管理上下文以保持模型智能。

**5. 执行测试与自动处理**  
- 让 Claude 读取 `plan.md` 等文档以确保理解项目。  
- 要求 Claude 运行全部测试，自动启动和关闭服务器。  
- 遇到 Docker 未运行时，Claude Opus 模型能自动启动 Docker Desktop（Sonnet 做不到），展示出更强能力。  
- 测试全部通过，仅有两个弃用警告，最后再次用 `/context` 查看上下文增长情况。

**核心要点**：使用 Claude Code 的关键是掌握 `/login`、`/init`、`/context` 等命令，理解编辑确认流程，并主动管理上下文窗口；项目记忆文件 `Claude.md` 最好由人工编写或严格审核。
