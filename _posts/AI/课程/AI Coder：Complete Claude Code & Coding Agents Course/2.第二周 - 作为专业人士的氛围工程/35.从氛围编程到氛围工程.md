# 总结
这段内容主要*介绍第2周课程的核心主题：* **从“`氛围编码`”（vibe coding）迈向“`氛围工程`”（vibe engineering）**，并引入 Claude Code 作为主要工具。

## 第2周定位与工具  
- 第2周是“专业周”，今天是“平台/产品日”，*核心是介绍 Claude Code*。  
- *后续两周将重点使用 Claude Code*，同时也会了解 OpenCode 等其他工具。  
- 对应 Steve Yegge 的 **AI 编码八阶段：** *第1周做前四阶段，第2周重点攻克第5阶段，第6-8阶段（多智能体编排等）留到第3周*。
参考：[[7.AI编码的8个阶段]]

## 心态转变：从 vibe coding 到 vibe engineering  
- 第1周是 `vibe coding`： **快速、松散、以提示词驱动，不太关注代码质量**。  
- 第2周引入 Simon Willison 提出的 “`vibe engineering`”： **专业工程师利用 LLM 加速工作，同时保持对产出代码的完全负责**。  
- 核心理念：**可以借助 AI 扩展能力，但最终质量责任在人，必须验证代码确实有效且优秀**。

## Simon Willison 博客中的关键观点  
- *使用 LLM 并不简单，有很多陷阱，但其产出速度惊人*。  
- Claude Code、Codex CLI、Gemini CLI 等编码代理*能迭代、测试、修改代码直到达成目标，极大提升了 LLM 的实用性*。  
- **有经验的工程师**开始*并行运行多个代理处理多个项目，这有效但精神消耗大*。  
- **好的流程**会得到回报：*自动化测试、提前规划、完善的文档、良好的版本控制习惯*（如 Claude Code 内置检查点）。  
- 需要**建立代码审查文化**，让 LLM 审查它自己的工作。  
- 需要*良好的手动 QA、强大的研究能力、知道何时换一种方法解决问题*。  
- **需要培养判断力：** 哪些工作可以外包给 AI（如前端），哪些不能（如复杂后端，容易产出混乱代码）。  
- *项目估算方式变了：* AI 能快速生成大量代码，给人虚假的乐观，但随后可能遇到难以突破的瓶颈，因此估算时要考虑这些风险，不要盲目相信“10倍效率”的炒作。

## 总结与建议  
- ***如果要真正发挥这些能力，必须做到：*** **设计明确的成功标准、设计代理循环、规划 QA、管理一群“会偷懒的数字实习生”（指 LLM 代理）、并花大量时间做代码审查**。  
- 强烈推荐阅读 Simon Willison 的完整博客文章，链接在资源中，内容非常有价值。
