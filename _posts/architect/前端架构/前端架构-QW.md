>前端架构，应该怎么学？

后端架构有几十年的经典著作打底，而"前端架构"常被误解为"选框架 + 配打包器"。学它的第一步，不是扎进某个框架，而是**先看清它的版图**。

---

## 〇、先画地图：前端架构到底管什么？

把它拆成四层，学习就是逐层攻克：

| 层次       | 回答的核心问题      | 典型议题                       |
| -------- | ------------ | -------------------------- |
| **代码架构** | 一个功能内部怎么组织？  | 组件设计、状态管理、分层、依赖方向          |
| **应用架构** | 一个应用怎么拆分与运行？ | CSR/SSR/RSC、微前端、BFF、路由设计   |
| **工程架构** | 多人多项目怎么协作？   | Monorepo、构建工具、CI/CD、规范与脚手架 |
| **质量架构** | 怎么保证系统不烂掉？   | 测试金字塔、性能预算、监控、灰度发布         |

---

## 一、分阶段学习路线

### 阶段 0 · 地基（绕不过去）
- **JavaScript / TypeScript 到语言级理解**：原型、闭包、事件循环、类型系统的思想（而不只是会写 `interface`）
- **浏览器原理**：渲染流水线、缓存策略、CORS/CSP 安全模型
- **设计模式与 SOLID**：这是所有架构讨论的"词汇表"

> ✅ 检验标准：能向别人讲清楚"React 为什么要求数据不可变"这类 *为什么* 的问题。

### 阶段 1 · 组件与状态（单兵能力）
- **组件设计原则**：单一职责、受控/非受控、组合优于配置、headless 组件思想
- **状态分类思维**——这是现代前端最重要的架构认知之一：
  - 服务端状态 → TanStack Query / SWR（缓存、失效、重试）
  - 客户端状态 → zustand / jotai / Pinia / signals
  - URL 状态 → 路由参数（能被分享的状态就该放进 URL）
  - 表单状态 → 专门的表单库
- **逻辑复用**：hooks / composables / HOC 各自的适用边界
- 🔨 实践：把一个 500 行的"上帝组件"拆成 10 个职责单一的组件

### 阶段 2 · 应用架构（一个应用的骨架）
- **渲染模式选型**：CSR / SSR / SSG / ISR / RSC / Islands——重点不是背概念，而是问"各自的代价是什么"
- **前端分层**：UI 层 → 领域层 → 数据层，**依赖方向永远向内**（Clean Architecture 在前端的落地）
- **路由即架构**：路由怎么切，往往决定了代码怎么拆、团队怎么分
- **微前端**：搞清楚它解决的是*组织问题*（多团队、异构技术、遗留系统），而不是技术问题——小团队用它是灾难
- **BFF**：前端是否需要自己的后端聚合层

### 阶段 3 · 工程架构（一个团队的秩序）
- **构建原理**：Vite / Rspack / Rolldown 背后的 ESM、tree-shaking、HMR 机制
- **Monorepo**：pnpm workspace + Turborepo/Nx——依赖图、任务编排、版本策略
- **质量门禁**：把 ESLint、类型检查、测试卡进 CI，而不是靠自觉
- **脚手架与设计系统**：把架构"固化"成工具——**正确的路，要成为最容易走的路**

### 阶段 4 · 质量与演进（让系统活得久）
- **测试金字塔**：单元（Vitest）→ 集成（Testing Library）→ E2E（Playwright）
- **性能预算**：Core Web Vitals、首屏、包体积治理，且要能进 CI 自动卡控
- **可观测性**：错误上报、用户行为、灰度发布
- **演进式改造**：用"绞杀者模式"逐步替换遗留系统，而不是推倒重写

## 二、四个真正有效的学习方法

1. **带着问题读源码**——React 的 Fiber 解决什么问题？Vue 为什么用 Proxy 做响应式？Vite 的 HMR 怎么实现？源码是最高密度的架构教材。
2. **造迷你轮子**——手写 mini-vue / mini-vite / mini-redux，100 行代码胜过读 10 篇文章。
3. **给每个决策写 ADR**——一页纸：背景、备选方案、权衡、结论。架构能力本质上是*决策能力*，写作会逼你把权衡想清楚。
4. **主动找"烂摊子"**——重构一个真实项目，比看十本书都管用。架构的痛感，只有在改不动代码时才学得会。

## 三、资源清单

- **书**：《架构整洁之道》《重构》《JavaScript 设计模式与开发实践》（曾探）——前两个是通用架构思维，最后一个是前端视角的经典
- **站**：patterns.dev（架构模式的可视化词典）、web.dev（性能与质量）
- **源码**：Vue 3（响应式/编译器）、React（调度）、Vite（工程化）、TanStack Query（服务端状态）
- **博客**：各大厂技术团队关于中台、微前端、Monorepo 落地的实战复盘——看他们*踩了什么坑*，比看他们*用了什么*更有价值

---

## 四、三个常见误区

- ❌ **把"用了什么框架"当成架构**——架构是决策与权衡，不是技术名词清单。
- ❌ **过度设计**——3 个人的项目上微前端，就像给自行车装变速箱。
- ❌ **只追新，不看旧**——新框架的卖点，常常是老问题的新包装。抓住不变的东西：组件化、状态管理、分层、依赖方向。

---

> **一句话总结**：前端架构不是学出来的，是*决策*出来的。从下一个功能开始，每写一行代码都问自己：这个依赖方向对吗？这个状态该放哪？三年后这段代码还能改得动吗？——问得多了，架构就在你手里了。
