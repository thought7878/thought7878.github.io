# 原文

Once new features or bug fixes have been merged into the main branch of your code base, the next step is deploying the changes to your customers. This is where development transitions into real world value, bringing new updates, features, and improvements to the customers. 

*当新功能或缺陷修复已合并到代码库的主分支后，下一步就是将这些变更部署给您的用户*。这正是开发迈向实际价值的关键阶段，为客户带来全新的更新、功能与优化。

A deployment pipeline takes code from development to production where your customers interact with it. This process is usually automated to ensure consistency and efficiency, but it must be carefully designed to prevent issues that could disrupt the user experience. A typical deployment pipeline consists of four main steps. Build, test, deploy to staging, and deploy to production. 

部署流水线会将代码从开发环境逐步推进至生产环境，最终供您的客户使用。此过程通常是自动化的，以**确保一致性和效率**，但必须仔细设计，以防止可能会干扰用户体验的问题。一个典型的部署管道由四个主要步骤组成：**构建、测试、部署至预发布环境、部署至生产环境**。

In the build phase, the code is compiled or package into a deployable format, such as a Docker image or executable file. This involves bundling files and ensuring all the dependencies are included so the application is ready to run. Once the code is packaged, the next step is testing. Automated tests are run to verify that new code doesn't introduce bugs or disrupt existing functionality. After successful testing, the code is deployed to a staging environment. Staging is a replica of the production environment where new code is tested in a live like scenario. This step helps identify any potential issues that might have not been caught during testing and ensures that the application behaves as intended before reaching end users. 
在`构建阶段`，**代码会被编译或打包成可部署的格式**，例如*Docker镜像或可执行文件*。这涉及*将文件打包，并确保所有依赖项都已包含在内，从而使应用程序能够直接运行*。
代码打包完成后，下一步就是`测试`，**会运行自动化测试，以确保新代码不会引入缺陷或破坏现有功能**。
测试通过后，代码将`部署至预发布环境`，预发布(预演)环境**是生产环境的副本，用于在接近实际运行的场景中测试新代码**，此步骤**有助于发现测试阶段可能未被识别的潜在问题**，并确保应用在面向最终用户之前能够按预期正常运行。

Finally, once everything is validated in staging, the code is deployed to the production environment. We often call this process a deployment. The production environment is where your customers interact with the new updates, features, and improvements. The deployment to production must be carefully managed to avoid downtime or disruptions to the user experience. To further enhance deployment reliability, techniques like blue green deployments can be used. This approach involves maintaining two production environments, one running the current version blue and one with the new code green. After validating the new code in green, traffic is switched from blue to green, minimizing downtime and reducing risk. 

最后，一旦所有内容都在测试阶段进行验证，代码就会`部署到生产环境`中。我们经常称这个过程为`部署`。
`生产环境`是您的客户与新更新、功能和改进进行交互的地方。必须仔细管理部署到生产环境，以避免停机或对用户体验造成干扰。
**为了进一步提高部署可靠性**，可以使用`蓝绿部署`等技术。*这种方法涉及维护两个生产环境，一个运行当前版本的蓝色，另一个使用新代码绿色。在验证绿色的新代码后，流量将从蓝色切换到绿色*，**从而最大限度地减少停机时间并降低风险**。

Continuous integration and continuous deployment or CICD are also key practices in this process. Ci involves automatically integrating code changes and running tests to catch issues early, while CD automates the deployment of these changes to production once they pass testing. These are often used by mature teams that have robust testing and deployment workflows. 

`持续集成与持续部署（CICD）`，也是这一过程中的关键实践。`CI`**通过自动集成代码变更并运行测试来及早发现问题**，而`CD`则**在这些变更通过测试后，自动将其部署到生产环境**。这些通常由具备完善测试与部署流程的成熟团队所使用。

By following a well defined by deployment pipeline and ensuring proper packaging, you can deliver new code effectively and reliably.

**通过遵循一条定义清晰的部署流水线并确保正确的打包流程，您可以*高效且可靠地交付新代码***。
