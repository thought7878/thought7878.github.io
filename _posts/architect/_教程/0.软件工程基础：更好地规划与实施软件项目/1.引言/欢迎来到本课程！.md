## 内容总结

这是 **Software Engineering 101** 课程的开场介绍，讲师为 Kurt Anderson。主要内容如下：

**1. 课程定位**
本课程聚焦于**团队协作开发大型复杂软件**，而非编写小型应用或脚本。目标项目是持续数周、数月乃至数年的工程。

**2. 核心理念（以建筑类比）**
讲师将软件工程比作建造房屋或摩天大楼——不能拿到材料就盲目开工，否则产出只能维持数周便会废弃。好的软件应当：
- **经过深思熟虑**（well thought out）
- **易于修改**（可适应新功能需求）
- **能够随环境演进而持续迭代**

**3. 课程涵盖内容**
- 业界日常使用的开发**框架**
- **团队管理**方法与协作流程
- 从规划到交付，完整构建复杂软件的全过程

**一句话概括：** 这是一门教你如何在团队中科学地规划、分工并构建可长期演进的大型软件的入门课程。

## 原文

Hello everyone, and welcome to Software Engineering 101. My name is Kurt Anderson, and I'm going to be the instructor for this course. I've been a software engineer for several years now, and I've learned a lot, and I'm happy to teach you some of the basics of how you can become a software engineer yourself.
Software engineering is an important field, and it's important to know how to work with a team to create complex pieces of software. That's really what this course is going to be about: working with a team in a way that allows us to split up work and create complex feature sets. We're not talking about building a small mobile application game or a little Python script that connects to services. Those can be learned really quickly and done in an afternoon. What we're talking about is multi-week, multi-month, or multi-year projects that a large team has to create.
How do we create this software? How do we plan to create this software?
Software engineering is a lot like building a house or a skyscraper. You can't just go in there with some concrete and some steel rebar and just start working away. Maybe you'd come out with something, but at the end of the day, it's not going to work in the long run. You're going to build something that lasts a couple of weeks, and then it's just going to fall by the wayside. So what we want to do is build software that is not only well thought out but can also be changed easily. It can be manipulated in the future, it can be adapted to a new feature set, and it can evolve with the world, because we're in a fast-paced world and environment. So this course is going to take us from beginning to end through the process of building a complex piece of software like that.
We're going to be going over frameworks that are used every day in the industry—frameworks that I use every day in my work. And we're going to be going over how to manage a team, and frameworks for not only the code but for the team as well. I'm really excited to jump right into all of this. So let's do that. Let's jump right in, and I'll see you in the next lesson.
