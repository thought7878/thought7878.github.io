
- 软件开发生命周期的**六个阶段是什么？**  
答：软件开发生命周期的六个阶段是`规划/需求`、`设计`、`开发`、`测试`、`部署`和`维护`。  
  
- 在软件开发的`规划阶段`必须考虑什么？  
答：在软件开发的规划阶段，必须考虑以下因素: **解决方案的用户，解决方案的总体目的，数据输入和输出，法律和法规合规性，风险识别，质量保证要求，人力和财务资源的分配，项目进度安排**。  
  
- 什么是软件需求规范 (SRS) 文档？  
答：`软件需求规范 (SRS) 文档`是一份组合收集的需求的文档，用于*清晰地记录和批准软件需求*。 它*必须得到所有干系人的理解和批准，并且开发人员也使用它来明确需求*。  
  
- 软件开发中`设计阶段`的目的是什么？  
答：软件开发中设计阶段的目的是使用从SRS中收集的需求来**开发软件架构**。 这个阶段**涉及多个团队成员共同设计架构，然后由利益相关者审查**，并可以包括原型的设计。  
  
- `开发阶段`包括什么？  
答：开发阶段涉及 **`开发人员`根据完成的设计文档开始编码过程**。 `项目规划人员`**使用设计文档来确定和分配编码任务**，这一阶段通常需要编程工具、不同的编程语言以及遵守组织标准或指南。  
  
- 在软件开发的`部署阶段`会发生什么？  
答：在部署阶段，**应用程序被发布到生产环境中并提供给用户使用**。 这可以**分阶段进行**，从用户验收测试 (UAT) 开始，一旦功能得到批准，就会发布到生产环境中。 部署可以在各种平台上进行，包括网站、移动设备、应用程序存储或公司网络上的软件分发服务器。  
  
- 软件开发中的`测试阶段`是什么？  
答：软件开发中的测试阶段包括*彻底测试已完成的代码，以确保其稳定、安全并满足SRS中列出的要求*。 测试可以是*手动、自动化或两者兼而有之*，任何产品错误都会被报告、跟踪、修复和重新测试，直到软件稳定为止。  
  
- 软件开发中`维护阶段`的目的是什么？  
答：软件开发中维护阶段的目的是*收集利益相关者的反馈，确定可能未在SRS中列出的任何剩余bug、用户界面问题或其他要求*。 在这个阶段也可以确定增强措施。 如果**发现并修复了错误**，或者**发现了新的需求**，它们可能会被纳入未来的软件版本中，有可能重新开始开发过程。

# 原文

Welcome to the phases of the software development lifecycle. After watching this video, you will be able to name the phases involved in the Sdlc, describe each phase, and identify several tasks associated with each phase. 
欢迎来到软件开发生命周期的各个阶段。观看本视频后，您将**能够列出软件开发生命周期的各个阶段、阐述各阶段的主要内容，并识别与每个阶段相关的若干任务**。

There are generally six phases in the Sdlc process, `planning`, `design`, `development`, `testing`, `deployment`, and `maintenance`. Each phase is discrete, meaning that tasks from a previous phase do not overlap with tasks in the next phase. The original Sdlc was conceived as a traditional waterfall method where the phases are linear, but have since been adapted to introduce iteration so that shifting requirements can be accommodated. Waterfall and other approaches to software development will be discussed in another video. Note that some organizations may have different names for each stage. For example, planning may be called requirements or strategy or analysis. Also, some organizations may have additional or fewer stages in the first stage of the Sdlc. 
软件开发生命周期通常包括**六个阶段**：`规划/需求`、`设计`、`开发`、`测试`、`部署`和`维护`。**每个阶段都是独立的**，*这意味着前一阶段的任务不会与下一阶段的任务发生重叠*。*最初的软件生命周期模型被设计为一种各阶段呈线性顺序的传统瀑布式方法*，但后来经过改进，**引入了迭代机制，以便适应需求的变更**。瀑布模型及其他软件开发方法将在另一期视频中进行介绍。请注意，不同组织对各阶段的称谓可能有所不同。例如，`规划`可能被称为`需求`、`战略`或`分析`。此外，一些组织在软件开发生命周期的*第一阶段可能会设置更多或更少的子阶段*。

## 规划阶段
The `planning phase` requirements are gathered, analyzed, documented, and prioritized When planning a software solution, the following factors must be considered. Users of the solution the overall purpose of the solution, data inputs and outputs, legal and regulatory compliance, risk identification, quality assurance requirements, allocation of human and financial resources, and project scheduling as part of the planning process, labor and material costs are estimated and weighed against time constraints. Also, project teams are identified and roles of each team member are proposed If stakeholders are struggling to define requirements, often the development team may produce prototypes during the planning stage to tease out those requirements. A prototype is a small scale replica of the end product used to get stakeholder feedback and establish requirements. A prototype is used to test basic design ideas, Though prototyping usually occurs during the planning stage, prototyping can occur at various phases of the Sdlc whenever requirements need to be reconsidered as the project develops. After requirements have been gathered, they are combined into a document called a Software Requirement Specification, or Srs document. The Srs needs to be clearly understood and approved by all stakeholders. The developers are also involved at this stage so they can gain a clear understanding of these requirements requirements and the Srs will be discussed in more detail in a later video. 
在`规划阶段`，**需求会被收集、分析、记录并确定优先级**。在规划软件解决方案时，**必须考虑以下因素：**
- 在规划过程中，解决方案的使用者需*明确方案的整体目标、数据输入与输出、法律法规合规要求、风险识别、质量保证要求，以及人力和财务资源的配置，并制定项目进度计划*；
- 同时，*对人工成本和材料成本进行估算，并与时间约束条件加以权衡*。
- 此外，项目团队将被明确，并提出各成员的职责分工。
- 如果相关方*在界定需求方面遇到困难，开发团队往往会在规划阶段制作原型，以逐步明晰这些需求*。`原型`是*最终产品的缩微模型，用于获取利益相关方的反馈并明确需求*。原型用于*验证基本的设计构想*。尽管原型开发通常发生在规划阶段，但随着项目推进，在需求需要重新审视时，原型开发也可在软件开发生命周期的各个阶段开展。
- *在需求收集完成后，这些需求将被整合到一份名为`《软件需求规格说明书》`的文档中，即`SRS文档`*。该需求规格说明书*必须得到所有相关方的明确理解并予以批准*。*开发人员也会在这一阶段参与，以便他们能够清晰地理解这些需求*。关于软件需求规格说明（SRS）的详细内容，我们将在后续的视频中进一步讨论。

## 设计阶段
In the design phase, the requirements gathered from the Srs are used to develop the software architecture. Several team members work together at this stage to design the architecture. The architecture is reviewed by the stakeholders and team, and during this phase prototypes can be designed. A prototype is a preliminary mockup of the system or parts of the system used for demonstration purposes. The document created in this phase is called a design document and is used by developers during the next phase, which is the development phase. 
在`设计阶段`，**依据需求规格说明书中的需求，来*构建软件架构***。
在这一阶段，**多名团队成员协同合作，共同进行架构设计**。
该架构**由相关干系人和团队共同评审**，并在此阶段可开展原型设计。`原型`是用于演示的系统或其部分组件的初步模型。
**在本阶段形成的文档称为`设计文档（架构文档）`，将在下一阶段——开发阶段——由开发人员使用**。

## 开发阶段
The development phase, sometimes called the building phase or the implementation phase, is when the developers start the coding process. Once the design document is completed, the project planners use the design document to determine and assign coding tasks. This phase often requires the use of programming tools, different programming languages, and software stacks. Organizations may also have standards or guidelines that need to be followed. 
`开发阶段`，有时也称为`构建阶段`或`实现阶段`，**是开发人员启动编码工作的时期。设计文档完成后，项目规划人员将依据该文档确定并分配编码任务**。这一阶段通常需要使用编程工具、多种编程语言以及软件栈。组织也可能有需要遵循的标准或指南。

## 测试阶段
The testing phase is next in the process once the coding is complete and some large projects have dedicated testing teams, code needs to be thoroughly tested to ensure it is stable, secure, and meets the requirements outlined in the Srs. Testing can be manual, automated, or a hybrid of both. Product bugs are reported, tracked, and fixed, and the code is retested until the software is stable. Some common levels of testing include unit testing, integration testing, system testing, and acceptance testing. Each of these testing levels will be described in further detail in another video. 
编码完成后，`测试阶段`随即启动。在一些大型项目中，通常会设立专门的测试团队。**为确保代码稳定、安全并满足需求规格说明书（SRS）中的各项要求**，必须对其进行全面而严格的测试。*测试可以是手动的、自动化的，也可以是两者的混合*。产品缺陷会被报告、跟踪并修复，代码也会反复测试，直至软件达到稳定状态。**一些常见的测试级别**包括`单元测试`、`集成测试`、`系统测试`和`验收测试`。这些测试层级将在另一期视频中作进一步详细说明。

Next, the deployment phase is where the application is released into the production environment and made available to users. This can also happen in stages. First, it is released onto a user acceptance testing, also called UAT platform. And once the customer off on the functionality, it is released to production. This approach can be used for making software available on a website, mobile device, app store, or a software distribution server on a corporate network. 


Finally, the maintenance phase happens once the code has been deployed into a production environment. This phase helps to find any other bugs, identify user interface issues or UI for short, and identify other requirements that may not have been listed in the Srs code. Enhancements can also be identified at this stage if bugs are discovered in this phase that were missed during testing, these errors may need to be fixed for high priority issues or incorporated into the requirement as part of a future software release, and the process can start over again. 

In this video, you learned that the Sdlc can be divided into six phases. Planning involves requirement gathering and development of the Srs. The architecture is developed during the design phase and the design document is created. The development phase is when coding takes place and then during the testing phase, issues with the code are found and fixed if possible. Deployment is when the code is released to the production environment. And finally, in the maintenance stage, feedback is collected from stakeholders. Other UI issues may be identified and code enhancements suggested, and this information can be fed into another software development cycle if necessary.
