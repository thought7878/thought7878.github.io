## 质量软件开发的关键软件工程过程
Welcome to building quality software. After watching this video, you will be able to list common software engineering processes and describe the common software engineering processes required for building high quality software. There are numerous processes that are common to software engineering projects. In this video, we will discuss six of them. 
欢迎开发高质量的软件。观看此视频后，您将能够**列出常见的软件工程过程**，并**描述构建高质量软件所需的常见软件工程过程**。在软件工程项目中，有许多共同的过程。在本视频中，我们将讨论其中的六个。

Requirements gathering, design, coding for quality testing releases, and documenting the software requirements Specification, or Srs, encompasses the process of collecting and documenting the set of requirements that the software needs to adhere to. It may include a set of use cases that describe the business needs and user flows that the software must implement. Software requirements can be classified into four broad categories, functional, external and user interface or UI system features and non functional. These categories are discussed in more detail in another video. 
需求获取、设计、编码以支持质量测试与发布，以及编写软件需求规格说明书（SRS），这些活动共同构成了对软件需满足的一系列需求的收集与文档化过程。它可能包含一组用例，用于描述该软件必须实现的业务需求和用户流程。软件**需求可分为四大类**：`功能性需求`、`外部接口需求`、`用户界面（UI）需求`以及`非功能性需求`。这些类别将在另一期视频中作更详细的探讨。

`Software design` is the process of transforming the requirements into a structure that is implementable using code. The software design process translates the requirements into a language the developers can use to write the code, it transforms the requirements into a software solution, the technical lead breaks down requirements into sets of related components with clearly defined behaviors, boundaries, and interactions. These components define the system architecture. The system design incorporates guidance on system functions, performance, security, and platform characteristics. The design communicates business rules and application logic, application programming, interface design, which is how apps talk to each other or communicate with database user interfaces, and database design, code quality refers to the characteristics of the code, including attributes such as maintainability, readability, testability, and security. 
`软件设计`是**将需求转化为一种可通过代码实现的结构的过程**。软件设计过程**将需求转化为开发人员可用于编写代码的语言，从而将需求转化为软件解决方案**。
`技术负责人`会**将需求分解为若干组相关组件，并明确界定各组件的行为、边界及其交互关系**。**这些组件定义了系统架构**。
`系统设计`涵盖了**对系统功能、性能、安全性和平台特性的指导**。该设计涵盖了**业务规则与应用逻辑、应用程序开发、界面设计**（即应用间如何交互以及与数据库和用户界面的通信），以及**数据库设计**。
而`代码质量`则指代码的各项特性，包括**可读性、可维护性、可测试性、安全性等**。

Quality code must fulfill the intended requirements of the software without defects. Additionally, it should be clean and consistent, easy to read and maintain, well documented and efficient. Coding for quality entails following a set of coding practices during development. These include following common coding standards, conventions, patterns, and styles using automated tools known as linters to detect pragmatic and stylistic errors, and commenting in the code itself to make it easy for others to understand and modify. 
`高质量的代码`*必须在无缺陷的情况下满足软件的预期需求*。此外，**代码应整洁规范、易于阅读与维护，并具备完善的文档和较高的效率**。质量导向的编码**要求在开发过程中遵循一套编码规范**。这些做法包括**遵循常见的编码标准、约定、模式和风格**，借助称为`linter`的自动化工具来**检测语法与风格方面的错误**，并**在代码中添加注释，以便他人更轻松地理解和修改**。

Software testing is the process of verifying that the software matches established requirements and is free of bugs. Its purpose is to identify errors, gaps, or missing requirements when compared with stated requirements. Properly tested software ensures reliability, security, performance, and efficiency. Software testing can often be automated or done manually. Levels of testing include unit integration system and user acceptance. Unit testing is often done by the developer and tests the smallest component of code that can be isolated from the rest of the system. Once components are integrated into the larger product, integration testing occurs, Then, after the larger product is deemed completed, system testing can take place. 
User acceptance testing, or UAT for short, and sometimes called beta testing, is when the software is tested by the intended end user. Types of testing can broadly be divided into three categories of nonfunction, and regressing levels and types will be further explained in an upcoming video when the newest version of the software is distributed, it is referred to as a release. 
`软件测试`是**验证软件是否符合既定需求并确保其无缺陷的过程**。其目的在于*对照既定需求，识别错误、遗漏或缺失的环节*。经过充分测试的软件能够**确保其可靠性、安全性、性能和效率**。
软件测试通常可以采用*自动化方式*，也可以通过*手动方式*进行。**测试的层次**包括**单元测试、集成测试、系统测试和用户验收测试**。
`单元测试`*通常由开发人员执行*，用于测试能够从系统其余部分中独立出来的*最小代码单元*。
当各组件集成到整体产品中后，将开展`集成测试`；待整体产品被确认为已完成时，方可进行`系统测试`。
`用户验收测试`，简称`UAT`，有时也称为`beta测试`，是指*由预期的最终用户测试软件*。测试类型大致可以分为三类非功能性，当最新版本的软件发布时，回归级别和类型将在即将发布的视频中进一步解释。这被称为释放。

## 了解软件发布阶段和文档
Different types of releases are intended for different audiences. There is generally an alpha, a beta, and a GA release. 
G stands for General availability The Alpha release is the first functioning version of the system released to a select group of stakeholders. The alpha release likely contains errors and may not contain the full feature set, but does contain most of the desired functionality. Design changes may still occur during this release stage. The beta release, also called a limited release, is given to the stakeholders outside of the developing organization. One of the intents of the beta release is to try out the software under real conditions, test the functionality, and identify any outstanding bugs or errors. The beta release should meet all the functional requirements. Then, after beta release, changes are agreed upon, made and tested, and a stable version is released, the audience for the GA release is all users. 
不同类型的发布版本面向不同的受众。通常会有一个*Alpha版*、一个*Beta版*和一个*GA（正式发布）版*。
`G`代表一般可用性。
`Alpha版本`是*发布给特定利益相关者的系统的第一个功能版本*。alpha版本可能包含错误并且可能不包含完整的功能集，但确实包含了大部分所需的功能。在此发布阶段仍可能发生设计更改。
`beta版本`，也称为*有限版本*，是提供给开发组织之外的利益相关者的。**测试版的目的之一**是在真实条件下试用软件，测试功能，并确定任何突出的错误或错误。测试版应满足所有功能要求。
然后，在beta发布之后，对更改达成一致并进行测试，并发布稳定版本，`GA`发布的受众是所有用户。

Software documentation should be provided to both non technical end users and technical users. System documentation is geared toward the technical users, technical users, maybe other engineers, developers, or architects. System documentation explains how the software operates or how to use it. It consists of Readme files, inline comments, architecture and design documents, verification information, and maintenance. User documentation is provided to the non-stepped the end users to assist them in the use of the product. Generally, user documentation is provided in the form of user guides, instructional videos and manuals, online help, and inline help. More details about documentation will be discussed in another video. 
`软件文档`应同时提供给非技术最终用户和技术用户。
`系统文档`面向技术用户，即技术人员，也可能包括其他工程师、开发人员或架构师。系统文档*说明了软件的运行机制或使用方法*。**它由自述文件、内联注释、架构与设计文档、验证信息以及维护相关内容组成**。
`用户文档`面向最终非技术人员提供，旨在*帮助他们正确使用产品*。通常，用户文档以用户指南、教学视频与手册、在线帮助以及内联帮助等形式提供。
有关文档的更多详情将在另一期视频中介绍。
