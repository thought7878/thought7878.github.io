# 视频内容总结

## 一、概述
- 团队需要统一的流程来**澄清沟通、促进信息共享**；
- **三种常见方法论**：`瀑布模型`（Waterfall）、`V 模型`（V-shape）、`敏捷`（Agile）。

## 二、瀑布模型（Waterfall）——顺序式
- **阶段依次推进**：计划 → 设计 → 开发 → 测试 → 部署 → **维护**，*呈阶梯状单向流动*；
- **优点**：阶段离散、定义明确，团队成员清楚各自职责；更易估算预算和分配资源；
- **缺点**：*缺乏灵活性；难以适应变更*。

## 三、V 模型（V-shape）——顺序式
- **左侧（验证 Verification）下行**：计划 → 系统设计 → 架构设计 → 模块设计 → 编码（V 底）；
- **右侧（确认 Validation）上行**：单元测试 → 集成测试 → 系统测试 → 验收测试；
- 每个设计阶段与对应测试阶段通过虚线关联（如模块设计↔单元测试、计划↔验收测试），**测试计划提前设计**；
- **优点**：易于使用；测试提前规划，节省开发与测试时间；
- **缺点**：僵化；无法适应需求变化。

## 四、敏捷（Agile）——迭代式
- 循环流程：计划 → 设计 → 开发 → 测试 → 部署 → **反馈**，**不断迭代**；
- 经过若干循环后发布 **MVP（最小可行产品）**；
- **敏捷宣言四大价值观：**
  - 个体与互动 高于 流程与工具；
  - 可工作的软件 高于 详尽的文档；
  - 客户协作 高于 合同谈判；
  - 响应变化 高于 遵循计划；
- **优点**：*轻松应对需求变化；定期纳入反馈*；
- **缺点**：预算与资源分配困难；项目范围不清晰。

## 五、顺序式 vs 迭代式对比
- **顺序式**：瀑布、V 模型（线性箭头）；
- **迭代式**：敏捷（闭环循环）。

## 六、总结
> - 三种常见方法论：瀑布、V 模型、敏捷；
> - 瀑布与 V 模型是*顺序式*，敏捷是*迭代式*；
> - 瀑布与 V 模型*易于使用*，但都*不擅长适应需求变化*；
> - 敏捷*允许需求变化*，但*资源分配可能具有挑战性*。

**核心结论**：`顺序式方法`**结构清晰、便于预算与职责管理，*适合需求稳定的项目***；`敏捷`**以迭代和反馈为核心，*适合需求多变的环境*，但需面对范围与资源管理的挑战**。
